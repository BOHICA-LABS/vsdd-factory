# S-25.18: Reservation Lifecycle — Leak Hygiene, Drain-Stall Diagnostics and Test Convention

**Epic:** E-25 - Validation Integrity and Large-Artifact Resilience
**Depends on:** S-25.06, S-25.08 (PR #848)
**Blocks:** (none)
**Priority:** P2
**Origin:** PR #848 pr-reviewer N1; code-reviewer CR-007, CR-008, CR-006, CR-011 (carried forward by the human decision of 2026-10-13, D-1264(a)/(i); "story anchors for the rest")

## Narrative

- **As a** factory operator whose `.factory/` is the `factory-artifacts` worktree and who runs the governed migrations
- **I want** a leaked reservation to be invisible to git, a stalled drain to tell me exactly what is blocking it and how to clear it, a momentary lock overlap not to be reported as a rival coordinator, one staleness rule with no swallowed errors, and privilege-dependent tests that cannot pass silently
- **So that** a broad `git add` can never commit a transient reservation, `DRAIN_TIMEOUT_ABORT` is actionable instead of a 30-second mystery, a re-run is not needed for a spurious contention, the GC and the drain cannot disagree about what is stale, and a green CI run means the tests really ran

## Problem Statement

**N1 / CR-007 (a) — untracked leak.** The reservation namespace is unconditional (EC-020): every protected `Edit`/`Write`/`MultiEdit` creates `.factory/migration-state/reservations/<id>.reservation`. If neither Post event arrives (another PreToolUse hook denies, the user rejects the permission prompt, the session is killed) the file stays until the 3,600 s TTL (BC-1.18.013 Precondition 6(c): "the designed, sole residual"). In a repository whose `.factory/` is the `factory-artifacts` worktree, which has no `.gitignore`, the leaked file is untracked: a broad `git add` can commit it and it trips the "factory-artifacts dirty" check. No story addresses it.
**N1 / CR-007 (b) — drain stall.** For up to an hour any coordinator drain that finds the file waits 30 s and aborts `DRAIN_TIMEOUT_ABORT` (S-25.06 AC-019/AC-020; remediation "operator deletion"), and the abort line does not say what blocked it. The retention bias is the spec's trade-off (PID liveness was rejected), so the behavior is not changed; the diagnostic and the runbook are missing.
**CR-008.** The coordinator's `flock(exclusive.lock, LOCK_EX|LOCK_NB)` fails with EWOULDBLOCK when the lock is held for an instant by something other than a coordinator — the dispatcher's PreToolUse reconciliation takes the same lock with `try_lock` for a short critical section — and the operator reads `MIGRATION_LOCK_CONTENTION` ("another coordinator holds the lock") although none exists. Exit 1 says "safe to re-run", but the message is wrong and the re-run is avoidable.
**CR-006.** The staleness predicate is meant to be ONE pure function (`reservation_is_stale`, BC-1.18.013 Precondition 6(c) timestamp rules); the code reviewer found a duplicated comparison, and a `remove_file` error in the drain GC is discarded (`let _ =`), the exact pattern D-1264's sibling sweep (S-25.09 AC-015) forbids.
**CR-011.** Tests that need an unprivileged process (an unwritable directory, `chmod 000`) skip when the suite runs as root (a container CI image); the skip is a bare early return and passes silently. PR #848's round-2 fix made one such skip loud; the rest were not swept.

## Acceptance Criteria

> Every black-box assertion uses the real `factory-dispatcher` binary / the real coordinator subcommand (spawned process, tempdir project with a `.factory/`, and where stated a real `git` worktree), never a direct function call alone (S-25.08 claim boundary).

### AC-001 (N1 (a); the reservation namespace is ignored by git; traces to BC-1.18.013 Precondition 6(c) "Unconditional reservation namespace" and EC-020 (the admitter creates `migration-state/reservations/` idempotently); the `.gitignore` is NOT in the BC — GAP-S2518-001)
ONE helper `ensure_migration_state_dir(factory_root)` is the only place `migration-state/` is created (admission, the release leg's presence probe never creates, both coordinators). After creating the directory it creates `migration-state/.gitignore` with exactly the single line `reservations/` using create-new semantics (`O_CREAT|O_EXCL`): an existing `.gitignore` (operator-edited or already written) is NEVER overwritten or appended to, `EEXIST` is success, and an existing deployment whose `migration-state/` predates this story gains the file on the next admission. The file lives in `migration-state/`, NOT in `reservations/`, so the drain's "`reservations/` is empty" quiescence test is unaffected. A failure to write the `.gitignore` (EACCES, ENOSPC) is never a verdict: it is one `migration.admission_advisory` (existing reason `reservation_release_failed` is NOT reused; a distinct closed token `migration_state_gitignore_failed` is added: **NEW — add to BC-3.08.001 Event 13 (product-owner)**) on the dispatcher legs and one stderr line on the coordinator legs.
- **Test:** `test_BC_1_18_013_EC020_migration_state_gitignore_created_once_with_exact_content_blackbox()`, `test_BC_1_18_013_EC020_existing_gitignore_is_never_overwritten_blackbox()`, `test_BC_1_18_013_EC020_leaked_reservation_is_invisible_to_git_status_in_a_real_worktree_blackbox()` (real `git init` worktree: admit a protected write, never send Post; `git status --porcelain` lists nothing under `migration-state/reservations/`; a txn record file IS still listed), `test_BC_1_18_013_EC020_gitignore_write_failure_is_an_advisory_not_a_verdict_blackbox()`, `test_BC_1_18_013_EC020_no_second_migration_state_create_site_source_gate()`.

### AC-002 (N1 (b), CR-007; `DRAIN_TIMEOUT_ABORT` names its blockers; traces to BC-1.18.013 Precondition 6(c) "How DRAINING waits" + "Timeout", EC-011, EC-012; BC-1.18.011 Postcondition 10 (stderr mirror); the summary line is NOT in the BCs — GAP-S2518-002)
On BOTH coordinators (`migrate-bc-index` via `drain_bc_index_writers`, `backfill-append-logs` via `run_backfill_append_logs` drain step 4) the `DRAIN_TIMEOUT_ABORT` stderr output gains exactly ONE line before the existing taxonomy line: `<subcommand>: DRAIN_BLOCKED: <n> reservation(s) block the drain; oldest age <a> s; earliest reclaim in <r> s (TTL <t> s); see docs/guide/migration-reservation-leak-recovery.md`, where `<n>` is the count of `*.reservation` entries still present at the timeout, `<a>` the maximum age in whole seconds by the single `reservation_is_stale` basis (`created_at`, else mtime; `unknown` when neither is usable), `<r>` the minimum of `TTL - age` over the blockers clamped at 0, `<t>` the effective TTL. The line carries NO file name and NO `tool_use_id` (names embed raw ids; control characters never reach stderr), and `<subcommand>` is one of the two closed subcommand tokens. Exit code, the abort effects (txn ABORTED, gate OPEN, lock released, canonical files byte-identical) and the existing line are unchanged. The `DRAIN_BLOCKED` prefix is **NEW — add to the error taxonomy as an advisory prefix with Display parity rows (S-12.13 lint gate)**; it is not an exit-code class and not a verdict.
- **Test:** `test_BC_1_18_013_EC011_drain_timeout_abort_prints_one_drain_blocked_line_per_coordinator_blackbox()` (both subcommands; injected ~200 ms timeout), `test_BC_1_18_013_EC011_drain_blocked_line_has_no_file_name_or_tool_use_id_blackbox()` (reservation named with a control-character-bearing id), `test_BC_1_18_013_EC012_drain_blocked_age_and_reclaim_arithmetic_table()` (pure; `created_at` / mtime / unknown / future / TTL boundary), `test_BC_1_18_013_EC011_drain_abort_effects_and_exit_code_unchanged_regression()`.

### AC-003 (N1 (b); the operator runbook; traces to BC-1.18.013 Precondition 6(c) "Stale reservations from dead writers" ("remediation is operator deletion"), EC-012; the runbook is a story deliverable like S-25.09 AC-018)
`docs/guide/migration-reservation-leak-recovery.md` documents, from the operator's seat: how a reservation leaks (the three causes above), why it blocks a drain and why it is not reclaimed early (TTL-only; PID liveness rejected, ADR-052 §5a), how to read the `DRAIN_BLOCKED` line, the SAFE manual remediation (confirm no tool call is in flight in any session, then delete the specific `*.reservation` files under `migration-state/reservations/`; never touch `txn-*.json`, `gate-state.json` or `exclusive.lock`), the alternative of waiting for the TTL, and the `.gitignore` of AC-001 (a pre-existing untracked reservation is removed, not committed). Every shell recipe in the document is fixture-verified (a test extracts each fenced recipe and runs it against a golden tempdir tree, as S-25.09's runbook parser self-check does).

### AC-004 (CR-008; a momentary lock overlap is not reported as a rival coordinator; traces to BC-1.18.011 Precondition 6(e) flock-contention clause and BC-1.18.013 Precondition 6(c) (lock ordering, `try_lock`, EWOULDBLOCK) incl. S-25.09 AC-013 `MIGRATION_LOCK_CONTENTION` exit 1 on every path; the grace is NOT in the BCs — GAP-S2518-003)
Each coordinator acquires `exclusive.lock` with `LOCK_EX|LOCK_NB`, and on EWOULDBLOCK retries with a short fixed backoff until `LOCK_ACQUIRE_GRACE` elapses, then declares `MIGRATION_LOCK_CONTENTION` (exit 1, nothing mutated, the existing taxonomy text) exactly as today. The grace is an injectable parameter (production default chosen at T-1 from the MEASURED maximum hold time of the admission reconciliation critical section plus a documented margin, and recorded; it is a duration, not a count of retries); tests inject `0` to keep S-25.09 AC-013 and S-25.06 AC-036 deterministic and inject a long hold to prove a genuinely held lock still ends in contention after the grace. The ordering guarantees are unchanged: the lock attempt is still FIRST, on EVERY path, before any loader or read (flock-first), and `completed.json` / state is still read only under the lock. No new error code; the message text is the existing taxonomy row (no invented wording).
- **Test:** `test_BC_1_18_011_6e_brief_admission_reconcile_overlap_does_not_report_contention_blackbox()` (hold the lock for less than the grace via a seam: coordinator succeeds), `test_BC_1_18_011_6e_genuinely_held_lock_still_exits_1_after_the_grace_blackbox()` (both coordinators), `test_BC_1_18_011_6e_grace_zero_reproduces_todays_immediate_contention_regression()` (the S-25.09 AC-013 vectors, unchanged), `test_BC_1_18_011_6e_lock_attempt_precedes_every_read_ordering_regression()`.

### AC-005 (CR-006; one staleness predicate and no swallowed GC error; traces to BC-1.18.013 Precondition 6(c) "Reservation timestamp rules" (the ONE pure predicate `reservation_is_stale`, rule (5) stderr advisories) and EC-012, EC-025; BC-1.18.011 Precondition 6(c), EC-009, EC-020; the GC error surfacing is NOT in the BCs — GAP-S2518-004)
(a) Exactly one definition of the staleness comparison exists in `crates/factory-dispatcher/src`; the drain GC of BOTH coordinators, the AC-002 blocker summary and any other age computation call `reservation_is_stale` / its shared age helper (literal-shell source gate with captured stdout; TD-VSDD-060). (b) In the drain GC, `remove_file` returning ENOENT is tolerated (the release won the race); ANY other error is not discarded: it is written as one coordinator stderr line `<subcommand>: reservation GC remove failed (<ErrorKind>)` (no path, no id) and the reservation is treated as STILL PRESENT, so the drain keeps waiting and, at the timeout, `DRAIN_TIMEOUT_ABORT` carries the AC-002 summary that counts it. The five timestamp-fallback stderr tokens of rule (5) are unchanged.
- **Test:** `test_BC_1_18_013_EC012_single_staleness_predicate_source_gate()`, `test_BC_1_18_013_EC012_gc_remove_error_other_than_enoent_is_surfaced_and_counts_as_blocker_blackbox()` (read-only `reservations/` directory seam), `test_BC_1_18_013_EC012_gc_remove_enoent_is_silent_regression()`, `test_BC_1_18_013_EC025_timestamp_fallback_stderr_tokens_unchanged_regression()`.

### AC-006 (CR-011; privilege-dependent tests never pass silently; traces to BC-1.18.013 EC-032 / BC-1.18.011 EC-043 (the unstatable-`.factory` and `Io` vectors whose fixtures need an unprivileged process) and VP-143 D1; the convention is a test-infrastructure rule, no BC clause — GAP-S2518-001)
A single helper (`skip_if_root!(reason)` in each crate's `tests/common`) is the ONLY way a test may skip for lack of privilege: it prints one `SKIPPED(root): <test name>: <reason>` line to stderr and returns; when `VSDD_REQUIRE_NO_SKIP=1` it FAILS the test instead. The `cargo-host` CI jobs run the privilege-sensitive suites as a non-root user with `VSDD_REQUIRE_NO_SKIP=1`, and one step asserts that the captured test output contains zero `SKIPPED(` lines. A source gate (literal-shell sweep with captured stdout) asserts that no test body in `crates/factory-dispatcher/tests` or `crates/last-amended-migrate/tests` contains an inline `geteuid`/`euid == 0`/`is_root` early return outside the helper; T-1 records the swept sites (PR #848's round-2 fix converted one) and the story converts every remaining one.
- **Test:** `test_BC_1_18_013_EC032_skip_if_root_helper_prints_marker_and_fails_under_require_no_skip()`, `test_BC_1_18_013_EC032_no_inline_root_skip_outside_the_helper_source_gate()`, and a CI step (`! grep -q 'SKIPPED(' <captured log>`) recorded in the workflow diff.

### AC-007 (PR #848 round-2 SEC-002-N4; orphaned temp files left by a crash are swept; traces to BC-1.18.013 Precondition 6(c) "Unconditional reservation namespace" (what the admitter and coordinators create under `migration-state/`) and EC-012 (stale leftovers are reclaimed, never trusted); the temp-sweep rule is NOT in the BC — GAP-S2518-005)
A process killed between creating a temp file and the rename leaves an orphan: under `migration-state/` (the atomic-write temps of the reservation, gate, txn and terminal-record writers) and wherever `last-amended-migrate`'s `atomic_write` places its temps (the PR #848 SEC-002 fix gave them unpredictable names). (a) Every such temp name carries one closed, documented marker (prefix or suffix) and is created only by the shared atomic-write helpers, so an orphan is recognizable without reading content. (b) Each coordinator, at start and BEFORE the drain's quiescence test, removes marker-matching temps older than `MAX_RESERVATION_TTL` (age by mtime through the single age helper of AC-005, same skew and unknown-age rules: unknown age is KEPT), never a younger one (a live writer's temp), and never any file that does not match the marker; `atomic_write`'s own temps in the migrated tree are swept by the migrate command under the same rule. (c) A sweep `remove_file` error other than ENOENT is surfaced exactly as AC-005(b) (one stderr line, no path); ENOENT is silent. (d) The drain's "`reservations/` is empty" test ignores nothing new: a leaked temp under `reservations/` is a blocker like a reservation and is counted by the AC-002 summary until swept. The file MODE of new temps (`0o600`) is NOT anchored here: it is fixed inside PR #848 (human decision, round 2).
- **Test:** `test_BC_1_18_013_EC012_orphaned_temp_older_than_ttl_is_swept_at_coordinator_start_blackbox()`, `test_BC_1_18_013_EC012_younger_or_unknown_age_temp_is_kept_regression()`, `test_BC_1_18_013_EC012_non_marker_file_is_never_swept_regression()`, `test_BC_1_18_013_EC012_atomic_write_orphan_temp_in_migrated_tree_swept_by_migrate_command_blackbox()` (`last-amended-migrate` crate), `test_BC_1_18_013_EC012_temp_sweep_remove_error_surfaced_not_discarded_blackbox()`, `test_BC_1_18_013_EC012_temp_marker_created_only_by_shared_helpers_source_gate()`.

### Forbidden Dependencies (build-time enforcement)

- `crates/factory-dispatcher` MUST NOT gain `tracing-subscriber` or any logging-framework dependency; the S-26.06 AC-008 source gate fails the build if it does.
- The pure arithmetic modules MUST NOT depend on `std::fs`, `std::process`, `std::env` or ambient time; the clock is an injected `now: u64` exactly as `reservation_is_stale` takes it.
- `last-amended-migrate` MUST NOT depend on `factory-dispatcher` (ADR-051 §8); the existing reverse edge is unchanged.
- No process-liveness probe (`kill(pid, 0)`, `/proc`) may enter the reservation code (PID liveness was rejected by ADR-052 §5a).
- No new external crates without architect approval.
