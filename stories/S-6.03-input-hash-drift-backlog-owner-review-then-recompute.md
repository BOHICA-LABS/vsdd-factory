# S-6.03: Input-Hash Drift Backlog — Owner-Review-Then-Recompute + BC-INDEX Input De-Loop

## Narrative

- **As a** factory operator who relies on `input-hash` (POLICY 18) to detect that an artifact is stale relative to its
  inputs
- **I want** the ~1,000 stale/partial artifacts reviewed by their owning specialist against the CURRENT inputs and only
  then recomputed — never bulk-refreshed — and the remaining six BCs that list `BC-INDEX.md` as an input de-looped
- **So that** `compute-input-hash --scan` becomes a trustworthy signal again (a hash means "reviewed against these inputs",
  and a non-zero STALE count means real unreviewed drift), instead of a permanently red dashboard that agents learn to
  ignore or refresh blindly

## Context / Evidence

**Backlog size.** Read-only drift scan recorded at D-1247 (2026-10-06): TOTAL=2593 MATCH=1407 STALE=889 UNCOMPUTED=54
NOINPUT=243 PARTIAL~56. Human breakdown of the ~1,000 stale/partial artifacts (2026-10-07): ~430 BCs, ~90 VPs and
ADRs, ~180 stories and epics, ~330 cycle files. The counts are re-measured by T-1 against the tree at dispatch time
(E-25 will have changed them); the story's deliverable is the cleared END STATE, not these numbers.

**Why review-then-recompute.** `compute-input-hash --update` writes the hash of the inputs' current bytes; it proves
nothing about the artifact. Bulk `--scan --update` would convert every real staleness (a BC whose ADR moved under it)
into a green hash, destroying the one signal POLICY 18 exists to give. The procedure therefore has two halves per
artifact: (1) the OWNER reviews what changed in each input since the stored hash was computed (git history of the input
files since the artifact's last commit) and confirms the artifact still conforms — amending it when it does not
(a content change, version bump and changelog row per normal rules) — and (2) only then recomputes and records the review.

**Ownership split (CLAUDE.md Agent Routing Table):** BCs, holdout scenarios -> `product-owner`; VPs and ADRs ->
`architect`; stories and epics -> `story-writer`; cycle files (burst logs, adversarial reviews, lessons, decision logs) and
STATE/indexes -> `state-manager`. No agent reviews another owner's artifacts (Companion Principle: agents own their domain).

**The loop.** An artifact that lists an index which itself lists the artifact (BC -> BC-INDEX.md, BC-INDEX -> BC rows)
can never have a stable hash: bumping the BC changes BC-INDEX, which changes the BC's hash input. BC-1.18.011 v1.14
dropped `BC-INDEX.md` from its `inputs:` (D-1247). Six BCs still list it in their frontmatter `inputs:` (verified
2026-10-07): BC-1.18.012 (v1.1), BC-4.13.001 (v1.18), BC-5.39.009 (v1.9), BC-5.39.010 (v1.24), BC-5.40.001 (v1.21),
BC-6.23.001 (v1.2).

## Acceptance Criteria

> Evidence is scan output: `compute-input-hash --scan .factory` (literal invocation, captured stdout) before and after
> each owner wave, recorded in the review record (AC-002). "Cleared" = the artifact's stored hash equals the recompute AND
> a review record exists for it.

- **AC-001 (traces to BC pending PO authorship):** T-1 produces the TRIAGE MANIFEST
  (`.factory/cycles/<cycle>/input-hash-drift-triage.md`, state-manager-owned artifact): from a literal
  `compute-input-hash --scan .factory --resolve` + `--scan .factory` run, every STALE / UNCOMPUTED / PARTIAL / NOINPUT
  artifact classified by owner (PO / architect / story-writer / state-manager), by input-graph depth (topological level),
  and by disposition: `review-recompute`, `frozen-historical` (cycle files whose inputs are immutable history — the hash is
  recorded as `frozen` with the commit it froze at, not refreshed), `no-inputs-by-design` (NOINPUT with a one-line reason),
  or `fix-inputs` (unresolvable/missing input). Counts by owner and disposition are stated; the manifest is the work list.
- **AC-002 (traces to BC pending PO authorship):** The REVIEW RECORD convention (rules text, SS-08): per artifact reviewed,
  one line in the owner's wave log — artifact id, stored hash -> new hash, the list of changed inputs, a verdict
  `CONFORMS` or `AMENDED (vX -> vY)`, and the reviewer agent. A recompute without a matching review-record line is a
  procedure violation. The convention lives in `plugins/vsdd-factory/rules/` (and is cited by `check-input-drift`'s SKILL).
- **AC-003 (traces to BC pending PO authorship):** Wave order is TOPOLOGICAL over the `inputs:` graph (ADR -> BC ->
  error-taxonomy -> VP -> story -> epic -> index -> cycle files; lesson L-BB-D1196-cascade-input-hash-topological): no
  artifact is recomputed before every artifact it depends on has been reviewed and recomputed in the same run;
  `compute-input-hash` gains (or the wave tooling uses) a topological-order listing mode proving it (AC-009).
- **AC-004 (traces to BC pending PO authorship):** Wave P (product-owner): every BC on the manifest reviewed against its
  current inputs (ADRs, domain spec, parent BCs, error-taxonomy), amended where the review finds non-conformance, then
  recomputed in topological order; BC-INDEX row/version parity is state-manager's follow-up burst (not the PO's).
- **AC-005 (traces to BC pending PO authorship):** Wave A (architect): every VP and ADR on the manifest reviewed
  (VP -> its BC and ADR inputs; ADR -> its research/BC inputs), amended where needed, recomputed; VP-INDEX /
  verification-architecture / coverage-matrix propagation is same-burst (POLICY 9) and owned by the architect.
- **AC-006 (traces to BC pending PO authorship):** Wave S (story-writer): every story and epic on the manifest reviewed
  (BC cites current; ACs still trace; token budget; dependency anchors) and recomputed in topological order; STORY-INDEX
  catalog rows / three-way parity (frontmatter = catalog = blockquote, POLICY 18) are state-manager's follow-up burst.
- **AC-007 (traces to BC pending PO authorship):** Wave M (state-manager): cycle files and indexes dispositioned per the
  manifest — `frozen-historical` entries marked with the freeze commit; live ones recomputed; STATE/indexes last. All
  wave commits obey single-commit-per-burst (TD-VSDD-053) and never run concurrently with another `.factory/` writer
  (D-1251-PG-001; S-12.17 when delivered).
- **AC-008 (traces to BC pending PO authorship):** DE-LOOP: BC-1.18.012, BC-4.13.001, BC-5.39.009, BC-5.39.010,
  BC-5.40.001 and BC-6.23.001 drop `.factory/specs/behavioral-contracts/BC-INDEX.md` from frontmatter `inputs:` (product-
  owner; version bump + changelog row per BC; any body text that relied on the input restated as a cite, not an input);
  BC-INDEX version/row parity follows (state-manager). Precedent: BC-1.18.011 v1.14 (D-1247).
- **AC-009 (traces to BC pending PO authorship):** A CYCLE DETECTOR prevents regression: `compute-input-hash --scan
  .factory --check-cycles` (or an equivalent mode) walks the `inputs:` edges and exits non-zero naming any directed cycle
  (artifact A lists B and B's inputs transitively list A); wired into the existing drift-check surface (the
  `check-input-drift` skill and, if the architect agrees in T-2, a CI lint). A fixture graph with a planted 2-cycle is
  detected; the post-wave tree reports zero cycles. (Tooling deliverable, TDD strict.)
- **AC-010 (traces to BC pending PO authorship):** END STATE evidence, captured literally in the final wave log: `compute-
  input-hash --scan .factory` reports STALE=0 and UNCOMPUTED=0; every remaining NOINPUT artifact is on the
  `no-inputs-by-design` list with a reason; PARTIAL=0; `--check-cycles` clean; a re-scan one burst later shows no new
  drift introduced by the waves themselves. Any artifact the owner could NOT bring to CONFORMS within the story is a
  routed finding (fixed in scope by its owner), never left red or silently recomputed.

## Architecture Compliance Rules

1. **Owner-review-then-recompute is mandatory:** no `--scan --update` bulk refresh of any artifact class; a recompute
   without a review-record line is a violation (AC-002).
2. **Topological order (AC-003)** and **quiescence:** no wave runs while another `.factory/` writer is active.
3. **Agents own their domain (Companion Principle):** each artifact class is reviewed/amended only by its owner.
4. **Tool invariants preserved:** `compute-input-hash` never silently skips a missing input; `--update/--check/--scan`
   exit codes unchanged; the detector is additive.
5. **Single-commit-per-burst / POL-3 (TD-VSDD-053, TD-FACTORY-HOOK-BYPASS-001):** all `.factory/` edits via Edit/Write; no
   shell-mediated rewrites of artifact bodies (hash lines are updated by the sanctioned tool only).
6. **Index parity is a follow-up burst owned by state-manager,** never edited by the reviewing specialist.

### Forbidden Dependencies (build-time enforcement)

- The cycle detector MUST NOT depend on network access or on any artifact outside `.factory/` and the repo-root engine
  paths `compute-input-hash` already resolves.
- If implemented in Rust, the bin MUST NOT depend on `factory-dispatcher`; and `last-amended-migrate` MUST NOT depend on
  `factory-dispatcher` (workspace rule; ADR-051 §8).
- No new external dependencies without architect approval.
