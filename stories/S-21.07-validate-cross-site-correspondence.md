### AC-026: Primary-target read succeeds as bytes but fails UTF-8 decoding — MUST block, not silently Continue (traces to BC-5.39.010 v1.23 precondition 15a, postcondition 25, invariant 4 extension / EC-038)

`HookResult::block_with_fix(...)` naming the file path and the decode error, under the same
fail-closed posture as invariant 4. The hook MUST NEVER return `HookResult::Continue` for
this case, regardless of which arm(s) the primary target would otherwise dispatch to. Citing
invariant 9 (`is_char_boundary()` slicing safety on already-decoded strings) as authorization

only, not read-decode disposition.

Under BC-5.39.010 v1.23 invariant 4 extension (ADV-RECON-007): the shipped implementation's
primary-target UTF-8 decode step (post-primary-read, pre-arm-dispatch) had filled this
previously-undefined case by citing invariant 9 as authorization for `HookResult::Continue`
on decode failure; invariant 9 does not grant this. New precondition 15a and postcondition 25
close the gap and name the invariant-9 misattribution NON-CONFORMING to prevent recurrence.

### AC-027: Class A Arm2 — Phase 2 same-field scan-stop; an intervening different-BC token before the qualifying v-token yields no citation (traces to BC-5.39.010 v1.23 precondition 13 Phase 2 same-field scan-stop / EC-039)

## Forbidden Dependencies

The following MUST NOT appear in `crates/hook-plugins/validate-cross-site-correspondence/Cargo.toml`.
If any appears, the build MUST fail (CI enforces this via `cargo deny` or similar):

| Forbidden Crate | Reason |
|-----------------|--------|
| `serde_yaml` | Deprecated, archived 2024; workspace migrated to `serde_norway = "0.9"` via TD #72. Any import is a regression. |
| `wasmtime` | Hook plugins are WASM binaries; they must NOT link against wasmtime. Only the dispatcher binary links wasmtime. A hook crate depending on wasmtime creates a circular compile dependency. |
| `factory-dispatcher` | Same reason — binary crate; hook plugins must not depend on the dispatcher binary. |

Note: `serde_norway` is permitted (YAML deserialization if needed) but YAML parsing is
not required for this hook — frontmatter is extracted via line-scanning regex as in all
existing hook plugins. `serde` + `serde_json` (for payload deserialization) are permitted.
