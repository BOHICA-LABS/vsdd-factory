# S-25.17: Admission Gate Dispatcher-Leg Hardening

**Epic:** E-25 - Validation Integrity and Large-Artifact Resilience
**Depends on:** S-25.08 (PR #848), S-25.09
**Blocks:** (none)
**Priority:** P2
**Origin:** PR #848 security-reviewer SEC-003 and SEC-005, code-reviewer CR-001 and CR-009, pr-reviewer N2 (carried forward by the human decision of 2026-10-13, D-1264(a)/(i); "story anchors for the rest")

## Narrative

- **As a** factory operator who relies on the PreToolUse admission gate as the writer half of the migration interlock
- **I want** a relative `file_path` classified against the session's own project root as well as the payload cwd, an admitted write at an absent factory root to leave an observable record, the release leg to cost no more than it must, the reservation write to avoid a pointless disk flush on every protected write, and every admission block to carry the dispatcher's trace id
- **So that** a payload-supplied `cwd` cannot steer the classifier away from the governed tree, a misanchored session is visible instead of silent, the gate's hot path stays cheap, and an operator can correlate a block on stderr with the durable `migration.admission_*` events

## Problem Statement

**SEC-005 (LOW).** BC-1.18.013 Precondition 6(b)(iv)(a) joins a relative `file_path` onto the payload's `cwd` when that is an absolute path, else onto `project_root`. The payload `cwd` is harness-supplied per call and need not equal the session project root: a relative path `cycles/x.md` with `cwd = <root>/.factory` classifies as governed, but the same call with `cwd = /tmp` classifies out of scope although the tool, run against the session root, may still land under `.factory`. The harness sends absolute `file_path`s for Edit/Write, so the branch is "defensive" — which is exactly where a bypass hides.

**SEC-003 (LOW).** Admission admits unconditionally when the session's `.factory` is absent or a non-directory (Precondition 6(b)(iii), Precondition 7, EC-035; S-25.09 AC-007 ABSENT controls), and the project root is whatever `CLAUDE_PROJECT_DIR` or the process cwd says. A session launched from a subdirectory without `CLAUDE_PROJECT_DIR` therefore anchors on a root with no `.factory`, admits every protected write, and a coordinator run from the real project root drains nothing — the interlock guards nothing and nothing says so. The spec ruled this posture on purpose (a project with no `.factory` has no governed tree; S-25.09 AC-001(a) forbids an ancestor walk); the finding is that the posture is SILENT. ADR-052 §5a is the ruling surface for any change to the verdict, and amending an ADR is the human's call (CLAUDE.md rule 12), so this story makes the posture observable and records the verdict question as a human ruling rather than changing it silently.

**CR-009 (LOW).** Every `PostToolUse` / `PostToolUseFailure` with a valid id pays an extra `lstat` walk on the release path beyond the minimum (`.factory` stat, `migration-state/reservations` presence probe, one `unlink`), per the code reviewer.

**CR-001 (MEDIUM).** The reservation write sits on the hot path of EVERY protected `Edit`/`Write`/`MultiEdit` and uses the strict-durable atomic write (file `fsync` plus directory sync). The reservation is a consistency interlock reclaimed by TTL (EC-012), not a durable record: a power loss that drops it also kills the in-flight writer it guarded. The durability buys nothing and costs a media flush per write (`F_FULLFSYNC` on macOS).

**N2 (pr-reviewer, non-blocking).** The registry-independent admission early return in `main.rs` prints only the indented `plugins_run=... block_intent=true ... block_reason=...` continuation line; the `factory-dispatcher trace=<id> event=... tool=...` header is printed only after `Registry::load`. An `E-MAINTENANCE-001/002` block therefore reaches stderr with no trace id — the documented diagnostic handle — although S-25.09 AC-002 writes the matching InternalLog event with that id.

### AC-001 (SEC-005; a relative `file_path` is classified under BOTH anchors; traces to BC-1.18.013 Precondition 6(b)(iv)(a) input guards and 6(b)(iv)(e) either-form union; the either-anchor join is NOT in the BC — GAP-S2517-001)
`resolve_target_path` joins a relative `file_path` onto the session project root (`SessionProjectRoot.path`, S-25.09 AC-001(a)) AND, when the payload `cwd` is an absolute path that differs, onto the payload `cwd`; the write is in scope iff EITHER join classifies as governed (the existing union philosophy: over-matching costs one spurious reservation, never a missed protection). A relative path with no payload `cwd`, an empty or relative `cwd` joins onto the project root only (unchanged). The Bash write-effect classifier of S-12.16 keeps joining onto the command's own cwd (the shell resolves relative to it): S-12.16 AC-004 is unchanged and the sibling sweep (TD-VSDD-060) records every caller of the resolver with its anchor choice.
- Vectors: (1) relative `cycles/c1/log.md` with `cwd = <root>/.factory` — governed through the cwd join, as today (regression); (2) relative `.factory/cycles/c1/log.md` with `cwd = /tmp` and session root `<root>` — NEW: governed through the project-root join (today: joined onto `/tmp`, out of scope); (3) relative `cycles/c1/log.md` with `cwd = /tmp` — out of scope under both joins, as today (regression; the project-root join yields `<root>/cycles/c1/log.md`, which is not under `<root>/.factory`); (4) a relative path containing `..` that leaves and re-enters the tree; (5) a symlinked payload `cwd`.
- **Test:** `test_BC_1_18_013_EC024_relative_path_classified_under_project_root_even_when_payload_cwd_differs_blackbox()`, `test_BC_1_18_013_EC024_relative_path_cwd_arm_unchanged_regression()`, `test_BC_1_18_013_EC024_relative_path_without_usable_cwd_uses_project_root_only()`, `test_BC_1_18_013_EC024_every_resolver_caller_names_its_anchor_source_gate()`.

### AC-002 (SEC-003; an admitted write at an absent or non-directory factory root is OBSERVABLE; traces to BC-1.18.013 Precondition 6(b)(iii), Precondition 7 and EC-035 (absent root admitted, nothing created), Postcondition 10(d) advisory domain; the advisory reason and the totality statement are NOT in the BC — GAP-S2517-002)
(a) `resolve_session_project_root` is total: it never fails and never returns "unresolved" (a canonicalize failure falls back to the as-given path, an absent or empty `CLAUDE_PROJECT_DIR` to the process cwd — S-25.09 AC-001(a)); a test table asserts it, so the "project root unresolved" half of SEC-003 is a documented non-case. (b) When the PreToolUse admission leg decides ABSENT (the closed set of Precondition 6(b)(iii): missing, non-directory, dangling symlink, `ENOTDIR` root) for a path that, under the session's own anchor spelling, is lexically `<project_root>/.factory/<governed family>/...`, the verdict is UNCHANGED (admitted, nothing created, no reservation) and EXACTLY ONE `migration.admission_advisory` is written with `reason=factory_root_absent` and the closed context fields `detail` (the sanitized, length-capped `root_source` token `CLAUDE_PROJECT_DIR` | `process cwd`; no raw path, no raw id). The reason domain grows from five to six tokens: **NEW — add to BC-3.08.001 Event 13 (product-owner)**; no other event, field or error code changes. A path that is not lexically under the session's own `.factory` spelling emits nothing (EC-023(d) look-alikes). (c) Whether the VERDICT for case (b) should change (block when the root source is `process cwd` and an ancestor holds a `.factory`) is a HUMAN ruling on ADR-052 §5a recorded at T-1 as GAP-S2517-002; this AC does not pre-empt it.
- **Test:** `test_BC_1_18_013_EC035_resolve_session_project_root_is_total_table()`, `test_BC_1_18_013_EC035_absent_root_protected_looking_write_admitted_with_one_factory_root_absent_advisory_blackbox()` (four ABSENT forms x two root sources), `test_BC_1_18_013_EC035_absent_root_non_protected_path_emits_no_event_blackbox()`, `test_BC_1_18_013_EC035_absent_root_verdict_and_filesystem_unchanged_regression()` (tree byte-identical, exit 0).

### AC-003 (CR-009; the release leg has a fixed filesystem-call budget; traces to BC-1.18.013 Precondition 6(c) release-leg evaluation order (1)-(5) and EC-021 "Release-leg order and silent-before-any-stat"; the budget is NOT in the BC — GAP-S2517-003)
For a `PostToolUse` / `PostToolUseFailure` envelope carrying a valid `tool_use_id`, the release leg issues exactly: one `stat` of `<project_root>/.factory` (`resolve_factory_root`), one presence probe of `migration-state/reservations`, one `unlink` of the reservation file — and no per-component `lstat` walk, no `canonicalize`, no directory listing. An absent or invalid id issues ZERO filesystem calls (unchanged, EC-021). Asserted by a counting filesystem seam; T-1 first records the CURRENT count on the PR #848 head so the removal is measured, not assumed.
- **Test:** `test_BC_1_18_013_EC021_release_leg_valid_id_issues_exactly_three_fs_calls_counting_seam()`, `test_BC_1_18_013_EC021_release_leg_invalid_or_absent_id_issues_zero_fs_calls_regression()`, `test_BC_1_18_013_EC021_release_leg_behavior_unchanged_blackbox()` (reservation removed on Post and PostToolUseFailure; ENOENT silent; non-ENOENT error is one `reservation_release_failed` advisory).

### AC-004 (CR-001; the reservation write is atomic but not durable; traces to BC-1.18.013 Precondition 6(c) reserve-then-verify W1 and "Unconditional reservation namespace", EC-012 (TTL GC reclaims a reservation whose writer is gone), EC-020; the durability class of W1 is NOT stated in the BC — GAP-S2517-004)
W1 (the reservation write, strictly before the gate/txn reads of W2) is performed as write-temp-then-rename in the same directory, so a reader never sees a partial file, WITHOUT `fsync` of the file or the directory; every OTHER admission write (the Branch B txn rewrite, the gate reopen, the terminal-record finalize) keeps `write_atomic_strict_durable` unchanged. Ordering (W1 visible to a coordinator's drain before the admitter reads the gate) is preserved: the rename is the visibility point. Asserted by a counting seam (zero `fsync`/`sync_all`/`F_FULLFSYNC` calls attributable to W1; the strict-durable writes still issue theirs) and measured: T-1 records the median and p95 wall time of the admission leg for a protected write before and after, on macOS and Linux, in the story's Adversarial Review section (the number is evidence, not a threshold invented here). If the architect rules in T-1 that W1 durability is load-bearing for a reason this story missed, the story returns to the story-writer before T-3; the decision is not left open inside implementation.
- **Test:** `test_BC_1_18_013_EC020_reservation_write_issues_no_fsync_counting_seam()`, `test_BC_1_18_013_EC020_strict_durable_writes_unchanged_counting_seam()`, `test_BC_1_18_013_EC020_reservation_visible_to_drain_before_gate_read_ordering_regression()` (existing no-check-then-reserve race test must stay green), `test_BC_1_18_013_EC012_reservation_without_durability_still_reclaimed_by_ttl_gc()`.

### AC-005 (N2; the registry-independent early return prints the trace header; traces to BC-1.18.013 EC-040 (verdict surface label on the real dispatcher stderr) and Postcondition 10 (InternalLog events carry the dispatch's trace id); the header on this path is NOT in the BC — GAP-S2517-005)
Before the registry-independent early return of `main.rs` prints the `plugins_run=... block_intent=true ... blocking_plugins=migration-admission block_reason=...` continuation line, the shell prints the same `factory-dispatcher trace=<id> event=<event> tool=<tool> host_abi=<n> sync_plugins=0 async_plugins=0` header the post-registry path prints (the registry was not loaded on this path, so both plugin counts are literal `0`). Exit codes, the continuation line text and the `blocking_plugins=migration-admission` label (S-25.09 AC-005) are unchanged. No new error code.

### AC-006 (SEC-001 residual; NotebookEdit is in the admission gate's protected-tool set; traces to BC-1.18.013 Precondition 6(b) "Which events / tools" (tool scope: `Edit`/`Write`/`MultiEdit`), EC-021 and Postcondition 10; adding `NotebookEdit` is NOT in the BC — GAP-S2517-006)
The native admission gate treats `NotebookEdit` exactly like `Edit`/`Write`/`MultiEdit`: the protected-tool predicate admits it, the target path is read from the tool's own path field (`notebook_path`; T-1 confirms the field name against a captured real payload and records it, falling back to `file_path` only if the payload carries that), and the SAME classification, reservation, release and verdicts apply (admitted with a reservation, `E-MAINTENANCE-001` block while a txn is live, `E-MAINTENANCE-002` for an invalid `tool_use_id`, release on both Post events).
