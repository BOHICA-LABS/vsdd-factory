# S-6.02: Raise the workspace toolchain 1.95 -> 1.96 and bump wasmtime / wasmtime-wasi to 49.x

> **Epic anchoring rationale (E-6, not E-22 / E-26):** E-22 was DISSOLVED 2026-08-07 (its file is
> retained only as a charter) and cannot host new stories. E-26 is a post-rc.25 hook-hardening
> epic whose five stories ship via the rc.26 release (S-26.05 cuts it); a workspace-wide
> toolchain/MSRV move is not a hook defect, has no rc.26 deadline, and would blur that epic's
> scope and release gate. E-6 ("VSDD Self-Improvement / Tooling Backlog") is the open-ended
> (`status: open`) backlog epic for toolchain and developer-infrastructure work that does not
> ship product behavior; this story fits that charter. Epic story-count / `inputs:` registration
> and the STORY-INDEX row are owed to state-manager (see report).

## Narrative
- **As a** vsdd-factory maintainer responsible for the dispatcher's security and release posture
- **I want to** raise the single workspace toolchain from rustc 1.95 to 1.96 and then move
  `wasmtime` / `wasmtime-wasi` from the 48.x LTS line to 49.x
- **So that** the workspace tracks a current wasmtime major without ever violating the
  single-workspace-MSRV rule, and the operator-facing toolchain floor (ASM-02), CI, release
  cross-compilation and hook-plugin `wasm32-wasip1` builds all move in lockstep

## Context

ADR-035 v1.2 §Decision 6 (2026-10-07) moved the workspace to wasmtime 48.x (min 48.0.4) to clear
RUSTSEC-2026-0316/0314/0321/0322/0323/0324/0327 and explicitly deferred 49.x, because 49.x
requires rustc 1.96 while the workspace is pinned at 1.95 (`rust-toolchain.toml`
`channel = "1.95.0"`, root `Cargo.toml` `rust-version = "1.95"`). The ADR names the toolchain
move as "a **separate planned toolchain-upgrade story**" because it is cross-cutting: CI images,
MSRV, ASM-02 operator toolchain floor, hook-plugin WASM builds. This is that story.

The 1.96 requirement is taken from the ADR; the implementer MUST re-confirm it against the
published `rust-version` of the exact wasmtime 49.x release selected at implementation time
(crates.io metadata), and record the selected version in this story's Library table.

Known toolchain-version sites (non-exhaustive; the implementer MUST grep for `1.95` and
`rust-version` across the repo, including per-crate `Cargo.toml` files, docs, and bats fixtures,
and sibling-sweep per TD-VSDD-060):
- `rust-toolchain.toml` (`channel`)
- root `Cargo.toml` `[workspace.package] rust-version` and any per-crate `rust-version`
- `.github/workflows/ci.yml` (several `dtolnay/rust-toolchain@1.95.0` steps plus comments)
- `.github/workflows/release.yml` (`dtolnay/rust-toolchain@1.95.0`; matrix cross-compile for
  darwin-arm64 / darwin-x86_64 / linux-x86_64 / linux-musl / windows-x86_64; `cross` images;
  `wasm32-wasip1` hook-plugin builds)
- `.github/workflows/kani.yml` (Kani's pinned nightly must remain >= workspace MSRV)
- `.factory/specs/prd.md` ASM-02 ("Operators have a working Rust toolchain >=1.95 for plugin
  authoring") — product-owner-owned; routed, not edited by this story's implementer

### AC-002 (traces to BC-TBD — CI and release toolchain parity)
- Every `dtolnay/rust-toolchain@<ver>` reference in `ci.yml`, `release.yml` and `kani.yml`
  resolves to the same 1.96.x as `rust-toolchain.toml`; the release cross-compile matrix

  `wasm32-wasip1` hook-plugin builds succeed on 1.96; Kani's toolchain remains >= the workspace MSRV.
- **Test:** `test_ci_workflow_toolchain_pins_match_rust_toolchain_toml()` (bats/grep over the
  workflows) plus a green `release.yml` dry run (or `workflow_dispatch` build-only) on the PR.

### AC-003 (traces to BC-TBD — wasmtime 49.x pin and version gate)
- `Cargo.toml` `[workspace.dependencies]` pins `wasmtime` and `wasmtime-wasi` in lockstep at the
  selected 49.x release (minimum = the lowest 49.x that clears all open advisories at
  implementation time); `Cargo.lock` resolves both to that line. The S-21.12 AC-008 Cargo.lock
  floor test (`test_wasmtime_version_satisfies_rustsec_2026_0188_patched_range`, floor already
  raised to `>= 48.0.4` by the wasmtime-48 fix) is raised to the new 49.x floor.
- **Test:** the existing Cargo.lock version-gate test, floor raised; fails against 48.x lockfile
  (Red Gate), passes against 49.x.

### AC-004 (traces to BC-TBD — ASM-02 operator floor; validates ASM-02)
- ASM-02 in `prd.md` states the operator plugin-authoring toolchain floor as >=1.96; operator-facing
  docs and the toolchain-provisioning/preflight surface (e.g. the dx-engineer / setup-env /
  toolchain-provisioning skills and any `rust-version` check they perform) cite 1.96, not 1.95.
  The `prd.md` edit is routed to product-owner; this story's implementer sweeps non-spec docs/skills.
- **Test:** `test_asm_02_operator_toolchain_floor_consistent_across_docs()` — greps the
  operator-facing docs and skills for stale `1.95` toolchain-floor claims.

### AC-005 (traces to BC-TBD — sandbox semantics preserved across 48 -> 49)
- The `wasmtime-wasi` preopen grant remains the exact behavioral equivalent of the pre-upgrade
  grant (full read/write on the preopened directory); the `FsPerms` / `WasiCtxBuilder::preopened_dir`
  API is re-checked against 49.x and migrated mechanically if renamed or reshaped. No widening or
  narrowing of the plugin filesystem capability; SEC-001 preopen hardening remains a separate decision.
- **Test:** `test_wasi_preopen_grant_equivalent_to_full_rw()` (existing/updated sandbox test).

### AC-006 (traces to BC-TBD — fuel/epoch classification unchanged)
- `build_engine`, `invoke_plugin`, and the `Trap::OutOfFuel` / `Trap::Interrupt` classification
  (ADR-047; `TimeoutCause::Fuel` vs `TimeoutCause::Epoch`) behave identically on 49.x;
  `HOST_ABI_VERSION` stays `1`; `FUEL_EXHAUSTED` vs `plugin timed out` block reasons remain distinct.
- **Test:** the existing fuel/epoch classification tests in `crates/factory-dispatcher` re-run
  green with no assertion changes.

### AC-007 (traces to BC-TBD — advisory gate, suites green)
- `cargo deny check advisories` is clean on the 49.x lockfile (no new ignore entries added to
  `deny.toml`); `cargo fmt --check --all`, `cargo clippy --workspace --all-targets -- -D warnings`
  (with any 1.96-new lints fixed in-scope, not allow-listed), `cargo test --workspace --all-targets`

- **Test:** CI jobs `cargo-deny`, fmt/clippy/test, and bats-darwin/linux legs green on the PR.
