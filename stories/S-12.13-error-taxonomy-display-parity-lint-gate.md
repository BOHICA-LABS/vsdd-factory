### AC-001 (traces to BC-TBD postcondition 1 — E-SHD Display ↔ taxonomy parity)

A Cargo integration test `crates/factory-dispatcher/tests/lint_taxonomy_parity.rs` exists and
passes under `cargo test --workspace`. The test:

1. Scans every `*.rs` file under `crates/` (recursively) for `format!` / `#[error(...)]`
   strings matching the pattern `E-SHD-[0-9]+:[^"]*` — this extracts every emitted
   `E-SHD-NNN:` prefix and the literal text that follows it in the Display string.
2. Parses the Message Format column of `error-taxonomy.md`'s Error Catalog table for every
   `E-SHD-NNN` row, extracting the canonical message text (stripping inline parenthetical
   annotations).
3. Asserts that for every `E-SHD-NNN` code found in either side: the Display string emitted
   by the code is a prefix-match or exact-match of the taxonomy's Message Format cell text,
   modulo the standard placeholder conventions (`<artifact>`, `<io-error>`, `<detail>`, etc.
   corresponding to `{artifact_stem}`, `{source}`, `{detail}`, etc. in the format string).
4. Fails (test panics with a diff) when any code found in the Rust source is absent from the
   taxonomy, OR any code present in the taxonomy is absent from the Rust source AND is not
   explicitly marked "NOT YET IMPLEMENTED" in the taxonomy row, OR the emitted Display text
   diverges from the taxonomy Message Format cell.

The test runs as part of `cargo test --workspace --all-targets` (already in `ci.yml`). No
additional CI configuration is required — the existing CI gate picks it up automatically.

**Falsifiable test:** The test itself IS the Red Gate artifact. Pre-implementation: the test
file exists and compiles, but the parsing and diffing logic is `todo!()`. Red Gate = test
panics at the `todo!()`. Green Gate = the test passes with the current E-SHD-001..E-SHD-014
corpus verified correct.

### AC-002 (traces to BC-TBD postcondition 2 — stale pre-implementation narrative gate)

A second Cargo integration test (or a second test function in the same file) flags stale
pre-implementation narrative tokens in doc-comments of GREEN Rust source files.

**Definition of GREEN file:** A `*.rs` source file under `crates/` (not under `tests/` or
`#[cfg(test)]` scope) that contains no `todo!()` macro call outside of `#[cfg(test)]`-gated
blocks. A file is NOT GREEN if it contains any `todo!()` in non-test code — such a file is
legitimately under construction and its "not yet implemented" doc-comments are expected.

**Tokens flagged:** Any of the following appearing on a `///` or `//` doc-comment line (or
in a `/** ... */` doc-comment block) in a GREEN file:
- `NOT YET IMPLEMENTED` (case-insensitive)
- `not yet implemented`
- `// stub` or `/// stub`
- `RED-gate` or `RED gate` (case-insensitive)
- `awaiting implementation`
- `// TODO:` (upper-case TODO in doc-comment — distinguishing from `// todo!()` invocations)

Additionally, in `*_test.rs` and `tests/` files: flag any test function's doc-comment
containing `expected to fail`, `does not yet exist`, `RED surface`, or `not yet implemented`
when the test body contains `assert!()`, `assert_eq!()`, or `assert_ne!()` (i.e., the test
is asserted-passing, not a `todo!()`-gated Red Gate test).

**Falsifiable test:** Same Red Gate / Green Gate pattern as AC-001. The test fails at
`todo!()` pre-implementation; passes once the grep+classification logic is written and
verified clean against the current `crates/` tree.

## Architecture Mapping

| Component | Module | Pure/Effectful |
|-----------|--------|---------------|
| Taxonomy parity lint test | `crates/factory-dispatcher/tests/lint_taxonomy_parity.rs` | Effectful-shell (reads filesystem: `*.rs` source files + `error-taxonomy.md`) |
| Taxonomy parser (extraction helper) | `crates/factory-dispatcher/tests/lint_taxonomy_parity.rs` (inline) or `crates/factory-dispatcher/src/lint_helpers.rs` (if shared) | pure-core (string parsing, no I/O) |
| GREEN-file detector | co-located in `lint_taxonomy_parity.rs` | Effectful-shell (reads filesystem) |

**Note on placement:** Integration tests in `crates/factory-dispatcher/tests/` can access the
filesystem path to `error-taxonomy.md` via the `CARGO_MANIFEST_DIR` env var or a relative
path from the workspace root. The test MUST resolve the taxonomy path relative to
`env!("CARGO_MANIFEST_DIR")/../..` (the workspace root), not hardcoded absolute paths, for
portability across developer machines and CI environments.

## Edge Cases

| ID | Scenario | Expected Behavior |
|----|----------|-------------------|
| EC-001 | A new `E-SHD-NNN` code added to Rust source but not yet added to `error-taxonomy.md` | AC-001 test fails with diff: "E-SHD-NNN found in source but absent from taxonomy" — forces taxonomy update before merge |
| EC-002 | A taxonomy row updated (e.g., wording correction) without a matching Rust source update | AC-001 test fails with diff: "E-SHD-NNN: taxonomy says X but source emits Y" — forces source correction before merge |
| EC-003 | A taxonomy row is marked "NOT YET IMPLEMENTED" (i.e., `E-SHD-004`, `E-SHD-005` at taxonomy v1.0) | AC-001 test skips the diff assertion for that code and passes — implemented codes only are diffed |
| EC-004 | E-SHD-NNN has multiple real emissions under one code (e.g., `E-SHD-002` forms a/b/c, `E-SHD-003` forms a/b) | AC-001 test asserts EACH distinct emitted string against ALL forms documented in the taxonomy row, not just the first |
| EC-005 | A GREEN source file gains a new `todo!()` call (work-in-progress commit) | AC-002 test no longer classifies the file as GREEN — stale-narrative assertions for that file are skipped until the file returns to GREEN (deferred to implementer verification, not a lint failure) |
| EC-006 | `shard_manager.rs` contains a scope-note comment like "// Not yet implemented as of ..." on a shipped variant (e.g., the recurring F-C4-B1-001 pattern) | AC-002 test flags this as stale narrative if the variant's implementation is non-`todo!()` — forces the scope-note to be removed or reworded before merge |
| EC-007 | Lint test cannot locate `error-taxonomy.md` at the resolved relative path | Test fails with a clear "taxonomy file not found at <path>" panic — never silently passes due to a missing input file |
