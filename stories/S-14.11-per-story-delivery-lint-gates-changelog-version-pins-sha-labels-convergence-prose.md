### Part (d) — Version-pin gate over every changed path

Background: the gate was declared closed twice while pins survived (Background item 2).

### AC-005 (was S-14.10 AC-013; version-pin sweep over the whole diff; traces to BC-5.39.001 postcondition 6 (the gate is a pre-dispatch condition inside the Step 4.5 loop, wired by AC-008) and BC-8.31.001 postcondition 1 (extended); rule content NEW clause owed — GAP-S1411-002; extends the [D-1255-CHANGELOG-PINS] rule from CHANGELOG entries to every added line)
A new subcommand `story-delivery-gates check-version-pins --base <rev> [--allowlist <file>]` (pure core `scan_added_lines(diff_added_lines, allowlist)` in the `story-delivery-gates` library; POLICY 21: Rust, no shell) enforces, as a gate run by the orchestrator before every adversary pass and before push, and by `ci.yml` on PRs:
1. **Scope is EVERY path** in `git diff --name-only <base>..HEAD` (no directory filter: `crates/`, `.factory/`, `plugins/`, docs, workflows, templates, CHANGELOG all included; renames and binary files are listed, binary files skipped with an explicit `skipped binary` line). Only ADDED lines (`+` lines of `git diff -U0 <base>..HEAD`, excluding `+++` headers) are scanned; removed and context lines are never scanned.
2. **Two sweeps on each added line:** the PREFIXED pattern `(BC-[0-9]+\.[0-9]+\.[0-9]+|VP-[0-9]+|error-taxonomy|ADR-[0-9]+|S-[0-9]+\.[0-9]+) ?\(?v[0-9]+\.[0-9]+` AND the BARE sweep `\bv[0-9]+\.[0-9]+\b`. A line matching either is a violation unless allowlisted.
3. **Literal output (D-449(a)):** every hit is printed as `path: line` (the path, then the added line's number and text) with the matched token, the full path list scanned is printed first as `scanned: <path>` lines, and the run ends with a literal summary line `version-pin-gate: <n> violation(s) over <m> path(s) (base <rev>, head <sha>)`; exit 0 when n = 0, exit 1 otherwise, exit 2 on a git failure or unreadable allowlist. No pseudocode attestation: the burst log pastes this stdout verbatim.
4. **Explicit allowlist mechanism:** an allowlist file (a checked-in, reviewed file; default `.factory/policies/version-pin-allowlist.toml` when present, else none; changes to it go through review like any spec file) holds entries `{ path = <glob>, pattern = <regex or literal>, justification = <non-empty, min 10 chars> }`; an entry with an empty or too-short justification is rejected (exit 2); every allowlisted match is still PRINTED as `allowed: path:line:<text> (justification: …)` so provenance text (for example a changelog row recording which BC version a burst cited) is visible, never silently dropped. An inline marker is NOT supported (no silent per-line escapes).
- **Test (Rust):** `test_S1411_AC005_scans_every_changed_path_not_only_crates()` (fixture git repo with pins in a story file, a plan file and a crate file; all three reported), `..._prefixed_regex_matches_bc_vp_adr_s_error_taxonomy_forms()`, `..._bare_v_x_y_sweep_matches_a_prefixless_pin()`, `..._ignores_removed_and_context_lines()`, `..._output_lists_scanned_paths_and_the_literal_summary_line()`, `..._allowlist_entry_suppresses_but_still_prints_the_match_with_justification()`, `..._allowlist_entry_without_justification_exits_2()` and `..._exits_2_on_git_failure()` in `crates/story-delivery-gates/tests/check_version_pins.rs`; and `test_S1411_AC005_ci_workflow_invokes_the_gate()`.

### Part (e) — SHA-label truth check

Background: Background item 3. A label is a claim; the gate must verify the claim.

### AC-006 (was S-14.10 AC-014; SHA-label truth check; traces to BC-5.39.001 postcondition 6 (the gate is a pre-dispatch condition inside the Step 4.5 loop, wired by AC-008); rule content NEW clause owed — GAP-S1411-003; closes F-S2508-L10-001 and F-S2508-L11-001)
A new subcommand `story-delivery-gates check-sha-labels <story-file> <worktree> [--branch <ref>]` (pure core `check_sha_labels(cited_shas, split_ranges, reflog, reachability)` in the `story-delivery-gates` library; POLICY 21: Rust, no shell; the only external process is `git`) verifies every commit SHA the story cites, by the label the story gives it:
1. **What is scanned and what a label is.** Every backtick-quoted token of 7 to 40 lowercase hex characters anywhere in the story file (frontmatter `last_amended:` text, Tasks, body, Changelog; `input-hash:` values and the Delivery Reconciliation Ledger's own `reconciled_through` column excepted). A label is the word that immediately follows the closing backtick, bare or in parentheses: `pre-split`, `pre-rebase`, or `on <ref>`. A SHA introduced by `earlier:` is a `pre-rebase` SHA by the story convention `(earlier: <sha>)`. A SHA with no label is UNLABELLED.
2. **`pre-split`:** the SHA must be a member of a split range RECORDED in the story's Delivery Reconciliation Ledger (new sub-table `Recorded Split Ranges`, columns `| split | base | tip |`, added to the S-14.10 ledger section of the story template by this AC and written by the story-writer at the reconcile that records the split), i.e. it appears in `git rev-list <base>..<tip>`. A story that uses the label with no recorded split range is a violation (exit 1, "no recorded split range"), never a silent pass.
3. **`pre-rebase`:** the SHA's subject (`git log -1 --format=%s <sha>`) must match a LATER `rebase (pick): <subject>` entry in the worktree HEAD reflog (`git -C <worktree> reflog show --format=...`), whose resulting SHA differs from the labelled SHA and is reachable from `<ref>` (default: the story branch `feature/<story-id>`). A subject match with no later pick, or a pick whose result is unreachable, is a violation.
4. **`on <ref>`:** `git merge-base --is-ancestor <sha> <ref>` must hold for the named `<ref>`.
5. **UNLABELLED:** `git merge-base --is-ancestor <sha> <story-branch>` must hold.
6. **Literal output (D-449(a)):** one line per cited SHA `<sha> | <label or unlabelled> | <rule applied> | OK|FAIL | <evidence: range member / matching pick sha / merge-base result>`, preceded by `scanned: <story-file>` and followed by the literal summary line `sha-label-gate: <n> violation(s) over <m> cited sha(s) (story <id>, branch <ref>, head <sha>)`; exit 0 when n = 0, exit 1 otherwise, exit 2 on a git failure, a missing story file, or an unresolvable `<ref>`. No pseudocode attestation: the burst log pastes this stdout verbatim.
- **Test (Rust):** `test_S1411_AC006_pre_split_sha_inside_recorded_range_passes_and_outside_fails()` (the pass-11 vector: an S-25.09-native commit created after the split and labelled `pre-split` is reported FAIL), `..._pre_split_label_without_a_recorded_range_exits_1()`, `..._pre_rebase_sha_with_a_later_pick_of_the_same_subject_passes()`, `..._pre_rebase_sha_with_no_later_pick_fails()`, `..._pre_rebase_pick_that_is_unreachable_from_the_branch_fails()`, `..._on_ref_label_requires_ancestry_of_that_ref()`, `..._unlabelled_sha_must_be_reachable_from_the_story_branch()` (the pass-10 vector), `..._earlier_prefix_is_treated_as_pre_rebase()`, `..._input_hash_values_and_ledger_reconciled_through_are_not_scanned()`, `..._output_has_one_literal_line_per_sha_and_the_summary_line()` and `..._exits_2_on_git_failure_or_unresolvable_ref()` in `crates/story-delivery-gates/tests/check_sha_labels.rs` (fixture git repository built with `tempfile` that performs a real split and a real `git rebase`, so the reflog `rebase (pick)` entries are genuine); `test_S1411_AC006_story_template_ledger_carries_the_recorded_split_ranges_sub_table()` in `crates/story-delivery-gates/tests/workflow_docs.rs`.

### Part (f) — Persist-task parity and convergence prose

Background: Background item 4.

### AC-007 (was S-14.10 AC-015; persist-task parity and convergence-prose lint; traces to BC-6.04.006 postcondition 1 (findings file exists at the target path via a state-manager dispatch) and BC-5.39.001 postcondition 1 (each pass result is recorded); rule content NEW clause owed — GAP-S1411-004; closes F-S2508-L8-004, F-S2508-L10-002 and F-S2508-L12-001)
A new subcommand `story-delivery-gates check-convergence-prose <story-file> [<code-delivery-dir>]` (default dir `.factory/code-delivery`; pure cores `check_persist_parity(ticked_persist_tasks, persisted_files)` and `lint_convergence_prose(section_text)` in the `story-delivery-gates` library; POLICY 21: Rust, no shell; read-only) enforces two rules and exits on the worse of the two:
1. **Parity (R1).** Let T be the set of pass numbers N for which the story's Tasks hold a TICKED (`[x]`) persist task, i.e. a checklist line that contains the token `adv-local-pass-<N>.md` and the word `persist` (the task S-14.10 AC-006 adds per pass), and F the set of N for which `<dir>/<story-id>/adv-local-pass-<N>.md` exists. R1 holds iff T = F, which implies the counts are equal. On a difference the gate exits 1 and names each N present on one side only (`pass 11: file present, no ticked persist task` / `pass 12: ticked persist task, no file`) and prints both counts.
2. **No restatement (R2).** The story's convergence prose is every paragraph under a heading whose text contains `Convergence` or `Adversarial Review`. It MUST NOT contain (a) a persisted-file count (a digit or number word one..twenty immediately followed by `review file` / `review files` / `files persisted`, or the phrase `are persisted` after a file range such as `adv-local-pass-1.md .. adv-local-pass-8.md`), or (b) a persist-task status (a task id `T-<n>` followed within 40 characters by `OPEN`, `DONE`, `ticked`, `pending` or `not persisted`, or the phrase `is not persisted until`). It MAY name the folder path and MAY point to the persist tasks without stating their status (for example "persistence is recorded by the persist tasks and the code-delivery folder"). Each hit is reported as `<story-file>:<line>: <matched token>`.
3. **Literal output (D-449(a)):** the gate prints `ticked persist tasks: <n> (<sorted pass list>)`, `persisted files: <m> (<sorted pass list>)`, each R2 hit, and the literal summary line `convergence-prose-gate: <v> violation(s) (parity <ok|fail>, prose <ok|fail>, story <id>)`; exit 0 when v = 0, exit 1 otherwise, exit 2 on a missing story file, an unreadable directory, or a story whose Tasks section cannot be found.
- **Test (Rust):** `test_S1411_AC007_parity_ok_when_ticked_persist_tasks_equal_files_on_disk()`, `..._pass_12_vector_file_present_and_task_ticked_but_prose_says_open_is_reported()` (the L12-001 vector, built from the three S-25.08 paragraphs quoted in the Background), `..._exit1_names_each_pass_present_on_one_side_only()`, `..._unticked_persist_task_does_not_count_as_persisted()`, `..._prose_with_a_review_file_count_or_number_word_is_reported()`, `..._prose_with_a_task_id_and_open_or_done_is_reported()`, `..._prose_that_only_points_to_the_folder_and_tasks_passes()`, `..._text_outside_convergence_and_adversarial_review_headings_is_not_linted()`, `..._output_has_both_lists_and_the_literal_summary_line()` and `..._exit2_for_missing_file_unreadable_dir_or_no_tasks_section()` in `crates/story-delivery-gates/tests/check_convergence_prose.rs`.
