# S-25.12: Closure of the ADR-054 Chain - `decide_recovery` Kani Totality (h1b), Hardened Operator Runbook and Sibling-Sweep Evidence (slice 3 of 3)

## Narrative

- **As a** factory maintainer who must be able to certify that the migration recovery decision is total, that an operator can verify a crashed migration with the runbook alone, and that no half-renamed state survives in the tree
- **I want** a Kani proof that `decide_recovery` returns exactly one outcome for every input and matches the seven-row table, an operator runbook whose commands reproduce the golden vector, and captured literal-shell evidence that the old field name, the old struct, the old markers outside the module and the deleted functions are gone
- **So that** the `FailClosed` / `TreatDone` / `AlreadyDone` / `RedoRename` decision cannot regress silently (the OBL-1 CI job pins eleven harnesses), an operator performing the interim six-step verify-then-finalize follows exactly the steps ADR-052 item 11(e) now specifies, and S-25.06 can rebase onto a tree with no second copy of anything
