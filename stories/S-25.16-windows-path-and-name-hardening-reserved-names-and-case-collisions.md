# S-25.16: Windows Path and Name Hardening for the Admission Gate

**Epic:** E-25 - Validation Integrity and Large-Artifact Resilience
**Depends on:** S-25.08 (PR #848)
**Blocks:** (none)
**Priority:** P2
**Origin:** PR #848 code-reviewer CR-010 and security-reviewer SEC-004 (carried forward by the human decision of 2026-10-13, D-1264(a)/(i); "story anchors for the rest")

## Narrative

- **As a** factory operator running the dispatcher on Windows (and on case-insensitive macOS volumes)
- **I want** the writer-admission gate to classify a protected path by the platform's real name-equivalence rules (trailing dots and spaces, the verbatim `\\?\` prefix, reserved device names, the volume's case folding) and to key reservations by a `tool_use_id`-derived file name that no reserved device name and no case-only variant can alias
- **So that** a spelling the filesystem treats as the governed tree cannot slip past the classifier, and two concurrent writers whose ids differ only by case cannot share one reservation file (the first release would delete the second writer's interlock while it is still writing)

## Problem Statement

**CR-010 (classification).** S-25.08's classifier (BC-1.18.013 Precondition 6(b)(ii)/(iv)) compares components with an ASCII fold plus `str::to_lowercase`. Windows resolves several further spellings to the same name: a component with trailing dots or spaces (`.factory.`, `Cycles `) names `.factory` / `Cycles`; `\\?\C:\proj\.factory\cycles\x` names the same file as `C:\proj\.factory\cycles\x`; NTFS compares through the volume's upcase table, whose simple-uppercase mappings differ from `to_lowercase` for some non-ASCII letters (`ſ` (U+017F) uppercases to `S`, `ı` (U+0131) to `I`), so `.factory\ſpecs\behavıoral-contracts\x` can name the governed family; and a reserved device name component (`CON`, `NUL`, `COM1`, ...) must never be `lstat`-ed by the real-form walk (an `lstat` of a serial-device name can block or return device metadata). The BC states none of this.

**SEC-004 (`tool_use_id`).** The grammar `[A-Za-z0-9_.-]{1,128}` (no leading `.`) admits ids that the Windows filesystem treats specially once `.reservation` is appended: `CON`, `NUL`, `COM1`, `con.x` (a reserved device name with ANY extension is still the device). It also admits ids differing only by case (`toolu_Abc`, `toolu_aBC`) which map to ONE reservation file on a case-insensitive volume (Windows, default macOS): writer A's release removes writer B's reservation while B's write is still in flight, so a coordinator drain can reach quiescence with a writer active — the interlock S-25.08 exists to provide. Real harness ids are `toolu_<alphanumerics>` and mixed-case, so the collision is reachable, not theoretical.

**Claim boundary (stated honestly).** The Windows name-equivalence classes below are the ones the code reviewer named plus the documented NTFS/Win32 path-normalization behaviors; the story's T-1 verifies each on a real Windows runner and records the result, and any class it cannot confirm is asserted as in-scope anyway (the union is fail-closed: over-matching costs one spurious reservation, never a missed protection). 8.3 short names (`FACTOR~1`) and NTFS alternate data streams (`.factory::$INDEX_ALLOCATION`) are evaluated in T-1 and either handled in AC-001 or recorded as accepted residuals with the reason; they are not silently dropped.

## Acceptance Criteria

> Every black-box assertion uses the real `factory-dispatcher` binary (spawned process, PreToolUse / PostToolUse envelope on stdin, a tempdir project with a `.factory/`), never a direct call of a function alone — a unit test cannot see a missing call site (S-25.08 claim boundary). Unit tables run on every host: the platform rules are a PARAMETER (`PlatformPathRules::{Windows, Unix}`), production passes the host's, tests pass both, so the Windows tables are exercised on the Linux and macOS jobs as well as the Windows job.

### AC-001 (CR-010; component equivalence key in the ONE classification function; traces to BC-1.18.013 Precondition 6(b)(ii) component-wise classification and 6(b)(iv)(f) case rule; the equivalence classes are NOT in the BC — GAP-S2516-001)
A pure `component_key(component: &OsStr, rules: PlatformPathRules) -> ComponentKey` is the only comparison primitive the classifier and `factory_root` prefix match use. Under `Windows` rules it (a) strips trailing `.` and ` ` characters, except for the components `.` and `..` themselves; (b) treats a `\\?\` verbatim disk prefix as equal to its non-verbatim form; (c) compares case under BOTH the simple lowercase and the simple uppercase fold (a union: equal under either => equal). Under `Unix` rules the behavior is exactly today's (ASCII fold plus `to_lowercase`; nothing stripped).
- Vectors (each classified IN SCOPE under Windows rules, as the matching governed path): `.factory./cycles/x`, `.factory /cycles/x`, `.factory\Cycles.\x`, `.factory\cycles \x`, `\\?\C:\proj\.factory\cycles\x`, `.factory\ſpecs\behavıoral-contracts\x`. Look-alikes stay OUT of scope under both rules (BC-1.18.013 EC-023(d)): `x.factory\cycles\x`, `.factory-old\cycles\x`, `.factoryx\cycles\x`.
- **Test:** `test_BC_1_18_013_EC023_windows_component_key_equivalence_table()`, `test_BC_1_18_013_EC023_unix_rules_unchanged_regression_table()`, `test_BC_1_18_013_EC023_lookalikes_stay_out_of_scope_under_both_rules()` (unit); `test_BC_1_18_013_EC023_windows_equivalent_spellings_are_admitted_with_reservation_blackbox()` (real binary).

### AC-002 (CR-010; reserved device names are never `lstat`-ed; traces to BC-1.18.013 Precondition 6(b)(iv)(d) real-form walk, non-`NotFound` error => `T_real` unavailable and classification proceeds on `T_lex`, fail-closed; the reserved-name handling is NOT in the BC — GAP-S2516-002)
Under `Windows` rules a component whose stem (the text before the first `.`, trailing dots/spaces stripped, case-folded) is one of `CON`, `PRN`, `AUX`, `NUL`, `COM1`..`COM9`, `LPT1`..`LPT9`, `CONIN$`, `CONOUT$` (the superscript-digit forms `COM¹ COM² COM³ LPT¹ LPT² LPT³` included) ends the real-form walk exactly like a non-`NotFound` error: no `lstat`/`open` of that component is issued, `T_real` is unavailable, and the path is classified on `T_lex` alone (fail-closed). Asserted with a counting filesystem seam: zero filesystem calls name a reserved-device component.
- **Test:** `test_BC_1_18_013_EC024_reserved_device_component_is_never_statted_counting_fs()`, `test_BC_1_18_013_EC024_reserved_device_component_classified_on_lexical_form()`, `test_BC_1_18_013_EC024_reserved_stem_table_windows_vs_unix_rules()`.

### AC-003 (CR-010; T-1 evidence for the classes not asserted above; traces to BC-1.18.013 Precondition 6(b)(v) residuals, 6(b)(iv)(e) either-form union)
T-1 records, from a real Windows runner (the existing `cargo-host` Windows job), whether each of: 8.3 short name of `.factory` (`FACTOR~1`), `.factory::$INDEX_ALLOCATION` / `::$DATA` stream suffixes, a `\\.\` device-namespace prefix and a UNC `\\server\share` spelling of the same tree resolves to a governed file. Each confirmed class is added to AC-001's table with a vector; each unconfirmed class is recorded in BC-1.18.013's residual list by the product-owner (GAP-S2516-003) with the evidence. The recorded evidence lives in the story's Adversarial Review section at delivery; no class is left unexamined.
- **Test:** `test_BC_1_18_013_EC024_windows_runner_probe_records_equivalence_classes()` (`#[cfg(windows)]`, prints one `CLASS=<name> RESOLVES=<yes|no>` line per class; CI greps the lines, no silent pass); one vector per confirmed class under AC-001.

### AC-004 (SEC-004 part 1; reserved device names in `tool_use_id`, decided from the payload alone on EVERY platform; traces to BC-1.18.013 Precondition 6(c) "`tool_use_id` presence and validity" (grammar, fail-closed `E-MAINTENANCE-002` `invalid_tool_use_id`, byte length only, release-leg silent no-op) and EC-026; the reserved-name rule is NOT in the BC — GAP-S2516-004)
`is_valid_tool_use_id` additionally rejects an id whose stem (the text before the first `.`, case-folded) is a reserved device name from AC-002's list, on every host platform (the verdict is a pure function of the payload, never of the host, so tests and operators see one behavior). The admission leg fails closed with `E-MAINTENANCE-002: writer-admission check failed (invalid_tool_use_id)` (exit 2, NO reservation, the error carries the byte length only); the release leg treats it as the existing fully silent no-op before any filesystem access. Ids of the real harness form (`toolu_<alphanumerics>`) and every id matching EC-026(i) that does not have a reserved stem remain valid. Error codes: only the existing `E-MAINTENANCE-002` (`invalid_tool_use_id`); NO new code.
- Vectors: `NUL`, `nul`, `CON`, `con.txt`, `Com1`, `LPT9.x`, `AUX` rejected; `toolu_NUL`, `console`, `nul_x`, `communicate`, `COM10` (not a reserved name), `toolu_` + 122 alphanumerics accepted.
- **Test:** `test_BC_1_18_013_EC026_reserved_device_stem_tool_use_id_fails_closed_blackbox()`, `test_BC_1_18_013_EC026_reserved_stem_near_misses_stay_valid()`, `test_BC_1_18_013_EC026_release_leg_reserved_stem_is_silent_noop_before_any_stat()` (counting seam: zero filesystem calls), `test_BC_1_18_013_EC026_validity_is_platform_independent()`.

### AC-005 (SEC-004 part 2; the reservation file name is injective under case folding; traces to BC-1.18.013 Precondition 6(c) "Unconditional reservation namespace" (`reservations/<tool_use_id>.reservation` created at admission, removed at release) and EC-021, EC-012; the file-name form is NOT in the BC — GAP-S2516-004)
One pure function `reservation_file_name(tool_use_id: &str) -> String` is the ONLY place a reservation file name is built; admission create, the release-leg unlink and the drain GC all call it (source gate: no `format!`/`join` of a raw `tool_use_id` + `.reservation` anywhere else in `crates/factory-dispatcher/src`). The name is `<ascii-lowercased id>~<first 16 hex of sha256(raw id bytes)>.reservation`: two ids that differ only by case produce DIFFERENT names on every platform (the hash covers the raw bytes), the name has no reserved stem (AC-004 already excluded them, and the stem is `<id>~<hex>`), and its length is at most 128 + 1 + 16 + 12 = 157 bytes (< 255). The drain's reservation listing and the GC read only the directory entries and the file CONTENT (`created_at`); no code derives a `tool_use_id` from a file name (T-1 sweeps and records this). **Upgrade window:** a reservation created by a build that used the old name is not found by the new release leg and ages out by the TTL GC (it is listed by its `*.reservation` suffix); this is the same designed residual as EC-021 and is stated in the CHANGELOG entry.
- **Test:** `test_BC_1_18_013_EC021_case_variant_ids_get_distinct_reservation_files_blackbox()` (two admissions `toolu_Abc` / `toolu_aBC` in flight: two files exist; releasing one leaves the other; the drain stays blocked until the second is released), `test_BC_1_18_013_EC021_reservation_file_name_pure_table()`, `test_BC_1_18_013_EC021_no_raw_id_reservation_join_outside_the_helper_source_gate()` (literal-shell sweep with captured stdout, TD-VSDD-060), `test_BC_1_18_013_EC012_drain_gc_lists_new_form_names()`.

### AC-006 (real-binary vectors run on all three host OS jobs; traces to BC-1.18.013 EC-021, EC-023, EC-024, EC-026; VP-143 D1 black-box)
The black-box tests of AC-001, AC-004 and AC-005 run in the Linux, macOS and Windows `cargo-host` jobs. On the host OS where a vector cannot run (the `\\?\` prefix vector on Unix; the reserved-device `lstat` probe off Windows), the test asserts the pure-function half on every host and the real-filesystem half only where applicable; a skipped real-filesystem half prints one `SKIPPED(reason): <test>` line (never a silent pass; see S-25.18 AC-004 for the repository-wide skip convention).
- **Test:** `test_BC_1_18_013_EC023_windows_vectors_run_on_windows_job_and_emit_no_silent_skip()` (CI log assertion), the AC-001..AC-005 tests above.

## Edge Cases

|----|----------|-------------------|

| EC-003 | Two writers in flight with ids differing only by case | Two distinct reservation files; each release removes only its own (AC-005) |
| EC-004 | A reservation made by the previous build (old name) at upgrade | Not found by release; reclaimed by the TTL GC; documented residual (AC-005) |
| EC-005 | Component `COM10`, `console`, `nul_x` | Not reserved (stem must equal exactly) |
| EC-006 | `..` / `.` components | Never stripped or treated as trailing-dot names (AC-001(a)) |
| EC-007 | Non-UTF-8 component under Windows rules | ASCII-fold bytewise as today; the equivalence key applies only to UTF-8 components (WTF-8 on Windows is converted lossily for the key only, never for the path used for I/O) |
