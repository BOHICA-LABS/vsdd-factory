# S-25.09: Admission Diagnostics as InternalLog Events + Single Session-Root Anchoring + Closed Verdict Label + Neutral Entry-Point Names (ADR-052 v1.21)

## Narrative

- **As a** factory pipeline operator who must be able to see WHY a protected write was blocked and who relies on the
  governed one-time migrations (`migrate-bc-index`, `backfill-append-logs`) actually excluding concurrent writers
- **I want** the admission gate and both migration coordinators to anchor on ONE session-project-root rule, every
  admission/reconciliation/release diagnostic to reach `dispatcher-internal-*.jsonl` as a typed InternalLog event
  (not a `tracing` call the production dispatcher discards), admission verdicts to carry their own
  `migration-admission` label, state-integrity failures to carry their own error variant, and the shared core's entry
  points to carry migration-neutral names
- **So that** the Dekker interlock between the PreToolUse gate and the coordinator can never silently guard nothing
  (the gate and the coordinator resolving different `.factory` trees), an operator reading the dispatcher log or the
  stderr summary sees an accurate, bounded, sanitized account of every block/failure/advisory, a corrupt migration
  state is never reported as a binary-integrity failure, and the shared admission core cannot acquire a second
  per-migration implementation under a second name

### AC-001 (formerly S-25.08 AC-021; D-2; single session-project-root anchoring rule for admission, the release leg AND both coordinators; traces to BC-1.18.013 Precondition 6(b)(i) Anchor, Precondition 7, Invariant 8, EC-033, EC-034, EC-035, EC-036; BC-1.18.011 Precondition 6(b)(i), Precondition 7, Invariant 6, EC-027, EC-028, EC-029, EC-030; ADR-052 §Decision 5a "Single anchoring rule — admission AND both coordinator binaries"; VP-143 D1)

(a) *One pure function.* `resolve_session_project_root(claude_project_dir: Option<&OsStr>, process_cwd: &Path) ->
SessionProjectRoot { path: PathBuf, source: ProjectRootSource }` (`ProjectRootSource { ClaudeProjectDir,
ProcessCwd }`, label tokens `CLAUDE_PROJECT_DIR` / `process cwd`) is a `pub` pure function (no env read, no ambient
cwd; the type lives in `shard_manager/admission.rs` and is re-exported by `shard_manager.rs`): a PRESENT non-empty
`CLAUDE_PROJECT_DIR` wins and is canonicalized (a canonicalize failure falls back to the as-given path — NEVER to
the cwd); an absent or empty value falls back to `process_cwd` exactly (NO ancestor walk for a `.factory`, NO
`git rev-parse`). `main.rs::resolve_project_cwd()` is reduced to a call to it (env read in the shell, rule in the
pure function). Unit table (BC-1.18.013 EC-034): (a) `Some(<abs existing dir>)`; (b) `Some("")`; (c) `None`; (d)
`Some(<abs nonexistent path>)`; (e) `Some(<symlink to dir>)`; (f) a `process_cwd` below a git work-tree root that
has a `.factory` => the cwd, NOT the work-tree root.
(b) *One derivation.* `resolve_factory_root(project_root)` is the ONLY way admission, the release leg and the
`migrate-bc-index` coordinator obtain a factory root; `migration-state/` is `FactoryRoot::migration_state_dir()`;
EVERY other path `run_bc_index_migration` reads or writes (`specs/behavioral-contracts/BC-INDEX.md`, `…/shards`,
`cycles/…`, the activation manifest) is derived from the SAME resolved real factory root. The six
`_cwd.join(".factory/…")` literals are REMOVED; the coordinator parameter formerly named `_cwd` is renamed
(`project_root` — it was never a cwd, and the underscore is dropped because it is used). `main.rs` computes the
project root with (a) from `std::env::var_os("CLAUDE_PROJECT_DIR")` and `std::env::current_dir()` for BOTH
`migrate-bc-index` routes. Sibling-sweep gate (source-level, deterministic): `grep -n 'join(".factory'
crates/factory-dispatcher/src/shard_manager.rs` returns only the resolver.
(c) *Fail-closed on a missing factory root; the `root_source` field.* A project root with no `.factory` directory
(absent, or a regular file) => `BcIndexMigrationError::FactoryRootNotFound { project_root: PathBuf, root_source:
Option<ProjectRootSource> }` (the field is `root_source`, NOT `source`: `thiserror` treats a field named `source` as
the error's `Error::source()` and would not compile — BC-1.18.013 Precondition 7 "Field name"), migration-binary
exit 2 `FACTORY_ROOT_NOT_FOUND`, NOTHING created (no `.factory`, no `exclusive.lock`, no `migration-state/`, no gate
write), nothing on stdout, and EXACTLY this single stderr line (normative; error-taxonomy v1.39 row):
`<subcommand>: FACTORY_ROOT_NOT_FOUND: no .factory directory under project root <project_root> (resolved from
<source>)` where `<subcommand>` ∈ {`migrate-bc-index`, `backfill-append-logs`} (this story delivers the
`migrate-bc-index` route and the shared variant; the `backfill-append-logs` route is S-25.06 AC-035), `<source>` ∈
{`CLAUDE_PROJECT_DIR`, `process cwd`} and `<project_root>` has control characters escaped; the variant's Display is
exactly the text after `<subcommand>: `. **Optionality (BC-1.18.013 Precondition 7 "Optionality" rule (a), normative):** the CLI route
threads the WHOLE `SessionProjectRoot` (path AND source, as `resolve_session_project_root` returned it — never
re-read from the environment) to `run_bc_index_migration_for_session(&SessionProjectRoot)`, so `root_source = Some(_)`
on every CLI-reachable `FactoryRootNotFound` and the operator line ALWAYS carries the ` (resolved from <source>)`
suffix; the path-only library entries (`run_bc_index_migration(&Path)` and the crate-private
`run_bc_index_migration_with_ttl(&Path, ttl)`) have no source to report, are permitted (embedding / test seams, not
invoked by a CLI route) and set `root_source = None`, whose Display omits the suffix entirely (no trailing space, no
` (resolved from )`). The coordinator NEVER creates `.factory` and never falls back to another directory.
(d) *Real-binary vectors* (BC-1.18.013 EC-033 / EC-036; BC-1.18.011 EC-027 / EC-030): (i) process cwd !=

## Architecture Compliance Rules

The implementer MUST NOT violate any of these; violations are bugs, not style preferences.

1. **One anchoring rule (ADR-052 §Decision 5a "Single anchoring rule"; BC-1.18.013 Precondition 6(b)(i)/7):**
   admission, the release leg and every coordinator obtain the project root ONLY from `resolve_session_project_root`
   and the factory root ONLY from `resolve_factory_root`; no `join(".factory` outside the resolver; no ancestor walk;
   never create `.factory`; a missing `.factory` is `FACTORY_ROOT_NOT_FOUND` with nothing created.
2. **One diagnostics channel, no `tracing` reliance (ADR-052 §Decision 5a "Admission diagnostics channel"):** every
   admission/reconciliation/release diagnostic is an `InternalLog` event written by `main.rs` from `AdmissionDiagnostic`
   data — the core and the executor entry points never touch the log, and a diagnostic is NEVER emitted through
   `tracing` (the dispatcher installs no subscriber; installing one is out of scope); no event field or stderr line
   carries a raw `tool_use_id` or record content; every untrusted string passes the single sanitizer.
3. **Closed domains are enums, matches are exhaustive:** `AdmissionStateIntegrityKind`, `AdmissionFailureCause`,
   `NativeGate`, `ProjectRootSource` and the `check` token set carry no wildcard arm; the `reconciliation` / `branch` /
   `reason` / `check` event vocabularies are the closed domains of AC-002 (six / five / five / nine tokens).
4. **One set of migration-neutral entry points:** `migration_writer_admission` / `migration_writer_admission_precheck` /
   `migration_reservation_release` are the only admission entry points; no per-migration delegate, no
   `append_log_backfill_*`, no second reserve/verify implementation.
5. **The shared core is evaluated exactly once per PreToolUse event, registry-independent, ahead of
   `shard_cap_precheck` (S-25.08 AC-001/AC-002/AC-012):** this story must not change the evaluation position or add a
   second evaluation; the diagnostics drain runs after the single call and BEFORE the early return on a verdict.
6. **Error codes: ONLY existing taxonomy entries (error-taxonomy v1.39):** `E-MAINTENANCE-001` / `E-MAINTENANCE-002`

7. **No WASM-sandboxed executor (ADR-051 §Decision 7 / CLAUDE.md §WASM plugin fuel budgets):** the admission core and
   the diagnostics drain run native in the dispatcher binary, never inside a hook plugin.
8. **Single-commit-per-burst / POL-3 (TD-VSDD-053, TD-FACTORY-HOOK-BYPASS-001):** no `.factory/` mutation by shell
   bypass; this story does not touch live cycle files.
