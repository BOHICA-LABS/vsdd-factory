# S-25.09: Admission Diagnostics as InternalLog Events + Single Session-Root Anchoring + Closed Verdict Label + Neutral Entry-Point Names (ADR-052 v1.21)

## Narrative

- **As a** factory pipeline operator who must be able to see WHY a protected write was blocked and who relies on the
  governed one-time migrations (`migrate-bc-index`, `backfill-append-logs`) actually excluding concurrent writers
- **I want** the admission gate and both migration coordinators to anchor on ONE session-project-root rule, every
  admission/reconciliation/release diagnostic to reach `dispatcher-internal-*.jsonl` as a typed InternalLog event
  (not a `tracing` call the production dispatcher discards), admission verdicts to carry their own
  `migration-admission` label, state-integrity failures to carry their own error variant, and the shared core's entry
  points to carry migration-neutral names
- **So that** the Dekker interlock between the PreToolUse gate and the coordinator can never silently guard nothing
  (the gate and the coordinator resolving different `.factory` trees), an operator reading the dispatcher log or the
  stderr summary sees an accurate, bounded, sanitized account of every block/failure/advisory, a corrupt migration
  state is never reported as a binary-integrity failure, and the shared admission core cannot acquire a second
  per-migration implementation under a second name

## Architecture Compliance Rules

The implementer MUST NOT violate any of these; violations are bugs, not style preferences.

1. **One anchoring rule (ADR-052 §Decision 5a "Single anchoring rule"; BC-1.18.013 Precondition 6(b)(i)/7):**
   admission, the release leg and every coordinator obtain the project root ONLY from `resolve_session_project_root`
   and the factory root ONLY from `resolve_factory_root`; no `join(".factory` outside the resolver; no ancestor walk;
   never create `.factory`; a missing `.factory` is `FACTORY_ROOT_NOT_FOUND` with nothing created.
2. **One diagnostics channel, no `tracing` reliance (ADR-052 §Decision 5a "Admission diagnostics channel"):** every
   admission/reconciliation/release diagnostic is an `InternalLog` event written by `main.rs` from `AdmissionDiagnostic`
   data — the core and the executor entry points never touch the log, and a diagnostic is NEVER emitted through
   `tracing` (the dispatcher installs no subscriber; installing one is out of scope); no event field or stderr line
   carries a raw `tool_use_id` or record content; every untrusted string passes the single sanitizer.
3. **Closed domains are enums, matches are exhaustive:** `AdmissionStateIntegrityKind`, `AdmissionFailureCause`,
   `NativeGate`, `ProjectRootSource` and the `check` token set carry no wildcard arm; the `reconciliation` / `branch` /
   `reason` / `check` event vocabularies are the closed domains of AC-002 (six / five / five / nine tokens).
4. **One set of migration-neutral entry points:** `migration_writer_admission` / `migration_writer_admission_precheck` /
   `migration_reservation_release` are the only admission entry points; no per-migration delegate, no
   `append_log_backfill_*`, no second reserve/verify implementation.
5. **The shared core is evaluated exactly once per PreToolUse event, registry-independent, ahead of
   `shard_cap_precheck` (S-25.08 AC-001/AC-002/AC-012):** this story must not change the evaluation position or add a
   second evaluation; the diagnostics drain runs after the single call and BEFORE the early return on a verdict.
6. **Error codes: ONLY existing taxonomy entries (error-taxonomy v1.41 is the live version; its three NEW rows `INTENT_LOG_CORRUPT` / `INTENT_LOG_VALUE_REJECTED` / `CANONICAL_MOVE_HALTED` belong to S-25.10 and are NOT introduced or used by this story; AC-019 reuses `MIGRATION_STATE_INTEGRITY_FAILURE` `txn_record_malformed` only; the v1.40 detail follows; error-taxonomy v1.40; v1.40 extends the `E-MAINTENANCE-002` `io` / `state_integrity` triggers, narrows the `FACTORY_ROOT_NOT_FOUND` trigger to ABSENT, and ADDS exactly two codes, `FOREIGN_MIGRATION_REFUSED` (exit 2) and `MIGRATION_LOCK_CONTENTION` (exit 1), which AC-008 implements; no other code may be introduced by this story, and the retired 'LockContention-class' label must not reappear):** `E-MAINTENANCE-001` / `E-MAINTENANCE-002`
   (messages and causes unchanged), `RESERVATION_TTL_BELOW_FLOOR`, `FACTORY_ROOT_NOT_FOUND` (exit 2),
   `MIGRATION_STATE_INTEGRITY_FAILURE` (exit 2; never `BINARY_INTEGRITY_FAILURE`), `EXPIRY_ABORT` (exit 1, two arm-specific lines; exit 1 = no harm done, safe to re-run), and round 3 adds NO code — one KIND token, `txn_record_newer_schema`, of `MIGRATION_STATE_INTEGRITY_FAILURE` / `E-MAINTENANCE-002` `state_integrity` (BC-3.08.001 v1.37, six `kind` tokens),
   `COMPLETION_RECORD_MISMATCH_ABORT` (exit 2; the INTERIM line of AC-011), and the two v1.40 additions `FOREIGN_MIGRATION_REFUSED`
   (exit 2) and `MIGRATION_LOCK_CONTENTION` (exit 1). All exist in error-taxonomy v1.40; the exit codes above are the taxonomy's, and
   a Display string that differs from its row fails the S-12.13 lint gate.
7a. **Recovery-leg record interpretation (ADR-052 §Error Code Semantics 'Migration binaries — recovery and finalize legs'):**
   the `migrate-bc-index` coordinator MUST NOT deserialize a `txn-*.json` into `BcIndexMigrationTxnRecord` at read time; MUST NOT use
   `#[serde(default)]` on a txn field; MUST decode the one live known record whole (all TWELVE keys as of round 3, `schema_version` included, and each
   `pending_canonical_moves[]` element exactly `{staging_path, canonical_path}`) at the TOP of a rewriting arm, before
   its first mutation, with the version gate evaluated FIRST (integer >= 2 => `txn_record_newer_schema`, other non-1 => `txn_record_malformed`); MUST preserve a PRESENT `migration_id` verbatim on rewrite; MUST call the shared `abort_null_generation_txn`
   for the null-generation discard (no second implementation); MUST write the txn ABORTED THEN the gate OPEN and print `EXPIRY_ABORT`
   only after both succeeded; MUST acquire `flock(exclusive.lock, LOCK_EX|LOCK_NB)` before ANY state read (the loader and `completed.json` included; no pre-lock
   branch selection), reporting contention as exit 1 `MIGRATION_LOCK_CONTENTION` on EVERY path; MUST read `completed.json` UNDER the lock and
   pass that read to `recover()`; and MUST NOT grow a verifier (verify-then-finalize is S-25.06 AC-031).
7b. **Exit-code class and write-error propagation (round 3; ADR-052 items 7(e), 11(d)):** `BcIndexMigrationError::process_exit_code` MUST list every variant
   (no `_ =>` arm; exit 1 only for `ExpiryAbort` and `MigrationLockContention`); no txn-record or admission-gate write on the COMPLETED or an
   abort path may be discarded with `let _ =` (the single intended best-effort site is the gate-OPEN write after a SUCCESSFUL txn COMPLETED write); the
   txn ABORTED write is checked BEFORE the gate OPEN write and a failed write is returned as the write's `Io` naming the original failure's code;
   the null-generation discard stays under the version gate on BOTH surfaces (admission Branch B and the coordinator).
7. **No WASM-sandboxed executor (ADR-051 §Decision 7 / CLAUDE.md §WASM plugin fuel budgets):** the admission core and
   the diagnostics drain run native in the dispatcher binary, never inside a hook plugin.
8. **Single-commit-per-burst / POL-3 (TD-VSDD-053, TD-FACTORY-HOOK-BYPASS-001):** no `.factory/` mutation by shell
   bypass; this story does not touch live cycle files.
