# S-12.17: Single-Writer Guard — No Concurrent `.factory/` Writers During a State-Manager Burst

## Narrative

- **As a** factory orchestrator running single-commit state-manager bursts (TD-VSDD-053, POLICY 3 single-writer
  discipline)
- **I want** a mechanical guard that records a state-manager burst as IN-FLIGHT (with its declared file set), refuses to
  let a `.factory/`-writing specialist be dispatched while it is in flight, clears the burst on the state-manager's stop,
  and — in the prompts — requires the orchestrator to declare the burst set up front and the state-manager to halt and
  report on observing foreign mutation
- **So that** a burst commits a stable, reviewed working tree instead of a moving target, the input-hash graph does not
  cascade-drift from interleaved writers (BC -> error-taxonomy -> stories -> epic -> STORY-INDEX parity), and an
  in-flight unreviewed amendment can never be committed by accident

## Context / Evidence

**Incident (D-1251, 2026-10-07; process-gap D-1251-PG-001).** During the S-25.08 pass-1 registration burst the
orchestrator dispatched the product-owner, architect and story-writer while the state-manager burst was running. The
state-manager observed BC-1.18.011 (v1.16 -> v1.17), BC-1.18.013 (v1.8 -> v1.9), error-taxonomy, ADR-052, three stories and
the E-25 epic mutating beneath it, plus BC-INDEX and STATE.md; it halted before committing and reported; the orchestrator
confirmed the edits were routed work and re-dispatched the state-manager after quiescence (lesson
`L-BB-D1251-concurrent-spec-writers-during-state-burst`, `[process-gap][pending-codification]`).

**Root cause.** Violation of POLICY 3 (`state_manager_runs_last`, severity HIGH, `enforced_by: [orchestrator-rule]`,
`lint_hook: null`): the policy is enforced only by the orchestrator following a prose rule; no hook detects an in-flight
state-manager burst when other agents write. A single-commit burst needs a quiescent `.factory/` tree; concurrent writers
make the registered content a moving target and cascade the input-hash graph.

**Lesson items codified here:** (1) the orchestrator MUST NOT dispatch any `.factory/` writer while a state-manager
burst is in flight and MUST declare the burst's file set up front (late specialist work is registered in the NEXT burst or
the state-manager is re-dispatched after quiescence); (2) the state-manager halts and reports (does not commit) on
observing foreign mutation of the burst set; (3) hash convergence runs in dependency order only after all writers stop
(the existing topological-order discipline; unchanged, referenced from the checklist).

**Relationship to the cross-session factory lock (BC-6.23.001 / `verify-factory-lock`).** That lock is a CROSS-SESSION
single-writer guard on the factory-artifacts orphan branch keyed on session identity. It cannot express this incident:
the concurrent writers here are SUBAGENTS of ONE session (same session identity, different roles). This story's marker is
therefore an INTRA-SESSION burst-concurrency guard, complementary to (not a replacement for) the lock; it reuses the
lock's stale-detection and break-glass release patterns rather than inventing new ones.

## Acceptance Criteria

> Hook behavior is asserted against the real dispatcher with the shipped WASM plugin (spawned dispatcher, PreToolUse /
> SubagentStop envelopes on stdin, a tempdir `.factory/`), not by calling plugin functions directly.

- **AC-001 (traces to BC pending PO authorship):** When a PreToolUse `Agent` dispatch is allowed whose `subagent_type` is
  the state-manager (`vsdd-factory:state-manager`), the guard records a burst marker `IN_FLIGHT` under the session's
  `.factory/` state area containing `burst_id`, `started_at` (ISO-8601), the dispatching session id and — when the
  dispatch package declares one (a documented `BURST_FILE_SET:` block) — the declared file set. The marker write is
  atomic (temp + rename + fsync) and its path is registered in `artifact-path-registry.yaml`.
- **AC-002 (traces to BC pending PO authorship):** While a marker is `IN_FLIGHT` and unexpired, a PreToolUse `Agent`
  dispatch whose `subagent_type` is in the closed `.factory/`-writer set — product-owner, architect, story-writer,
  business-analyst, ux-designer, technical-writer, formal-verifier (spec-writing), consistency-validator,
  spec-steward, devops-engineer (factory-artifacts), implementer/test-writer dispatches that declare `.factory/` write
  scope — is BLOCKED (exit 2) with a single-line diagnostic naming the burst id, its age, the declared file set and the
  remedy ("wait for the state-manager to finish; late work is registered in the next burst"). Read-only specialists
  (adversary, code-reviewer, pr-reviewer, holdout-evaluator, research-agent) are NOT blocked. A second state-manager
  dispatch while one is in flight is blocked (single burst at a time).
- **AC-003 (traces to BC pending PO authorship):** On `SubagentStop` of the state-manager the guard clears the marker
  (idempotent; clearing an absent marker is a no-op) and writes a `burst.completed` InternalLog event (`burst_id`,
  `duration_ms`, `foreign_mutation_observed` boolean); a `SubagentStop` for any other agent leaves the marker untouched.
- **AC-004 (traces to BC pending PO authorship):** A marker older than its TTL (default 2 hours; configured via the
  hook's plugin_config, never env/argv) is STALE: a stale marker never blocks — the guard treats it as absent, replaces it
  at the next state-manager dispatch and emits a `burst.stale_cleared` event; a crashed state-manager can therefore not
  deadlock the orchestrator. Break-glass release: the existing `/vsdd-factory:factory-unlock` family (or a documented
  `burst-unlock` mode) clears an in-flight marker with a mandatory audit event; there is no unaudited manual `rm` path
  advertised.
- **AC-005 (traces to BC pending PO authorship):** Edit/Write arm (CONDITIONAL on T-1's research outcome): if the
  PreToolUse payload for Edit/Write/MultiEdit exposes the calling agent (e.g. `agent_type` / `agent_id`), a write under
  the session's `factory_root` by any agent other than the state-manager while a marker is `IN_FLIGHT` is blocked with the
  AC-002 diagnostic; if the payload does NOT expose the caller, this arm is recorded as "not implementable soundly"
  with the evidence (no identity guess, no env heuristics) and AC-002/AC-007 carry the guarantee. Whichever branch is
  true, a test asserts it.
- **AC-006 (traces to BC pending PO authorship):** State-manager halt-and-report (prompt + testable check): before
  committing a burst the state-manager compares `git -C .factory status --porcelain` against the declared burst file set;
  a path outside the set that changed during the burst is FOREIGN: the state-manager does NOT commit, reports the foreign
  paths and their mtimes, and the guard's `burst.completed` event records `foreign_mutation_observed=true`. A bats/lint
  test asserts the state-manager prompt carries the rule and the dispatch-package template carries the `BURST_FILE_SET:`
  block.
- **AC-007 (traces to BC pending PO authorship):** Orchestrator checklist/prompt amendment: `agents/orchestrator/
  orchestrator.md` (and the per-story-delivery / cycle checklist it loads) states, as a hard rule, "never dispatch a
  `.factory/` writer while a state-manager burst is in flight; declare `BURST_FILE_SET:` up front; register late specialist
  work in the next burst or re-dispatch the state-manager after quiescence", cross-referencing POLICY 3 and the guard. A
  bats/lint assertion fails if the rule or the `BURST_FILE_SET:` instruction is absent.
- **AC-008 (traces to BC pending PO authorship):** The policy registry records the enforcement: `.factory/policies.yaml`
  POLICY 3 (`state_manager_runs_last`) gains `lint_hook: <new hook name>` and `enforced_by: [orchestrator-rule,
  hook]` via the sanctioned policy-registry path (state-manager / `policy-add` family — the story specifies the change,
  the owner applies it), so the adversary's rubric auto-loads the mechanical enforcement.

## Architecture Compliance Rules

1. **Intra-session guard only:** do not claim or implement cross-session safety (BC-6.23.001 owns it).
2. **Pure decision core:** time (`now`) and marker contents are inputs; the plugin shell does all I/O.
3. **Capability over identity where possible:** the Agent arm keys on the dispatch's `subagent_type` (a tool input, not
   a guessed caller identity); the Edit/Write arm exists only if the payload exposes the caller (AC-005) — no heuristics.
4. **Fail-closed on the Agent arm; never deadlock:** stale detection + audited break-glass guarantee liveness.
5. **WASM fuel/size discipline (CLAUDE.md):** the marker is a few hundred bytes; the plugin reads only it (and the
   dispatch input); it never reads cycle artifacts such as `lessons.md` or `burst-log.md`.
6. **Error codes: new codes flagged "NEW — add to taxonomy"; no reuse with different semantics.**
7. **Single-commit-per-burst / POL-3 (TD-VSDD-053, TD-FACTORY-HOOK-BYPASS-001):** all `.factory/` edits by this story
   go through Edit/Write; POLICY 3's registry update is state-manager's.

### Forbidden Dependencies (build-time enforcement)

- The new hook-plugin crate MUST NOT depend on `factory-dispatcher` or `shard_manager`; if it gains that dependency
  the build MUST fail (hook plugins depend only on `hook-sdk`).
- The pure decision core MUST NOT depend on `std::fs`, `std::process`, `std::env` or ambient time.
