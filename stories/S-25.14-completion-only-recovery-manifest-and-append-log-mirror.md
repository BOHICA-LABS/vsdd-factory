# S-25.14: Completion-Only Recovery Manifest, `CompletionManifestRejection` and the `backfill-append-logs` Mirror (ADR-052 §Decision 4d)

## Narrative

- **As a** factory operator whose COMMITTING migration outlived its 24-hour authorization window, or who runs the `backfill-append-logs` migration
- **I want** a human-issued, narrowly-bound completion-only recovery manifest that allows ONLY post-pivot forward-recovery steps, and the same armed-activation enforcement on `backfill-append-logs` as on `migrate-bc-index`
- **So that** a stalled post-pivot migration can be completed without re-authorizing the whole activation (and without ever being silently self-completed), a malformed or mis-bound completion manifest is refused with a closed token and changes nothing, and the second migration binary is not an unauthorized side door

### AC-001 (was S-25.13 AC-016) (the completion-only recovery manifest reader; traces to BC-1.18.011 Precondition 5 COMMITTING lifecycle bullet; GAP-11 (no BC clause owns its format); taxonomy `COMPLETION_MANIFEST_REJECTION`, ADR-052 §Decision 4d)

A distinct manifest type bound to the OLD `activation_id`, the staged generation id, `allowed_steps` (post-pivot forward-recovery steps only), and the txn record's `fencing_generation`, approved by `"human-F4-recovery"`. The reader is the ONLY producer of `ManifestStatus::CompletionOnly`: a valid, fully bound completion-only manifest for a COMMITTING record whose original window lapsed or is absent -> `CompletionOnly` -> `ForwardRecovery` (the S-25.13 AC-011 `RecoveryRequiresReauthorization` arm is no longer taken for it). The decode is STRICT with the same closed grammar rules as S-25.13 AC-001 (lstat-first, bounded size, unknown/duplicate key = unparseable, no echo). Its file name, schema and the `allowed_steps` vocabulary are GAP-11; this AC is NOT implementable until they are ruled, and its test names carry `gap11_*` so the ruling re-points them.

### AC-002 (was S-25.13 AC-017) (rejections; traces to taxonomy `COMPLETION_MANIFEST_REJECTION`, ADR-052 §Decision 4d, BC-1.18.011 Precondition 5 COMMITTING bullet; GAP-11)

`BcIndexMigrationError::CompletionManifestRejection { reason }` is constructed (it never is today) for exactly the four causes - `activation_id` mismatch, `staged_generation_id` mismatch, `allowed_steps` includes a pre-pivot step, `fencing_generation` mismatch - with `reason` a CLOSED enum (today a free `String`, which would echo data) rendered as fixed tokens; exit 2; the txn record, intent log, `CURRENT.json` and gate byte-identical; the offending values are never echoed (each hostile value asserted absent from stderr). The exit-code table, `admission_failure_cause` and the taxonomy-code match name the variant explicitly with no wildcard arm. A parity test asserts the token set equals the ruled taxonomy set.

### AC-003 (was S-25.13 AC-018) (the `backfill-append-logs` mirror; traces to BC-1.18.013 Precondition 4 and Precondition 5 mirror sentence, BC-1.18.011 EC-087..EC-090; GAP-16)

`AppendLogMigrationError::ActivationManifestInvalid { manifest_path, reason }` (the SAME closed reason enum, shared from S-25.13) and the same two-phase check, the same `activation_id` validation, the same §4d gate wired into the append-log coordinator with `migration_id = "backfill-append-logs"`; `approved_arch_index_sha` and `expected_total_bcs` MUST be `null` for this migration and the §4c three-way ARCH parity is NOT evaluated (`ARCH_INDEX_PARITY_ABORT` is unreachable, BC-1.18.013 Precondition 4); its exit-2 table and exhaustive matches name the variant. A `migrate-bc-index` manifest presented to `backfill-append-logs` (and the reverse) is `migration_id_mismatch`. A rejection creates nothing (`migration-state/` byte-identical); `--census`, `ALREADY_MIGRATED` and the verify-then-finalize reconciliation need no manifest. Requires S-25.06's coordinator on the base.

## Architecture Compliance Rules

1. **Single producer:** `ManifestStatus::CompletionOnly` has exactly one producer (the completion-only reader); `recover()` and the four-variant enum are unchanged.
2. **Closed reason set:** `CompletionManifestRejection.reason` is a closed enum; the free `String` is removed; no manifest value is ever echoed.
3. **Post-pivot only:** a completion manifest NEVER authorizes a pre-pivot step and is never consulted for a STAGING record.
4. **Nothing mutated on rejection:** txn record, intent log, `CURRENT.json` and gate are byte-identical.
5. **Error codes: ONLY existing taxonomy entries** (`COMPLETION_MANIFEST_REJECTION`, `ACTIVATION_MANIFEST_INVALID`, `RECOVERY_REQUIRES_REAUTHORIZATION`); any new reason token is a taxonomy change owned by the product-owner and flagged "NEW - add to taxonomy".
6. **Mirror parity:** one reader, one reason enum, two coordinators; no second copy of the decode, the clock seam or `is_safe_path_component`.
7. **POLICY 21 / POL-3 / POLICY 19:** no new `.sh`; no `.factory/` shell bypass (manifests are written by state-manager with the Write tool); ADR-052 cited by section, never by version.
