# S-25.13: Armed-Activation Manifest System - Reader, Arming Procedure and Authorization Gate (ADR-052 §Decision 4; CORE slice)

## Narrative

- **As a** factory operator who authorizes a one-time governed migration (`migrate-bc-index`) at the human F4 activation boundary
- **I want** the migration binary to read a real, validated, independently timestamped armed-activation manifest and refuse to run (or to cross the point of no return) without it
- **So that** "the human authorized this exact activation, recently" is a mechanically enforced precondition instead of an unread file the coordinator assumes is always valid; an expired window aborts cleanly before the irreversible pointer swap; a hostile or malformed manifest creates nothing; and a COMMITTING migration whose authorization lapsed demands an explicit human re-authorization instead of silently self-completing

## Context / Feature Summary

The recovery table of ADR-052 §Decision 4e, the authorization gate of §Decision 4d (§Decision 7c step 4) and the Branch 3 validation of §Decision 5c are all written against a manifest that nothing reads. This CORE slice builds the B2 reader system in the order the ADR defines; the completion-only recovery manifest, the `backfill-append-logs` mirror and the Branch 3 guard block were split out by human decision (2026-10-13) into S-25.14 and S-25.15.

1. **Format and location (§4a):** `.factory/activation/<migration_id>-YYYY-MM-DD.json`, JSON, the §4a field set plus the two fields the binary adds (`staged_generation_id`, `consumed_at`).
2. **Writer (arming) - HUMAN DECISION 2026-10-13 (GAP-15 CLOSED): MANUAL ARMING, NO CLI SUBCOMMAND.** The ADR names the writer: state-manager, at the F4 human-directed step. State-manager writes the manifest with the Write tool, following the documented procedure with golden fixtures (AC-014). The accepted CLI grammar of §Decision 3 stays CLOSED at four forms; this story adds NO "arm" subcommand. The binary writes only two amendments to an existing manifest (`staged_generation_id`, `consumed_at`), atomically. The story delivers the arming PROCEDURE (a document with golden fixtures that the real reader parses, so the document cannot drift from the code) and the pure serializer used to generate those fixtures.
3. **Reader (§4b / §4c / §4d):** a pure module that decodes strictly, validates, applies an injected clock to checked arithmetic, and PROJECTS to the existing four-variant `ManifestStatus`. The enum is not changed.
4. **Coordinator wiring:** the hard-wired `StillValid` is replaced by the reader's projection; the §4b checks run before the flock (two-phase, see AC-004 and GAP-04); the §4c checks run under exclusion before staging; the §4d gate runs immediately before the fingerprint recheck on a fresh run and on a STAGING resume.
5. **Errors:** `BcIndexMigrationError::ActivationManifestInvalid { manifest_path, reason }` with the CLOSED five-token reason set (exit 2), **added by THIS story (GAP-14 closed by orchestrator decision; S-25.09 must NOT add it)**; `ExpiryAbort`, `RecoveryRequiresReauthorization` become reachable; `ArchIndexParityAbort` is wired.

## Acceptance Criteria

> Every coordinator AC is asserted through the real `factory-dispatcher migrate-bc-index` binary (spawned process, tempdir project with `.factory/`), never a direct function call alone. `migration-state/` "byte-identical" means a recursive path + size + sha256 snapshot taken before and after.

### AC-001 (the manifest has one strict JSON format; traces to BC-1.18.011 Precondition 5 normative reader requirement, EC-088; GAP-01)

A NEW pure module `shard_manager/activation_manifest.rs` decodes the manifest from bytes into a typed `ActivationManifest { activation_id, migration_id, repo_root_sha, approved_arch_index_sha, expected_total_bcs, approved_by, timestamp_utc, expires_after_hours, staged_generation_id (optional), consumed_at (optional) }` (ADR-052 §Decision 4a). Decode is STRICT: valid UTF-8 JSON object only; an unknown key, a duplicate key, a missing required key, a wrong-typed value, trailing bytes, a non-regular file, a symlink (lstat-first, never followed), or a file larger than a fixed bound is the reason `unparseable`; no byte of the manifest and no field value is ever echoed. The reader never panics on any input (property test over arbitrary bytes). Field-level SEMANTIC rules not named by a BC (`expires_after_hours == 24`, `approved_by == "human-F4-interactive"`, `timestamp_utc` RFC 3339 and not future-dated beyond the existing clock-skew tolerance, SHA shapes) map to `unparseable` PENDING GAP-01 and are listed in the AC's test names as `gap01_*` so the product-owner's ruling re-points them.

### AC-002 (location, filename grammar and selection are deterministic and anchored; traces to BC-1.18.011 Precondition 7 (the activation manifest path derives from the SAME resolved factory root), Precondition 5; GAP-03)

The activation directory is `FactoryRoot`-derived (`.factory/activation/`), never from cwd or an env var. Only entries whose names match `<migration_id>-YYYY-MM-DD.json` for the RUNNING migration are candidates (other files in the directory, e.g. `factory-dispatcher.sha256`, are ignored). Fresh-run selection: the candidate with the greatest date; resume selection: the candidate whose `activation_id` equals the live txn's `activation_id`; no candidate means `absent`. An older candidate is never used as a fallback when the selected one fails to decode.

### AC-003 (expiry is pure, checked, fail-closed and clock-injected; traces to BC-1.18.011 Precondition 6(f)(iv) `EXPIRY_ABORT` paragraph and the taxonomy `EXPIRY_ABORT` trigger "timestamp_utc + expires_after_hours < now"; GAP-17)

The projection `classify(manifest_or_absence, now, running_migration_id) -> ManifestStatus` is pure with the clock a crate-private injected seam (never env or argv: an operator-controlled clock would defeat the gate, the same rationale as the TTL seam). `now == timestamp_utc + expires_after_hours` is NOT expired; `now` greater is expired; the addition is checked and an overflow is expired; a manifest with `consumed_at` set is never `StillValid`. The reader NEVER returns `Unknown`; a clock failure or a non-`NotFound` read error is `Io` (exit 2) with nothing mutated, because routing it to `CleanAbortExpiredStaging` would DISCARD staged work and print a claim ("expired or absent") that is false (GAP-17). The doc comment of `ManifestStatus::Unknown` is rewritten to say so.

### AC-004 (the §4b checks fail closed before any state exists; traces to BC-1.18.011 EC-088 (`unparseable`), EC-089 (`migration_id_mismatch`), EC-090 (`absent`); GAP-04, GAP-02)

`migrate-bc-index` on a first-run candidate (no `completed.json`, no live txn) with an absent, unparseable or foreign-`migration_id` manifest exits 2 with `ACTIVATION_MANIFEST_INVALID` and the reason token; `migration-state/` is byte-identical to its pre-call state (no `create_dir_all`, no `exclusive.lock`, no txn, no intent log, no gate write). Evaluation is TWO-PHASE because the coordinator must not let a pre-lock read SELECT a branch: phase 1 (before the flock) is a read-only hint that can only fail a clearly-fresh run early; phase 2 (under the lock, after `completed.json` and the live txn are read, before the txn path is derived) repeats the check authoritatively. Precedence among simultaneous failures is `absent` > `unparseable` > `migration_id_mismatch` > `activation_id_unsafe_component` > `activation_id_not_uuid` (GAP-02). A STAGING resume with an absent manifest is NOT this error: it is `EXPIRY_ABORT` (exit 1) via AC-010.

### AC-005 (the manifest `activation_id` validation precedes any txn path; traces to BC-1.18.011 Precondition 5 manifest `activation_id` sentence, EC-087)

For the four values `../x`, `a/b`, the empty string and `not-a-uuid` the coordinator exits 2 `ACTIVATION_MANIFEST_INVALID` with reason `activation_id_unsafe_component` (the first three; fails `is_safe_path_component`) or `activation_id_not_uuid` (the fourth), BEFORE `txn-<activation_uuid>.json` is derived; stderr contains the token and does NOT contain the value (each of the four is asserted absent from stderr); no file is created; `migration-state/` is byte-identical for each value. Control: a hyphenated lowercase UUID proceeds exactly as before. The check calls the S-25.09 `is_safe_path_component`; a second copy of the predicate is a sweep failure (AC-013).

### AC-006 (the variant, its exit code and its rendering; traces to BC-1.18.011 Precondition 6(f)(vi) exit-code classes, EC-057, Invariant 5, EC-087)

`BcIndexMigrationError::ActivationManifestInvalid { manifest_path: String, reason: ActivationManifestInvalidReason }` is ADDED BY THIS STORY (GAP-14 closed by orchestrator decision 2026-10-13; S-25.09 does not add it, and this story must not be merged alongside a second definition) with `ActivationManifestInvalidReason` a CLOSED five-variant enum rendering exactly `activation_id_unsafe_component`, `activation_id_not_uuid`, `migration_id_mismatch`, `unparseable`, `absent`. The reason enum is `pub(crate)` and shared so S-25.14 reuses it for the `AppendLogMigrationError` mirror. `process_exit_code` names it explicitly (exit 2, NOT 1); `admission_failure_cause` and the taxonomy-code match are exhaustive with no wildcard arm; the Display is `migrate-bc-index: ` + fixed text + the reason token + `manifest_path` capped by the same `render_with_cap` source (256 on stderr, 64 in an InternalLog event) as every other data-derived slot. The EC-057 compile-time-exhaustive table gains the row. A parity test asserts the token set equals the taxonomy row's set (five tokens, no sixth).

### AC-007 (no manifest is ever required where the ADR says none is needed; traces to BC-1.18.013 EC-004, BC-1.18.011 Postcondition 9 (verified `completed.json` reconciliation))

`migrate-bc-index --census`, an invocation that finds a valid `completed.json` (`ALREADY_MIGRATED`, exit 0), and the verify-then-finalize reconciliation succeed with the activation directory EMPTY and ABSENT; they never read it. Regression test per path.

### AC-008 (§4c under-exclusion validation; traces to BC-1.18.010 Invariant 2(b) (three-way ARCH-INDEX parity); GAP-06 and GAP-07 for the two checks and the SHA definition that have no BC clause)

## Architecture Compliance Rules

The implementer MUST NOT violate any of these; violations are bugs, not style preferences.

1. **Pure core, effectful shell:** `classify`, decode and the serializer do no I/O and read no clock; the clock and the filesystem enter through crate-private seams (never env, argv or a public parameter).
2. **Closed reason set:** exactly five `ActivationManifestInvalidReason` tokens; adding a sixth is a taxonomy change (product-owner) and the parity test fails the build.
3. **Never echo:** no manifest byte or field value appears on stderr, in a hook reason or in a log; `manifest_path` is the only data-derived slot and is capped by the one `render_with_cap` source.
4. **Nothing created on rejection:** a manifest rejection precedes the txn path derivation and creates no `txn-*.json`, intent log, gate write or flock; asserted by a `migration-state/` snapshot.
5. **Single decision authority:** `recover()` and its four-variant `ManifestStatus` are unchanged; the reader targets them; no parallel `match` on manifest state beside `recover()`.
6. **Post-pivot invariant (ADR-052 §Decision 4d):** authorization expiry NEVER aborts a COMMITTING record; the txn record and intent log are retained regardless of manifest expiry.
7. **Write order:** txn record ABORTED before gate OPEN; `staged_generation_id` before the txn `generation_id`; `consumed_at` only after `completed.json` is durable; a failed write is its own `Io` (exit 2), never `EXPIRY_ABORT`.
8. **Error codes: ONLY existing taxonomy entries.** This story adds no taxonomy code. `ACTIVATION_MANIFEST_INVALID`, `EXPIRY_ABORT`, `RECOVERY_REQUIRES_REAUTHORIZATION` and `ARCH_INDEX_PARITY_ABORT` exist; the two §4c checks without a code are GAP-06, flagged "NEW - add to taxonomy" if the product-owner assigns one.
9. **No WASM-sandboxed executor (ADR-051 §Decision 7 / CLAUDE.md WASM fuel budgets):** the reader runs in the dispatcher binary.
10. **POLICY 21:** no new `.sh` file; the arming procedure is a Markdown document plus Rust tests. **No CLI arming subcommand (human decision 2026-10-13).**
11. **POLICY 19:** cite ADR-052 by section, never by version.
12. **Single-commit-per-burst / POL-3 (TD-VSDD-053, TD-FACTORY-HOOK-BYPASS-001):** no `.factory/` mutation by shell bypass; this story does not touch live cycle files, and the arming document tells the state-manager to use the Write tool.
