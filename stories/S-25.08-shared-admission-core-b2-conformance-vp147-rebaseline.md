# S-25.08: Shared Admission Core Wired on the Production Path + B2 Conformance (B2-1/B2-3/B2-4) + VP-147 Re-baseline

## Narrative

- **As a** factory pipeline operator who relies on the governed one-time migrations (`migrate-bc-index`,
  `backfill-append-logs`) being safe against concurrent writer sessions
- **I want** the native admission gate to be ONE shared admission core that the dispatcher's real
  PreToolUse/PostToolUse path evaluates exactly once per event — reserve-then-verify, release-on-block,
  flock-gated stale-gate reconciliation (Branches A/B/C), a 3,600 s `created_at`-judged reservation TTL —
  and the already-merged B2 code brought into conformance with BC-1.18.011 v1.17, with the B2 Kani suite
  (VP-147) re-baselined against that core
- **So that** the writer-exclusion window is actually enforced on the production path (a gate that exists
  only behind unit tests protects nothing), the admitter/coordinator race is closed by construction rather
  than by an unsound `LOCK_SH`-on-rename-replaced-file ordering, a crashed abort can never leave writers
  permanently blocked, and S-25.06's mechanism-A drain, verify-then-finalize and cross-migration refusal can
  be built and proven on a real, conformant core instead of on dead code

## Context / Feature Summary

**Origin.** The S-25.06 formal-verifier found production defects D1/D2/D3 (HEAD `9886cbc1`); the architect
adjudication (ADR-052 v1.18 formal-finding exception) added D4/D5 and four sibling conformance defects in
the merged S-25.02 cluster-5 B2 code (PR #842). The human approved the exception and kept the B2 fixes in
the S-25.06 scope; the 21-point total was then split. This story is the shared-core half.

**Defect labels (canonical):** **D1** admission gate not wired on the production PreToolUse path in
`main.rs` (single shared core, evaluated once per event, ahead of `shard_cap_precheck`); **D5** admission race
-> reserve-then-verify + release-on-block; **B2-1** `reconcile_stale_admission_gate` is dead code — wire
Branches A/B/C on the production path; **B2-3** `DEFAULT_MAX_RESERVATION_TTL` 120 s < 1,800 s floor and
mtime-only staleness -> 3,600 s default, `created_at` staleness; **B2-4** B2 admission check-then-reserve race
-> B2 delegates to the shared core (reserve-then-verify).

## Architecture Compliance Rules

The implementer MUST NOT violate any of these; violations are bugs, not style preferences.

1. **Single shared admission core, evaluated exactly once per PreToolUse event (ADR-052 §5a "Shared
   protected-path union and shared admission state"; BC-1.18.013 Precondition 6(b) "Where"):** `main.rs` calls
   the core (v1.2, BC-1.18.013 v1.9 Precondition 6(b) O1-O4 / ADR-052 v1.20 §5a "Evaluation position") immediately
   after payload parse + `resolve_project_cwd()` and BEFORE the `CLAUDE_PLUGIN_ROOT` tiering /
   `resolve_registry_path()` / `Registry::load` — the former "position `bc_index_migration_admission_precheck`
   already holds" is AFTER `Registry::load` and inherits its fail-open arms and is superseded — structurally AHEAD
   of `shard_cap_precheck` and every registry plugin; the release leg (PostToolUse AND PostToolUseFailure,
   `tool_use_id`-keyed, gated by `is_tool_completion_event`) is registry-independent in the same way. A gate
   reachable only from unit tests, or a second evaluation per event, is a bug. Tools gated: `Edit`, `Write`,
   `MultiEdit` ONLY; `Bash` is left unprocessed (EC-014). Protected union (v1.2: component-wise, anchored on the
   session's own `factory_root`, via the shared `resolve_target_path`; never a substring test; out-of-root
   `.factory` paths out of scope): `<factory_root>/specs/behavioral-contracts/` ∪ `<factory_root>/cycles/`.
2. **Reserve-then-verify; no lock in the admitter; release-on-block (ADR-052 §5a step 0; D5):** create the
   reservation FIRST, read `gate-state.json` and scan `txn-*.json` second (then run step-3.5 and re-evaluate);
   remove one's own reservation on failed verification and when the dispatch's final aggregated outcome is a
   block or error. NEVER take `LOCK_SH` on the gate-state file for admitter ordering (the coordinator replaces
   it via `rename`). NEVER judge reservation liveness by PID.
3. **Reservation TTL (BC-1.18.011 Precondition 6(c) / BC-1.18.013 Precondition 6(c)):** default 3,600 s;
   production entry point rejects < 1,800 s; TTL and 30 s drain timeout are injectable test seams; staleness by

   never weakened to pass; only fixtures that model STAGING without `exclusive.lock` change.
