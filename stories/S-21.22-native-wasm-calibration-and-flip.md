# S-21.22: Native-WASM fuel-axis calibration and fail-closed flip — `validate-cross-site-correspondence` (ADR-039 Phase 3a+4d; split seam 4 of 6 from S-21.11)

## Narrative

  currently fails open on fuel exhaustion, silently approving cross-site-correspondence
  violations on large inputs
- **I want** `validate-cross-site-correspondence`'s `fuel_cap` calibrated against a

  as its calibrated `fuel_cap`

  bash-adapter wiring fix, per-plugin calibration, or the break-glass mechanism — none of

## Context / Finding Summary

**Native-WASM (fuel-axis calibration sufficient):** unlike the five
`legacy-bash-adapter.wasm`-hosted plugins, `validate-cross-site-correspondence` runs as a
native WASM guest — wasmtime's fuel counter sees the whole execution directly, with no host
subprocess in between. There is therefore no AMD-002-class wiring gap for this plugin: fuel
calibration alone (no `timeout_ms` axis, no wall-clock host-kill deadline) is a sufficient
CALIBRATION METHODOLOGY for this plugin. This is what makes this seam fully independent of S-21.21's
bash-adapter wiring/calibration work and S-21.23's break-glass mechanism — the only genuine
CALIBRATION dependency is S-21.19's decision-function authoring (Task 5's
`plugin_fail_closed_on_exhaustion`, unit-tested but unwired within S-21.19), which every one of
the six targeted plugins' enforcement rests on. **This methodology-independence claim is
distinct from ENFORCEMENT-timing (F-S2122-P1-001, HIGH):** this plugin's `Timeout` outcomes are
governed exclusively by `plugin_fail_closed_on_exhaustion`, whose LIVE WIRING remains
capstone-owned (S-21.24's Task 0, wave 8, per ADR-044, unchanged from v1.0) —
this story's own flip (Task 6) lands the registry annotation early and safely (inert, not
unsafe, prior to wiring) but does not itself make any real dispatch block; see the Narrative
section's caveat above.

**Task-ownership resolution (per `.factory/planning/S-21.11-decomposition-plan.md` §6):** the
operator-approved baseline described this seam as owning "Tasks #1–5, #26" and the capstone as
owning "Tasks #26–32" — an apparent overlap. The plan resolves this: Task #26 (the flip itself)
depends only on this seam's own calibration (Node A) and S-21.19's decision-function extension
(Node D) landing — it has no dependency on S-21.21 (Node B/C) or S-21.23 (Node E), so there is
no structural reason to defer it to the capstone. Landing it here lets this plugin's flip
proceed as soon as S-21.19 merges, rather than waiting on the five-story capstone convergence
gate.

**EC-004 escape valve:** if calibration reveals this plugin's required `fuel_cap` would be AT
OR ABOVE (`>=`, per F-S2122-P2-002 — not merely "exceed"/`>`) `PRACTICAL_FUEL_CEILING`
(500,000,000; formally defined in ADR-039 §Decision 4 per F-S2122-P1-003), this story's
flip is descoped and the plugin routes to S-21.13 instead (see AC-007 below and the
`depends_on` redirect in this story's `blocks:` frontmatter — ALREADY EXECUTED via D-1070,

## Acceptance Criteria

### AC-007 (native-WASM leg): Per-plugin calibration against production-scale corpus — `fuel_cap` for native-WASM (traces to BC-1.03.017 v1.27 Preconditions 2–6, enabling PC9; ADR-039 §Decision 4 Option A + §Erratum E-007 target-statistic correction)

**Leg-scope note (per `.factory/planning/S-21.11-decomposition-plan.md` §3):** AC-007 has two
legs. This story owns the native-WASM leg (`validate-cross-site-correspondence`) — the
`legacy-bash-adapter.wasm`-hosted leg (the five bash-adapter plugins) is owned by **S-21.21**.

For `validate-cross-site-correspondence` (native-WASM), calibration is bifurcated by adapter
class (ADR-039 §Decision 1/2/3/4 amendment, §AMD-001): `fuel_cap` MUST be set to at least
`max(ceil(observed_max × 1.5), 50_000_000)` where `observed_max` is the maximum `fuel_consumed`
value observed over the calibration corpus below, and `ceil()` rounds UP to the nearest whole
fuel unit (F-S2122-P2-002: rounding is pinned explicitly — `fuel_consumed` is an integer count
of WASM instructions, so `observed_max × 1.5` may be fractional; truncating instead of
rounding up would under-calibrate by up to 1 fuel unit and make the `PRACTICAL_FUEL_CEILING`
boundary case non-deterministic across implementations). For the hard-block/fail-closed boundary
validators in this story, the appropriate percentile basis is the **observed maximum over
the mandated corpus** — with ~4 corpus inputs, "p99" and "observed max" are effectively
identical. `fuel_consumed` MUST be read from the `Ok`-path measurement ONLY: on a
`Trap::OutOfFuel` outcome, `fuel_consumed == fuel_cap` (conveys the cap, not actual
demand), so a `Timeout`-path reading is invalid for calibration purposes. This element has
no dependency on S-21.21's AMD-002 wiring fix.

The calibration corpus MUST include:

1. `lessons.md` at ≥4000 lines (at the D-442(e) hard limit; soft limit is 3500, hard is 4000)
2. `STATE.md` at current live size
3. `decision-log.md` at current live size
4. The ≥574 KB synthetic fixture committed at `plugins/vsdd-factory/tests/fixtures/validate-cross-site-correspondence/a1-production-scale/factory/specs/behavioral-contracts/BC-INDEX.md` (576,396 bytes; `BC-INDEX.md` is the calibration input file — the tree also holds `ss-05/BC-5.39.010.md`; added in S-21.07 merge e94767bc)

A calibration run MUST be executed by the devops-engineer role before the implementer
annotates hooks-registry.toml. **(F-S2122-P1-002, HIGH, strengthened this burst):** the
calibration log MUST record `observed_max` (the measured `fuel_consumed` value) PER CORPUS
INPUT individually (`lessons.md`, `STATE.md`, `decision-log.md`, and the ≥574 KB fixture each
get their own recorded `fuel_consumed` reading) — not merely an aggregate/summary figure — so
that a future re-calibration can identify which specific input drives the calibrated `fuel_cap`.
The chosen `fuel_cap` MUST be recorded in the PR description or a calibration log artifact, not
merely asserted in code. **Additionally, per BC-1.03.017 v1.27 Precondition 6 (Q2/F-S2122-P1-002
machine-checkable sufficiency gate; DURABLE CI-resident enforcement added F-S2122-P2-001):**
