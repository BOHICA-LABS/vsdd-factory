# S-14.10: Per-Story-Delivery Process-Gap Codification — Story-Status Reconciliation, Adversary-Review Persistence, CHANGELOG Citation Discipline

**Epic:** E-14 — Engine Discipline Pass-2 — Process-Gap Remediation
**Delivery order:** TENTH in E-14. Independent of S-14.01 through S-14.09.
**Depends on:** (none) — `depends_on: []` is justified: Step 4.5 (the per-story adversary convergence loop) is already delivered by S-12.01 and merged; this story amends that step and adds gates around it, it does not need any unmerged story's output.
**Blocks:** (none) — S-25.08/S-25.09 and later cycles benefit but do not wait on this story; the orchestrator already applies the three disciplines manually (D-1257), this story makes them mechanical.
**Priority:** P1

## Narrative

- **As a** vsdd-factory orchestrator driving a story through the per-story-delivery workflow and its local adversary convergence loop
- **I want** the workflow to (a) reconcile the story file with the delivered commits after every fix batch and before the next adversary pass, (b) persist every adversary review verbatim through the state-manager before the next pass is dispatched, and (c) enforce that CHANGELOG entries carry no version pins and only owner-qualified, resolving EC/AC tokens — each as a documented workflow step backed by a mechanical gate
- **So that** the S-25.08 failure pattern (three consecutive passes finding a story whose tasks and status trailed its fix commits, four passes whose reviews existed only in orchestrator context, and a CHANGELOG pass that introduced mis-owned EC/AC tokens while removing version pins) cannot recur on any later story, and adversary passes spend their findings on implementation defects instead of bookkeeping drift

## Background — the three occurrences (source: D-1257 lessons in `.factory/cycles/v1.0-brownfield-backfill/lessons.md`)

1. **Story-status lag.** S-25.08 passes 5, 6 and 7 each found story Task and status lines not reconciled after the implementer's fix commits landed (L5-004, L6-002, L7-003). Three occurrences meet the codification threshold. Interim control: the orchestrator now dispatches a story-writer reconciliation after every fix batch and before the next adversary pass.
2. **Adversary reviews not persisted.** The S-25.08 pass-6 and pass-7 reviews existed only in orchestrator context until the D-1257 registration burst (pass 8 likewise), and no story task tracked their persistence; passes 4 and 5 had the same lag earlier (S-25.08 T-42, T-47). Finding F-S2508-L8-004. Interim control: persisted verbatim at registration.
3. **CHANGELOG EC/AC citations.** Closing the version-pin finding (S-25.08 L5-002) by replacing pins with section anchors introduced unqualified or mis-qualified tokens: "BC-1.18.013 AC-011" (a BC has no ACs; AC-011 is a story AC) and a BC-1.18.011 EC-045 whose scope belongs to S-25.09 (F-S2508-L6-001). This extends the open item [D-1255-CHANGELOG-PINS] (ban "current version" pins in CHANGELOG entries; cite by section anchor, POLICY 19 style).

### AC-013 (version-pin sweep over the whole diff; traces to BC-5.39.001 postcondition 6 (the gate is a pre-dispatch condition inside the Step 4.5 loop, wired with AC-011/AC-012) and BC-8.31.001 postcondition 1 (extended); rule content NEW clause owed — GAP-S1410-005; extends the [D-1255-CHANGELOG-PINS] rule from CHANGELOG entries to every added line)
A new subcommand `story-delivery-gates check-version-pins --base <rev> [--allowlist <file>]` (pure core `scan_added_lines(diff_added_lines, allowlist)` in the `story-delivery-gates` library; POLICY 21: Rust, no shell) enforces, as a gate run by the orchestrator before every adversary pass and before push, and by `ci.yml` on PRs:
1. **Scope is EVERY path** in `git diff --name-only <base>..HEAD` (no directory filter: `crates/`, `.factory/`, `plugins/`, docs, workflows, templates, CHANGELOG all included; renames and binary files are listed, binary files skipped with an explicit `skipped binary` line). Only ADDED lines (`+` lines of `git diff -U0 <base>..HEAD`, excluding `+++` headers) are scanned; removed and context lines are never scanned.
2. **Two sweeps on each added line:** the PREFIXED pattern `(BC-[0-9]+\.[0-9]+\.[0-9]+|VP-[0-9]+|error-taxonomy|ADR-[0-9]+|S-[0-9]+\.[0-9]+) ?\(?v[0-9]+\.[0-9]+` AND the BARE sweep `\bv[0-9]+\.[0-9]+\b`. A line matching either is a violation unless allowlisted.
3. **Literal output (D-449(a)):** every hit is printed as `path: line` (the path, then the added line's number and text) with the matched token, the full path list scanned is printed first as `scanned: <path>` lines, and the run ends with a literal summary line `version-pin-gate: <n> violation(s) over <m> path(s) (base <rev>, head <sha>)`; exit 0 when n = 0, exit 1 otherwise, exit 2 on a git failure or unreadable allowlist. No pseudocode attestation: the burst log pastes this stdout verbatim.
4. **Explicit allowlist mechanism:** an allowlist file (a checked-in, reviewed file; default `.factory/policies/version-pin-allowlist.toml` when present, else none; changes to it go through review like any spec file) holds entries `{ path = <glob>, pattern = <regex or literal>, justification = <non-empty, min 10 chars> }`; an entry with an empty or too-short justification is rejected (exit 2); every allowlisted match is still PRINTED as `allowed: path:line:<text> (justification: …)` so provenance text (for example a changelog row recording which BC version a burst cited) is visible, never silently dropped. An inline marker is NOT supported (no silent per-line escapes).
