## Narrative

- **As a** vsdd-factory orchestrator driving a story through the per-story-delivery workflow and its local adversary convergence loop
- **I want** the workflow to (a) reconcile the story file with the delivered commits after every fix batch and before the next adversary pass, and (b) persist every adversary review verbatim through the state-manager before the next pass is dispatched — each as a documented workflow step backed by a mechanical gate that a PreToolUse hook enforces on adversary dispatch
- **So that** the S-25.08 failure pattern (three consecutive passes finding a story whose tasks and status trailed its fix commits, and four passes whose reviews existed only in orchestrator context) cannot recur on any later story, and adversary passes spend their findings on implementation defects instead of bookkeeping drift

## Background — the two occurrences kept here (source: D-1257 lessons in `.factory/cycles/v1.0-brownfield-backfill/lessons.md`)

1. **Story-status lag.** S-25.08 passes 5, 6 and 7 each found story Task and status lines not reconciled after the implementer's fix commits landed (L5-004, L6-002, L7-003). Three occurrences meet the codification threshold. Interim control: the orchestrator now dispatches a story-writer reconciliation after every fix batch and before the next adversary pass.
2. **Adversary reviews not persisted.** The S-25.08 pass-6 and pass-7 reviews existed only in orchestrator context until the D-1257 registration burst (pass 8 likewise), and no story task tracked their persistence; passes 4 and 5 had the same lag earlier (S-25.08 T-42, T-47). Finding F-S2508-L8-004. Interim control: persisted verbatim at registration.
(The CHANGELOG-citation occurrence and the three later occurrences (version-pin sweep, SHA labels, convergence-prose restatement) are S-14.11's Background.)

### Part (a) — Story-status reconciliation

### AC-001 (reconciliation step after every fix batch; traces to BC-5.39.001 postcondition 4 (a non-clean pass resets the counter and the loop continues, so a fix batch always precedes the next pass); NEW clause owed — Gap Register GAP-S1410-001)
Both workflow files, in the Step 4.5 "Loop procedure", insert between "dispatch `implementer` to fix within-story findings" and "repeat from step 1" a mandatory reconcile step: after every implementer fix batch and BEFORE the next adversary pass the orchestrator dispatches `story-writer` with task "Reconcile S-N.MM against `feature/S-N.MM` commits since the last reconciliation": the story's Tasks checkboxes, `status:`, and `last_amended:`/version are brought into agreement with the delivered commits, one persistence task per adversary pass is added or ticked (part (b)), and one row is appended to the story's Delivery Reconciliation Ledger (AC-003). The step states that the next adversary pass MUST NOT be dispatched until the gate of AC-002 exits 0.
- **Test:** `test_S1410_AC001_both_workflow_files_carry_the_reconcile_step_between_fix_batch_and_next_pass()` in `crates/story-delivery-gates/tests/workflow_docs.rs` — asserts (i) the string "Reconcile S-N.MM" and `story-writer` appear inside the Step 4.5 section of BOTH files, (ii) the reconcile step's line number lies between the "fix within-story findings" line and the "Repeat from step 1" line, (iii) the two files agree on the step text (parity diff of the extracted step is empty).

### AC-002 (mechanical reconciliation gate; traces to NEW clause owed — GAP-S1410-001)
A new Rust gate (POLICY 21: no new shell scripts) — pure core `check_reconciliation(ledger, worktree_tip)` in the library of the new crate `crates/story-delivery-gates` (standalone native CLI pattern of `crates/last-amended-migrate`: `[lib]` carries the logic, `[[bin]]` `story-delivery-gates` is the operator entry) with subcommand `story-delivery-gates check-reconciliation <story-file> <worktree>` — exits 0 when the last row of the story's Delivery Reconciliation Ledger names a `reconciled_through` short SHA equal to `git -C <worktree> rev-parse --short HEAD`; exit 1 when it differs (message names both SHAs and the commit count in between, one line per unreconciled commit subject); exit 2 on a parse error (story file missing, no ledger section, ledger has no data row, worktree is not a git work tree). It is read-only and never edits the story file. It is enforced as a dispatch-blocking gate by the PreToolUse hook of AC-012 for every adversary pass N >= 2 (and for pass 1 when the story has any prior fix commit); the CLI subcommand is the same core for operators.
- **Test (Rust):** `test_S1410_AC002_gate_ok_when_ledger_tip_equals_worktree_head()`, `..._exit1_naming_both_shas_and_unreconciled_subjects_when_ledger_trails_head()`, `..._exit2_for_missing_file_missing_ledger_empty_ledger_and_non_git_worktree()` and `..._never_modifies_the_story_file()` in `crates/story-delivery-gates/tests/check_reconciliation.rs` (unit tests on the pure core plus `assert_cmd`-style tests driving the built binary against a fixture git repository created with `tempfile`).

### AC-003 (ledger section in the story template; traces to NEW clause owed — GAP-S1410-001; the template change must not disturb the BC-5.36.001/BC-5.36.002 ready-gate wording, which the existing template tests keep green)
`plugins/vsdd-factory/templates/story-template.md` gains a "Delivery Reconciliation Ledger" section (after "File Structure Requirements") with the columns `| Pass | reconciled_through | story version | status | persisted review |` and a one-row placeholder, with prose stating who writes it (story-writer, at each reconcile) and that it is consumed by `story-delivery-gates check-reconciliation`. The story-writer agent prompt (`plugins/vsdd-factory/agents/story-writer.md`) gains a bullet naming the reconcile obligation and the ledger.
- **Test:** `test_S1410_AC003_template_carries_the_ledger_section_and_columns()` and `test_S1410_AC003_story_writer_prompt_names_the_reconcile_obligation_and_ledger()` in `crates/story-delivery-gates/tests/workflow_docs.rs`.

### Part (b) — Adversary-review persistence before the next pass

### AC-004 (persist-before-next-pass workflow step; traces to BC-6.04.006 postcondition 1 (findings file exists at the target path via a state-manager dispatch) and BC-5.39.001 postcondition 1 (each pass result is recorded); NEW clause owed — GAP-S1410-002)
Both workflow files, in the Step 4.5 "Loop procedure", insert immediately after "Dispatch `adversary`..." a mandatory persist step: the orchestrator captures the adversary's full output verbatim (no summarising, no editing) and dispatches `state-manager` to write it to `.factory/code-delivery/<story-id>/adv-local-pass-<N>.md` BEFORE dispatching either the implementer fix batch or the next adversary pass. The step records the ordering `adversary -> state-manager persist -> implementer fix -> story-writer reconcile -> state-manager register -> adversary pass N+1` and cross-references the existing "State-Manager Ordering (MANDATORY)" rule (state-manager never concurrent with story-writer; runs last in a burst). The Adversarial Pass Context Injection section lists the prior pass's persisted review path as the fresh-context input.
- **Test:** `test_S1410_AC004_both_workflow_files_carry_the_persist_step_with_the_target_path_and_ordering()` in `crates/story-delivery-gates/tests/workflow_docs.rs` — asserts the path token `adv-local-pass-<N>.md`, the word `verbatim`, `state-manager`, and that the persist step precedes the implementer-fix step in the Step 4.5 section of both files.

### AC-005 (mechanical persistence gate; traces to BC-6.04.006 postcondition 1; NEW clause owed — GAP-S1410-002)
A new Rust gate — pure core `check_review_persisted(story_id, next_pass, dir_listing)` in the same `story-delivery-gates` library, subcommand `story-delivery-gates check-review-persisted <story-id> <next-pass-number> [<code-delivery-dir>]` (default dir `.factory/code-delivery`) exits 0 when files `adv-local-pass-1.md` .. `adv-local-pass-<N-1>.md` all exist under `<dir>/<story-id>/` and are non-empty and each begins with a heading line; exit 1 naming each missing, empty or malformed pass; exit 2 for a non-integer or less-than-1 pass number or an unreadable directory. For `<next-pass-number>` = 1 it exits 0 (nothing to persist). It is enforced by the PreToolUse hook of AC-012 before every adversary dispatch for pass N >= 2.
- **Test (Rust):** `test_S1410_AC005_gate_ok_when_all_prior_pass_files_exist_non_empty()`, `..._exit1_naming_each_missing_or_empty_prior_pass()`, `..._ok_for_pass_1()`, `..._exit2_for_invalid_pass_number_or_unreadable_dir()` and `..._detects_a_gap_in_the_sequence_pass_3_present_pass_2_absent()` in `crates/story-delivery-gates/tests/check_review_persisted.rs`.

### AC-006 (the story carries one persistence task per pass; traces to NEW clause owed — GAP-S1410-002 and GAP-S1410-001)
The reconcile step (AC-001) adds to the story's Tasks a task `persist adversary pass N review (state-manager)` for every pass that has run, ticked only when the file checked by AC-005 exists. The story-writer prompt names this obligation. A story whose last ledger row records pass N but whose Tasks lack the persistence task for pass N is a reconciliation failure (reported by the story-writer at the next reconcile, and checked in the structural test below against a fixture story).

### AC-011 (the two gates are wired into the workflow text the orchestrator actually reads; traces to BC-5.39.001 postcondition 6 (Step 5 must not run before convergence — the new gates are pre-dispatch conditions inside the same loop); NEW clause owed — GAP-S1410-001/002 for the gate-text content)
Both workflow files name the two gates (the `story-delivery-gates` subcommands) in the Step 4.5 loop procedure: `story-delivery-gates check-review-persisted` and `story-delivery-gates check-reconciliation` as pre-dispatch gates for pass N >= 2. A non-zero exit from a gate blocks the dispatch; the orchestrator remediates (dispatch the owning specialist) and re-runs the gate, never skips it. ### AC-012 (dispatch-blocking hook; traces to BC-5.39.001 postcondition 6 (the loop gates the step order) and BC-5.39.001 postcondition 1 (each pass recorded); NEW clause owed — GAP-S1410-001/002; answers the former OQ-S1410-01)

## Forbidden Dependencies

- The `story-delivery-gates` crate MUST NOT depend on `factory-dispatcher`, `vsdd-hook-sdk`, any WASM runtime, a shell, `jq`, Python or network access; its only external process is `git`. - No code in this story may write to `.factory/`; the state-manager is the only `.factory/` writer.
