# S-25.11: Fixed Canonical-Move Plan, Completion Evidence and the `canonical_move_plan` Rename (ADR-054 Decisions 2 and 3; slice 2 of 3)

## Narrative

- **As a** factory pipeline operator who must be able to trust that a recovered or crashed `migrate-bc-index` run either completed every move with evidence or stopped loudly
- **I want** a FIXED, immutable `canonical_move_plan` whose progress lives only in txn-bound, INTENT-confirmed `DONE` records, recovery that appends the `DONE` it counts, a `DONE` that is re-confirmed against its INTENT, and a completion that is verified before `completed.json` is written
- **So that** a crash at any fault point converges to a log holding a hash-confirmed `DONE` for every plan target and a second recovery pass changes nothing (B-1), a `DONE` can never be self-hashed into a circular proof (B-2), an empty or tampered plan can never "complete" vacuously with `canonical_paths_count: 0` (B-3), and the verifier, admission Branch C and the operator runbook all check the same three-way equality `DONE.expected_post_hash == INTENT.expected_post_hash == sha256(file)`

## Context / Feature Summary

**What the code does after S-25.10 and before this story.** The shared module exists with the hardened format, reader and writer; `execute_canonical_path_moves` reads the log through `read_log` and appends each `DONE` by copying the INTENT's four fields (S-25.10 AC-011), but it still decides with the three-outcome `decide_intent_log_recovery`
(adapted to `IntentRecord`), `TreatDone` still counts a move without appending its `DONE` (B-1), no comparison against the INTENT's `expected_post_hash` is made and `expected_pre_state` is recorded as the pre-S-25.11 code did (B-2), `finish_committing_migration` trusts `txn.pending_canonical_moves`
and counts `DONE`s without a plan/INTENT integrity check (B-3), and the txn record is rewritten after every move (ADR-052 §7c step 7 sub-step d).

**The defects this story closes (ADR-054 §Context).** B-1 (HIGH) `TreatDone` counts a move without appending the `DONE` the format requires; B-2 (HIGH) `DONE` carries no txn binding and its `expected_post_hash` is the post-rename observation (circular), `expected_pre_state` hard-coded `MISSING`;
B-3 an empty or tampered plan in a COMMITTING record completes vacuously. Plus the field-name defect: a field named `pending_...` that never shrinks misled the ADR's own author - rename cost is lowest before any record exists.

## Architecture Compliance Rules

The implementer MUST NOT violate any of these; violations are bugs, not style preferences.

1. **The plan is immutable (Decision 2):** `canonical_move_plan` is persisted in full before the pointer swap, never rewritten per move, never `null`, never empty for a COMMITTING txn; progress is derived from `DONE` records only; the old key is an unknown top-level key.
2. **Evidence before count; bound and confirmed `DONE` (Decision 3):** a move is counted complete only after its `DONE` is durably appended; the `DONE` copies `expected_post_hash` / `staging_path` / `expected_pre_state` / `target_canonical` from the INTENT and carries the live `txn_id` and CURRENT `fencing_generation` as parameters; NO log scraping; `completed.json` is written only after `verify_plan_completion` over a fresh read.
3. **One module, additive (Decision 4):** the new pure functions live ONLY in `shard_manager/intent_log.rs`, appended to S-25.10's file without editing S-25.10's functions; the module names no txn-record type; `decide_intent_log_recovery` / `IntentLogRecoveryDecision` are deleted, not wrapped.
4. **Pure decision core:** `decide_recovery` is pure and total (no I/O, no panic, no `unreachable!()`); the `Fs` seam performs every effect.
5. **Error codes: ONLY existing taxonomy entries (error-taxonomy v1.42).** This story introduces NO new code: `CANONICAL_MOVE_HALTED` (exit 2) is ALREADY in v1.42 and `MIGRATION_STATE_INTEGRITY_FAILURE` (`txn_record_malformed`) is reused for B-3; `INTENT_LOG_CORRUPT` (S-25.10) is reused for the post-loop re-read. None is exit 1. A `Display` that differs from its ADR-054 Decision 3.1 line fails the S-12.13 lint gate.
6. **Rename discipline (TD-VSDD-060):** sibling-sweep every spelling of the old name in `crates/` in the same commit as the struct/serde change; `TXN_RECORD_SCHEMA_VERSION` stays 1; the key set stays TWELVE.
7. **No WASM-sandboxed executor (ADR-051 §Decision 7 / CLAUDE.md §WASM plugin fuel budgets):** the code runs native in the dispatcher binary, never in a hook plugin.
8. **Single-commit-per-burst / POL-3 (TD-VSDD-053, TD-FACTORY-HOOK-BYPASS-001):** no `.factory/` mutation by shell bypass; this story does not touch live cycle files.
