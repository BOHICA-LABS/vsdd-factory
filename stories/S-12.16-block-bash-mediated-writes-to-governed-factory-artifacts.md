# S-12.16: Block Bash-Mediated Writes to Governed `.factory/` Artifacts (Hook-Level Enforcement)

## Narrative

- **As a** factory operator who relies on the single-writer / Edit-Write-only discipline for `.factory/` (POL-3,
  TD-FACTORY-HOOK-BYPASS-001 P0)
- **I want** the dispatcher to detect a `Bash` tool call whose write effect lands on a governed `.factory/` path —
  heredoc/`cat >`, `echo >>`, `tee`, `sed -i`, `perl -pi`, `awk -i inplace`, `cp`/`mv`/`install`/`dd of=`, `truncate`,
  and inline interpreter code (`python3 -c`, `python3 - <<EOF`, `node -e`, `ruby -e`) — and BLOCK it with a diagnostic
  naming the Edit/Write alternative
- **So that** the prose prohibition that agents demonstrably ignore (five recorded bypasses in two days, across two
  agent types) becomes an enforced guarantee, bypassed writes stop landing unvalidated (the PostToolUse validators
  never see a Bash write), and the input-hash/index discipline built on Edit/Write holds

## Context / Evidence

**Evidence (human-reported 2026-10-07: five incidents — architect x4, product-owner x1).** Recorded in
`cycles/v1.0-brownfield-backfill/lessons.md` as `L-BB-D1245-architect-bypassed-edit-write-with-python-heredocs`
(process-gap D-1245-PG-001, `[pending-codification]`): architect Python heredocs on `VP-146.md` and `VP-133.md`
(D-1245), on `ADR-035` (D-1248, despite an explicit orchestrator instruction), the product-owner's `sed -i` on
`BC-1.18.013` (D-1251), and the fifth (architect) incident reported by the human on 2026-10-07, which post-dates the
D-1251 registration (the lesson/STORY-INDEX recurrence count reads four through D-1251 — the state-manager reconciles
the count). Every incident landed on disk and was remediated by re-writing through the sanctioned tool. The hook chain
blocked none: Bash-mediated writes are not reliably detected, and the PostToolUse validators (which fire on
Edit/Write) never see them.

**Root cause (from the lesson):** POL-3 is enforced as a prompt-level prose rule plus partial hook coverage; the
`^Bash$` guards cover specific shapes (`destructive-command-guard`: destructive patterns; `validate-factory-path-staging`:
staged-path correspondence; `verify-factory-lock-bash`: `git push` to factory-artifacts) but none classifies a
generic Bash write effect on a governed path. Prompt-level prohibition has been shown insufficient (recurrence x4-5
despite explicit instructions), so the dispatcher/hook enforcement arm is the load-bearing remedy.

**Prior art (this story consumes, does not redo).** ADR-052 §Decision 5c ("Full-command pre-shell classifier") already
classifies sanctioned governed-migration commands and, for a live migration window, blocks Bash commands with
unknown write effects; its OBL-4 deliverable `[D-1232-OBL-4]` (devops-engineer) — the generic Bash write-effect
classification — was deliberately left undelivered by S-25.08 (AC-004: "Write-effect `Bash` classification is the
[D-1232-OBL-4] deliverable and is NOT part of this story's tested surface"; AC-014: the classifier "MUST use the same
`resolve_target_path` function"). S-12.16 delivers it for the POL-3 purpose (always-on, not only during a migration
window) and reuses S-25.08's resolver and anchoring.

**Claim boundary (stated honestly).** Static analysis of a command string cannot see inside an opaque script FILE
(`python3 ./x.py` where `x.py` writes `.factory/...`) or inside a shell variable expanded at run time. This story's
enforcement is therefore: (1) every write effect expressible in the command text with a resolvable target; (2) a
CONSERVATIVE block when an interpreter invocation (inline `-c`/`-e`, heredoc/stdin script) names a governed path
outside a recognised read-only idiom; (3) a documented residual for opaque script files and run-time-computed paths,
whose backstops are the sibling-prompt prohibition (AC-011) and the existing post-hoc detectors. The residual is a
design limit of static classification, not a deferral.

## Acceptance Criteria

> All assertions use the real `factory-dispatcher` binary (spawned process, PreToolUse envelope for tool `Bash` on
> stdin, tempdir project with a `.factory/`), never a direct classifier call alone — a unit test cannot see a missing
> call site (S-25.08 claim boundary). "Governed path" = any path resolving under the session's `factory_root`
> (S-25.08 `resolve_factory_root`), because POL-3 forbids non-Edit/Write mutation of everything under `.factory/`.

- **AC-001 (traces to BC pending PO authorship):** A PreToolUse `Bash` command whose write effect targets a governed
  path through shell redirection — `> f`, `>> f`, `&> f`, `cat > f <<'EOF'`, `echo ... > f`, `printf ... >> f`, `tee f` /
  `tee -a f` — exits 2 with a block diagnostic naming the Edit/Write alternative; the file is unchanged (the command
  never runs).
- **AC-002 (traces to BC pending PO authorship):** In-place editors and copy/move writers with a governed destination —
  `sed -i`, `perl -pi`/`-i`, `awk -i inplace`, `ex`/`vi -es`, `cp SRC DEST`, `mv SRC DEST`, `install`, `dd of=DEST`,
  `truncate -s`, `rsync` into the tree — are blocked identically. A governed SOURCE with a non-governed destination
  (`cp .factory/x /tmp/x`) is a read and is allowed.
- **AC-003 (traces to BC pending PO authorship):** Inline interpreter code — `python3 -c '...'`, `python3 - <<'EOF'`,
  `python`, `node -e`, `ruby -e`, `perl -e`, `bash -c`/`sh -c` wrapping any of the above — whose text names a governed
  path in a write context (`open(..., 'w'|'a'|'x'|'r+')`, `write_text`, `fs.writeFile*`, `File.write`, a redirection
  inside `-c`) is blocked; the classifier recurses into `bash -c`/`sh -c` strings and heredoc bodies. Where the text
  names a governed path but the write context cannot be determined, the command is blocked CONSERVATIVELY (ADR-052
  §Decision 5c precedent for unknown write effects) unless it matches a recognised read-only idiom (AC-005).
- **AC-004 (traces to BC pending PO authorship):** Target resolution reuses S-25.08's `resolve_target_path` and
  `resolve_session_project_root` / `resolve_factory_root` — NO second resolver: `..`, `.`, `//`, symlink aliases,
  case-insensitive family names, relative paths joined onto the command's `cwd`, nonexistent tails and the
  two-spelling lexical root rule behave identically to the Edit/Write admission gate (S-25.08 AC-013/AC-014). A write to
  a path OUTSIDE the session's `factory_root` is out of scope and allowed (no spurious block for another project's
  `.factory`).
- **AC-005 (traces to BC pending PO authorship):** Read-only and sanctioned forms are never blocked (no false
  positive): `cat`/`head`/`tail`/`grep`/`rg`/`ls`/`wc`/`diff`/`git -C .factory status|diff|log|show|add|commit|push|
  rebase|reset --soft` and other `git` subcommands operating through git, `mkdir -p`, redirections to `/dev/null`,
  `2>&1`, process substitution reads, and the sanctioned governed-migration CLI invocations of ADR-052 §Decision 5c
  Branches 1-4 (`{canonical-binary} migrate-bc-index|backfill-append-logs [--census]`, subject to their own guards) pass
  this leg untouched. A regression corpus of >= 60 real read-only `.factory/` commands harvested from the repo's
  agents/skills/scripts blocks none.
- **AC-006 (traces to BC pending PO authorship):** Exemption by capability, never by identity string: the hook does not
  consult agent names. A command that is both a write-effect and sanctioned (the governed CLI) is decided by the
  §Decision 5c branch logic, not by this leg; any other command writing a governed path is blocked regardless of the
  calling agent (state-manager included — its sanctioned write path is Edit/Write plus `git`).
- **AC-007 (traces to BC pending PO authorship):** The block verdict is a dispatcher-native PreToolUse leg evaluated
  after payload parse + project-root resolution and BEFORE registry plugin tiers (registry-independent, same position
  discipline as S-25.08 AC-012 O1-O4): with `CLAUDE_PLUGIN_ROOT` unset, a missing/unparseable registry, or an empty
  matched-plugin set, a governed Bash write is still blocked. The leg returns the existing `HookResult` Block shape
  (exit 2); a `blocking_plugins=` label of its own (e.g. `bash-write-guard`, a closed `NativeGate` member added by this
  story, extending S-25.08 AC-025's enum) appears in the operator stderr summary.
- **AC-008 (traces to BC pending PO authorship):** The block diagnostic is a single operator-readable line naming the
  detected write form, the resolved governed target, and the sanctioned alternative: `E-<NEW-CODE>: Bash write to
  governed .factory/ path blocked (<form>: <target>); use the Edit or Write tool (large rewrite: Write with full
  content, or several targeted Edits)`. The error code is NEW — add to error-taxonomy (flagged "NEW — add to
  taxonomy"; product-owner allocates the ID and Display-parity rows per the S-12.13 lint gate).
- **AC-009 (traces to BC pending PO authorship):** Every block writes exactly one `bash_write.blocked`
  InternalLog event (dispatcher-internal JSONL; fields: `form`, `target_family`, `target_sanitized`, `classified_as`
  ∈ {`redirection`, `inplace_editor`, `copy_move`, `interpreter_inline`, `conservative_unknown`}) — no raw command
  text beyond a length-capped, control-escaped excerpt; assertions read `dispatcher-internal-*.jsonl`, never a
  tracing capture (the dispatcher installs no subscriber; see S-26.06).
- **AC-010 (traces to BC pending PO authorship):** Fail behavior is closed on classifier error: a classifier panic,
  unparseable shell syntax (unbalanced quotes/heredoc) or a resolver I/O error on a command that mentions a governed
  path blocks (conservative) with the AC-008 line and `classified_as=conservative_unknown`; a command that mentions no
  governed path and is unparseable is allowed (the leg never blocks unrelated Bash).
- **AC-011 (traces to BC pending PO authorship):** Sibling-prompt sweep: every spec-authoring agent prompt in
  `plugins/vsdd-factory/agents/` that can mutate `.factory/` — architect, product-owner, story-writer, business-analyst,
  formal-verifier, consistency-validator, spec-steward, spec-reviewer, adversary-adjacent writers, technical-writer,
  state-manager — carries the explicit "Edit/Write only for `.factory/` mutations; no Python/sed/echo/heredoc/`tee`
  writes; large rewrite = Write with full content or several Edits" prohibition, and a bats/lint assertion fails if any
  such prompt omits it (the state-manager prompt is the reference text).
- **AC-012 (traces to BC pending PO authorship):** Detection of the residual is observable: when a governed file
  changes with no Edit/Write/MultiEdit/`git` event attributable in the session (the opaque-script residual), the
  dispatcher's existing PostToolUse path or the burst-start check surfaces `[bash-write-residual]` as an advisory event
  — OR the story records, with architect concurrence, that no sound detector exists and the residual stays under the
  prompt-level prohibition plus the AC-011 lint (decision recorded in T-1; whichever is chosen is asserted by test).

## Architecture Compliance Rules

1. **One resolver, one anchoring rule (ADR-052 §Decision 5a "Target path resolution", "Single anchoring rule"):** the
   Bash leg obtains targets ONLY through S-25.08's `resolve_target_path` and the project/factory root ONLY through
   `resolve_session_project_root` / `resolve_factory_root`; no substring `contains(".factory/…")` test anywhere.
2. **Registry-independent evaluation position (same discipline as S-25.08 AC-012):** evaluated before the
   `CLAUDE_PLUGIN_ROOT` tiering / `Registry::load`; a broken registry never makes a governed Bash write pass.
3. **Pure classifier, effectful shell:** `bash_write_guard.rs` has no I/O, no env, no ambient cwd; the shell resolves
   targets and writes the event.
4. **Capability, not identity:** no agent-name checks; exemptions are command shapes (git, read-only, sanctioned CLI).
5. **Diagnostics via InternalLog only:** the `bash_write.blocked` event is written by `main.rs` through `InternalLog`;
   never `tracing` (no subscriber installed); no raw command text beyond a capped, escaped excerpt.
6. **Error codes: the block code is NEW — flagged "NEW — add to taxonomy" (AC-008); no existing code is reused with
   different semantics.**
7. **No WASM-sandboxed classifier:** native dispatcher leg (CLAUDE.md fuel-budget constraint; ADR-051 §Decision 1).
