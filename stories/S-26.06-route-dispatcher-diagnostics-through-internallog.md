# S-26.06: Route Dispatcher Diagnostics Through InternalLog (No More Discarded `tracing` Output)

## Narrative

- **As a** factory operator diagnosing a dispatcher, hook or sharding problem in production
- **I want** every operator-relevant diagnostic the `factory-dispatcher` binary produces — today ~65
  `tracing::{error,warn,info,debug}!` call sites that go nowhere — to be a structured `InternalLog` event in
  `dispatcher-internal-YYYY-MM-DD.jsonl` (or, for the coordinator CLI subcommands, a stderr line), with the verdicts,
  exit codes and operator summary lines unchanged
- **So that** a warning the code already decided was worth emitting actually reaches someone, the production dispatcher
  stops carrying ~65 silent no-ops that read as observability, and tests assert diagnostics through the durable channel
  rather than a `tracing` capture that production never sees

## Context / Evidence

**Fact (re-verified 2026-10-07 on `develop` ce2421be).** `crates/factory-dispatcher/Cargo.toml` depends on `tracing`
(not `tracing-subscriber`); the binary installs no global subscriber; therefore every `tracing::*!` macro in the crate
is a no-op in production. Inventory by file (count method: `grep -rc 'tracing::\(warn\|error\|info\|debug\|trace\)!'
crates/factory-dispatcher/src`): `shard_manager.rs` 40, `invoke.rs` 9, `indeterminate_marker.rs` 7, `executor.rs` 6,
`vsdd_sink.rs` 2, `sinks/mod.rs` 1 = 65 (57 warn, 1 error, 2 info, 5 debug, 0 trace). The workspace root pins
`tracing-subscriber 0.3` (`env-filter`, `json`) for other crates, which is the "install a subscriber" alternative.

**Precedent and boundary.** ADR-052 §Decision 5a "Admission diagnostics channel" (S-25.08) decided the channel for the
ADMISSION-mandated subset: `InternalLog::write` called by the `main.rs` shell from diagnostics-as-data, three event types
(BC-3.08.001 Events 11-13), and explicitly "installing a global subscriber is explicitly NOT the fix ... a
dispatcher-wide logging-policy change that belongs to a separate decision". It also states the PRE-EXISTING dispatcher-wide
discard of the other call sites "is out of this ADR's scope and is not a S-25.08 obligation". THIS story is that
follow-up: T-1 is the separate decision; T-4..T-6 are the conversions.

**Default path (human direction: "route all dispatcher diagnostics through InternalLog (or install a proper subscriber
per ADR decision)").** The ACs below are written for the InternalLog outcome — consistent with ADR-052 §5a, BC-3.08.001's
durable-sink precedent and the registry-independent positions where no `HostContext` exists. T-1's architect decision
is made FIRST and recorded; if it elects a subscriber instead, this story is amended (ACs 001-007/009 rewritten) before
T-3 begins — the decision is not left open inside implementation.

## Acceptance Criteria

> Every assertion about emitted diagnostics reads `dispatcher-internal-*.jsonl` (or the coordinator's stderr) from a
> spawned real `factory-dispatcher` binary — never a `tracing` capture (production has no subscriber). "Site" = one
> `tracing::{error,warn,info}!` macro invocation in `crates/factory-dispatcher/src`.

- **AC-001 (traces to BC pending PO authorship):** A committed, machine-readable INVENTORY
  (`crates/factory-dispatcher/tests/fixtures/dispatcher_diagnostic_sites.toml`) classifies EVERY current site (file,
  enclosing function, level, message gist) into exactly one disposition: `event` (-> InternalLog event type + fields),
  `stderr` (coordinator CLI process line, S-25.09 AC-002(f) pattern), `breadcrumb` (developer-only; stays
  `tracing::debug!`, no obligation), or `remove` (dead/duplicate, with the reason). The inventory is the single source of
  truth for AC-002 and carries the count at authoring time (65 on `develop` ce2421be; the S-25.08-converted admission
  sites drop out once it merges).
- **AC-002 (traces to BC pending PO authorship):** A source-level gate test fails if any `tracing::error!`,
  `tracing::warn!` or `tracing::info!` macro invocation exists in `crates/factory-dispatcher/src` that is not a
  `breadcrumb`-classified `debug!` — i.e. the production-relevant levels are EMPTY after this story — and fails if an
  inventory entry no longer corresponds to a real site (no stale entries). New sites added later must either be
  breadcrumbs or use the channel (the gate makes the rule self-enforcing).
- **AC-003 (traces to BC pending PO authorship):** Every `event`-disposition site emits exactly ONE `InternalEvent` whose
  `type` is a named constant in `internal_log.rs` (like `MIGRATION_ADMISSION_*`), with a closed field set, written via
  `InternalLog::write`; each new event type is catalogued in BC-3.08.001 (product-owner) with wire format, trigger,
  emission path and durable sink; no event carries a raw id, raw command text, record content or an unbounded string
  (length-capped, control-character-escaped — the S-25.09 AC-002 sanitization rules).
- **AC-004 (traces to BC pending PO authorship):** Purity is preserved: pure modules and pure cores (`shard_manager`
  decision functions, `invoke.rs` classification, `indeterminate_marker` pure parts) do NOT write the log and do not
  gain an `InternalLog` dependency; they return diagnostics as DATA (`Vec<...Diagnostic>` on their result types, the
  S-25.09 `AdmissionDiagnostic` shape) and the effectful shell (`main.rs` / the executor shell that already holds the
  `InternalLog`) writes them immediately after the call. No `static`/global logger, no `lazy_static` log handle.
- **AC-005 (traces to BC pending PO authorship):** Behavior preservation: converting a site changes NO verdict, exit
  code, stdout byte, operator summary line (`blocking_plugins=` / `block_reason=`) or ordering of side effects; a
  black-box regression corpus (the existing bats + cargo suites plus a snapshot of exit codes/stderr for >= 10
  representative dispatch scenarios per converted file) is byte-identical before/after except for the added
  `dispatcher-internal-*.jsonl` lines.
- **AC-006 (traces to BC pending PO authorship):** Diagnostic failure is never a verdict: an `InternalLog` write failure
  (unwritable log dir, mount-gate suppression per issue #206, disk full) leaves every verdict and exit code unchanged,
  never panics (existing `InternalLog::write` best-effort contract), and surfaces the existing single stderr fallback
  line; asserted with an unwritable `VSDD_LOG_DIR` against the dispatch scenarios.
- **AC-007 (traces to BC pending PO authorship):** Representative black-box coverage: for EVERY file in the inventory
  (`shard_manager.rs`, `invoke.rs`, `indeterminate_marker.rs`, `executor.rs`, `vsdd_sink.rs`, `sinks/mod.rs`) at least one
  `event`-disposition site is triggered through the real binary and exactly one matching event (type, fields) is found
  in `dispatcher-internal-*.jsonl`; negative control: the benign path of the same scenario emits none.
- **AC-008 (traces to BC pending PO authorship):** No subscriber is installed and none is needed: `factory-dispatcher/
  Cargo.toml` gains no `tracing-subscriber`, and no `set_global_default` / `tracing_subscriber::` appears in
  `crates/factory-dispatcher/src` (source gate) — conditional on T-1 electing the InternalLog outcome; the remaining
  `tracing::debug!` breadcrumbs are explicitly documented as developer-only, discarded in production by design.
- **AC-009 (traces to BC pending PO authorship):** Coordinator CLI subcommands (`migrate-bc-index`,
  `backfill-append-logs`, and any other subcommand in the inventory) route their failures/advisories to STDERR as one
  `E-…`/`<VARIANT>`-prefixed line per the S-25.09 AC-002(f) / S-25.06 AC-035 pattern (a CLI process has no hook
  summary surface). Any developer trace kept alongside the stderr line is a `tracing::debug!` breadcrumb — a
  `tracing::error!`/`warn!` there would violate AC-002, so the former error-level trace becomes the stderr line plus,
  optionally, a `debug!`.
- **AC-010 (traces to BC pending PO authorship):** Error codes: every new operator-visible string is either an existing
  taxonomy code or flagged "NEW — add to taxonomy" with Display parity rows (S-12.13 lint gate); no invented code and no
  reuse of an existing code with different semantics.
- **AC-011 (traces to BC pending PO authorship):** Per-dispatch volume is bounded: no converted site inside a per-plugin /
  per-record loop can emit an unbounded number of events for one dispatch — each event type documents a per-dispatch
  maximum (dedupe by key like `INTERNAL_DISPATCHER_ERROR`, or a cap with a final `...truncated` count field); a test with
  500 plugin outcomes / 500 reservation files asserts the bound; the dispatcher-internal log growth for the existing
  bats suite stays within the documented budget.

## Architecture Compliance Rules

1. **Channel (ADR-052 §Decision 5a "Admission diagnostics channel"):** diagnostics are `InternalLog::write` events from the
   shell (or stderr lines for CLI subcommands); `tracing` is never a mandated channel; no subscriber is installed
   (conditional on T-1's recorded outcome).
2. **Pure core, effectful shell:** pure modules return diagnostics as data; only the shell writes the log; no global
   logger.
3. **No raw ids / record content / unbounded strings in any event or stderr line;** reuse the S-25.09 sanitizers.
4. **Verdict invariance:** a diagnostic conversion never changes a verdict, exit code, stdout byte or summary line.
5. **Bounded emission per dispatch** (AC-011); dedupe or cap like `INTERNAL_DISPATCHER_ERROR`.
6. **Error codes: ONLY existing taxonomy entries, or flagged "NEW — add to taxonomy" with Display-parity rows.**
7. **Single-commit-per-burst / POL-3:** this story touches no `.factory/` mutation except through Edit/Write.

### Forbidden Dependencies (build-time enforcement)

- `crates/factory-dispatcher` MUST NOT gain `tracing-subscriber` (or any logging-framework dependency) unless T-1's
  recorded outcome is "subscriber"; if it gains it otherwise the AC-008 gate MUST fail.
- Pure diagnostic-data modules MUST NOT depend on `InternalLog`, `std::fs`, `std::process`, ambient time or env.
- `last-amended-migrate` MUST NOT depend on `factory-dispatcher` (workspace rule; ADR-051 §8). The existing
  `factory-dispatcher` -> `last-amended-migrate` edge is legitimate and unchanged.
- No new external crates without architect approval.
