# S-21.19: Executor decision-function core — 3-arg `failure_policy` extension + axes-independence (ADR-039 Phase 4a; split seam 1 of 6 from S-21.11)

## Narrative

- **As a** factory pipeline operator whose validator writes are currently approved silently
  when a WASM plugin exhausts its fuel budget
- **I want** the dispatcher's block-decision function extended to consult a
  `failure_policy: FailurePolicy` axis (independent of `on_error`) for `Timeout{Fuel|Epoch}`
  outcomes, plus the narrow PC13 `on_error=Block` + `Ok{exit_code!=0}` predicate extension
  that closes the plugin-error-exit gap — with the standing AC-001 calibration gate and the
  AC-012 migration-window gate already authored and passing their pure-function controls
  before this extension lands
- **So that** the exhaustion-outcome enforcement decision is axes-independent and
  calibration-gated from the moment it ships, and every downstream seam (bash-adapter
  wiring/calibration, native-WASM flip, break-glass ordering, PC13 full-registry coverage)
  has a stable, already-tested decision-function core to build against

## Context / Finding Summary

ADR-039 §Context establishes the enforcement defect this story closes:

1. **The detection mechanism is already correct.** `Trap::OutOfFuel` is distinguished from
   clean completion in `invoke.rs` → `PluginResult::Timeout { cause: TimeoutCause::Fuel }`.
   The defect is enforcement, not detection.

2. **The enforcement defect is CWE-636.** `plugin_fail_closed` returns `false` when
   `on_error == OnError::Continue`, regardless of `TimeoutCause`. The existing deliberate
   test `fail_closed_timeout_with_on_error_continue_is_open` encodes this policy. Any change
   requires revising that test **deliberately** (TD-VSDD-059: not deleting it, not renaming
   it; revising it to cover the new semantics for the `fail-open` configuration case).

3. **Safe migration ordering (ADR-039 §Decision 3).** S-21.10 (Phase 1, merged prerequisite)
   added the `failure_policy` TOML field to the registry schema with a `fail-open` default.
   This story delivers the Phase 4a decision-function extension — the conceptual heart of
   ADR-039 Phase 3+4 enforcement, split from the originally-unified S-21.11 per the operator's
   2026-08-20 split directive. This story has **no dependency** on the bash-adapter wiring fix
   (S-21.21), per-plugin calibration (S-21.21/S-21.22), or the break-glass mechanism (S-21.23)
   — it is calibration-axis-agnostic, which is why it lands first (wave 6) and the four
   parallel seams land afterward (wave 7).

4. **PC13 (`on_error=Block` + `Ok{exit_code!=0}` → block, ADR-039 §AMD-003).** This story also
   authors a SECOND, STANDALONE decision-function predicate — `plugin_fail_closed_on_error_exit`
   (ADR-044) — distinct from point 3's `plugin_fail_closed_on_exhaustion`, to
   close a distinct gap: a plugin that ran to completion without crashing or timing out at the
   WASM-trap/epoch layer, but returned a nonzero exit via its own reported `HookResult::Error`.
   This closes F-001 (a `legacy-bash-adapter.wasm`-hosted plugin's host-wall-clock timeout does
   NOT produce `PluginResult::Timeout{..}` — it propagates as `Ok{exit_code:1}`) at the unit
   level. Unlike point 3's exhaustion leg, this leg's LIVE WIRING is not deferred to S-21.24 —
   per ADR-044 (F-S2121-P1-002), it is wireable immediately and owned by
   **S-21.21 at wave 7**, because it references neither `.failure_policy` nor `Timeout` and
   trips nothing in PC11's detector. The end-to-end fixture proof that this predicate closes
   F-001 against a real dispatch belongs to S-21.21 (gated on its own AMD-002 wiring fix AND
   its own new live-wiring task for this predicate); the registry-wide demonstration that this
   predicate protects all 18 `on_error="block"` entries, not just the six exhaustion-targeted
   plugins, belongs to S-21.20.
