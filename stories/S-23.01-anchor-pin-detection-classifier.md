# S-23.01: Live-section classifier + newline-normalized, anchor-interposed-tolerant pin-pattern detector

## Narrative

- **As a** downstream tool (the pre-commit normalization codemod, S-23.02, and the thin new-pin
  guard hook, S-23.03)
- **I want** a single, shared, pure Rust library that (a) classifies a markdown document's text
  into "live/load-bearing" vs "exempt/historical" regions, and (b) detects
  `(stable-ID, inline-version-token)` pairs within live regions even when they are separated by
  a line-wrap or an interposed section anchor
- **So that** both the codemod and the guard defeat Wave-7 failure modes 1 (line-wrapped cites),
  2 (anchor-interposed cites), and 3 (live-vs-historical ambiguity) identically, by construction,
  with no drift between the two tools' notion of "load-bearing"

## Context / Problem Statement

ADR-045 §Context documents four self-regenerating Wave-7 straggler failure modes. Modes 1–3 are
detection problems: a naive per-line `grep` misses a version token that wraps to the next
physical line (mode 1) or is separated from its ID by an anchor phrase like `§Decision 3` (mode
2); an undiscriminating sweep either destroys legitimate historical provenance in changelog rows
or misses live cites next to a misidentified section boundary (mode 3). ADR-045 §Migration Plan
Phase A requires both a codemod (step 2, cheaper than full Tier-3 AST) and a guard (also step 2)
that share this detection logic — building it twice would let the two tools' definitions of
"live" and "load-bearing" drift apart, silently reopening the exact failure classes ADR-045
closes.

A precedent already exists in this codebase for the *sibling* problem (volatile source-line
citations, not version pins): `crates/hook-plugins/validate-stable-anchors/src/lib.rs`
implements a `SOURCE_FILE_EXTENSIONS` allowlist detector plus an `is_exempt_line` classifier for
three exemption zones (Amendment sections, Changelog tables, one operationally-required
exception). This story's exemption-zone model generalizes that pattern to the ADR-045 target
form (`ID vN.NN` pairs, not `file.ext:NNN` pairs) and to the ADR-045-specific exemption list,
which is broader: frontmatter `modified:` / `last_amended:` / `[Prior:]` changelog blocks, cycle
logs, decision-log/burst-log narrative prose, and `## Amendment` / `## Changelog` sections.

This story does **not** build the full Tier-3 comrak/pulldown-cmark AST validator (ADR-045
§Decision, Tier 3, DEFERRED/GATED). It builds a lighter-weight, regex-plus-newline-normalization
detector sufficient for the "thin" guard and the one-shot codemod, per ADR-045's own framing of
the cheaper Phase-A build target ("a lightweight pre-commit check — regex-based codemod-class
detector is sufficient at this stage").

## Acceptance Criteria

### AC-001
The classifier correctly labels the following regions as **exempt** (non-load-bearing) when
present in a `.factory/` markdown document: frontmatter `modified:` array entries; frontmatter
`last_amended:` field; `[Prior: ...]` bracketed changelog-chain suffixes; `## Changelog` /
`## Amendment` sections and any body table under a heading matching
`Changelog|History|Revision History|Superseded|Modified|Prior`; cycle-log files under
`.factory/cycles/**`; decision-log (`decision-log.md`) and burst-log (`burst-log.md`) narrative
prose describing a specific prior revision by version. (traces to ADR-045 §Decision, Tier 1,
"Permitted exceptions" bullet list, precondition)

### AC-002
The classifier correctly labels all other markdown body text (headings, paragraphs, tables,
list items outside the exempt zones of AC-001) as **live/load-bearing**. (traces to ADR-045
§Decision, Tier 1, "Permitted forms" / "Prohibited forms" contrast, postcondition 1)

### AC-003
The detector finds a `(stable-ID, version-token)` pair when the two tokens are separated only
by a soft line-wrap within the same logical paragraph/table-cell/list-item (e.g., `BC-1.03.017`
at the end of one physical line and `v1.27` at the start of the next), by normalizing internal
newlines to a single space before tokenizing — defeating failure mode 1. (traces to ADR-045
§Context, failure mode 1; ADR-045 §Decision, Tier 3 item 3, "Normalizes soft breaks" — applied
here at the lighter regex-detector tier, not the full AST tier)

### AC-004
The detector finds a `(stable-ID, version-token)` pair when a semantic anchor phrase (e.g.
`§Decision 3`) intervenes between the ID and the version token within the same logical text
run, by tokenizing IDs and versions independently and associating the nearest following version
token within an N-token window (stopping at another identity token or a sentence boundary) —
defeating failure mode 2. (traces to ADR-045 §Context, failure mode 2; ADR-045 §Decision, Tier 3
item 4, "Tokenizes ID and version independently" — applied at the lighter regex-detector tier)

### AC-005
The detector recognizes all four ADR-045 stable-ID forms: `BC-\d+\.\d{2}\.\d{3}`, `ADR-\d+`,
`S-\d+\.\d+` (or `S-\d+\.\d{2}`), `VP-\d+`, each optionally followed by an inline version token
matching `v\d+(?:\.\d+)*`. (traces to ADR-045 §Decision, Tier 1, "Permitted forms" bullet)

### AC-006
The detector returns, for each finding, a structured result with source position (file path,
line, column) sufficient for the codemod to perform a targeted replacement and for the guard to
emit an actionable diagnostic. (traces to ADR-045 §Decision, Tier 3 item 5, "emits a diagnostic
with source position" — applied at the lighter regex-detector tier per this story's scope)

### AC-007
A documented informational-parenthetical exemption is honored: `(as of vX.Y at D-NNNN)` inside a
historical note is classified exempt even when it is not inside one of AC-001's structural
exempt zones, provided it is syntactically parenthetical and the surrounding sentence does not
gate on the version. (traces to ADR-045 §Decision, Tier 1, "Permitted exceptions" bullet,
"Provenance parentheticals")

### AC-008 (negative control)
The classifier does NOT exempt a live BC-traceability-table version cell or a live story AC body
sentence merely because it appears near a table — only headings/tables that are themselves
under an exempt heading (per AC-001) or are a `[Prior:]`/`modified:`/`last_amended:` frontmatter
field are exempt. (traces to ADR-045 §Context, failure mode 3, "Live vs historical ambiguity")

## Edge Cases

| ID | Description | Expected Behavior |
|----|-------------|-------------------|
| EC-001 | ID and version token both present but separated by more than the N-token association window (e.g., an entire unrelated sentence intervenes) | Detector does NOT associate them; ID alone is reported as a bare cite (no finding) |
| EC-002 | Two IDs in sequence, each followed by its own version token (`BC-1.03.017 v1.27, BC-1.03.018 v1.4`) | Each `(ID, version)` pair associates with the nearer ID, not a cross-pair mismatch |
| EC-003 | Version-token-looking substring inside a code fence (e.g., a Cargo version pin `wasmtime = "48.0.4"`; illustrative fixture only, not a statement of the current workspace pin — ADR-035 v1.2 §Decision 6) | Code fences are excluded from live-section scanning entirely; no false positive |
| EC-004 | `[Prior: ... BC-1.03.017 v1.20 ...]` bracketed chain nested inside a live-looking paragraph (not a dedicated Changelog heading) | Classified exempt by the `[Prior:]` bracket-form rule (AC-001), independent of heading structure |
| EC-005 | Escaped-pipe version chains inside a table cell (`v1.3 \| v1.6`, precedent from `validate-cross-site-correspondence` F-S2107-P1B-006) | Detector must not misparse the escaped pipe as a table-cell boundary; last unescaped-pipe-delimited value wins |

## Architecture Compliance Rules

- The crate MUST be pure Rust with zero host-function or filesystem dependency in its core
  `classify_region`/`detect_pins` API — callers (codemod binary, WASM guard) own all I/O.
- No `unwrap()` or `expect()` in the public API path (CLAUDE.md Conventions — error taxonomy).
- No `println!` — this is a library crate with no CLI surface of its own; if a debug-trace
  feature is added later, it must use `tracing::*!`.
- Regex compilation MUST be done once (e.g., via `once_cell`/`std::sync::LazyLock`), not
  per-call, to keep the detector cheap enough for the codemod to run corpus-wide and for the
  guard to run per-write without meaningful latency.
