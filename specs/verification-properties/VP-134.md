# VP-134: B2 BC-INDEX Migration Introduces No New Cohort-B Sequencing Dependency — BC-7.08.001's Fail-Closed Flip Gating Never Cites BC-1.18.011

## Property Statement

Unlike BC-1.18.008 (whose backfill-split BC-7.08.001's fail-closed flip DOES depend on, since
`regression-gate`/`convergence-tracker` read the four mechanism-A artifacts and VP-130 gates the flip
on that backfill's completion), the B2 `BC-INDEX.md` migration introduces NO Cohort-B sequencing
dependency: `regression-gate`/`convergence-tracker` do not read `BC-INDEX.md`. This is a structural,
source/config-level invariant best enforced by CI audit — the same enforcement class as VP-129
(Cohort-B config audit), VP-046, and VP-099.

1. **No flip-gating citation of BC-1.18.011.** BC-7.08.001's fail-closed-flip gating conditions — as
   expressed in `hooks-registry.toml`'s `failure_policy` deployment sequencing and any flip-PR
   template / sequencing gate (the VP-130 sequencing artifact) — cite ONLY BC-1.18.005 / BC-1.18.006
   / BC-1.18.008, and NEVER reference BC-1.18.011's migration completion as a precondition
   (BC-1.18.011 §Postcondition 7, §Invariant 4).

2. **No implicit dependency in the migration code.** `shard_manager.rs`'s B2 one-time-migration
   entry point does not write, signal, or gate any Cohort-B `failure_policy` state, and no
   `regression-gate`/`convergence-tracker` code path reads `BC-INDEX.md` or the B2 shard manifest as
   a fail-closed-flip precondition (BC-1.18.011 §Postcondition 7's migration-impact-map basis;
   §EC-005 — making this migration a flip precondition is a detectable scope violation, not a valid
   choice).

## Source Contract

  absent from those conditions.

### Why static-check

"No new sequencing dependency" is a structural, source/config-level ABSENCE invariant — the cheapest
and most reliable enforcement is a CI grep asserting BC-1.18.011 does not appear in BC-7.08.001's
flip-gating conditions and that the B2 migration code touches no Cohort-B `failure_policy` state (the
same enforcement class as VP-129's Bash-arm-exclusion config audit and VP-046's registry-correspondence
check). A behavioral test cannot prove the ABSENCE of a dependency across the whole flip-gating
surface; the static audit is the right tool for a negative structural guarantee.

## Proof Harness Skeleton

```bash
# ci/checks/vp134_b2_no_cohort_b_dependency.sh
# VP-134: BC-1.18.011 PC7/INV4/EC-005 — B2 migration adds no Cohort-B sequencing dependency

set -euo pipefail
REG=plugins/vsdd-factory/hooks-registry.toml
SM=crates/factory-dispatcher/src/shard_manager.rs

# (1) BC-7.08.001's flip-gating must NOT cite BC-1.18.011 anywhere in its sequencing conditions.
if grep -REn 'BC-1\.18\.011' "$REG" ci/flip-sequencing/ 2>/dev/null | grep -iE 'failure_policy|precondition|gate|flip'; then
  echo "FAIL: BC-1.18.011 referenced as a Cohort-B flip precondition (BC-1.18.011 PC7/INV4 violation)"; exit 1
fi

# (2) The B2 migration handler must write no Cohort-B failure_policy state.
# v1.1 (ADR-052 v1.18): shard_manager.rs now also hosts the SHARED admission core and the
# mechanism-A recovery/reconciliation cores, whose migration-internal decision enums legitimately
# contain `FailClosed` / `FailClosedMismatch` / `RecoveryDecision::FailClosed` (crash-recovery
# outcomes, not Cohort-B `failure_policy`). The pattern therefore targets the Cohort-B CONFIG
# vocabulary only (the `failure_policy` key / `FailurePolicy` type and the two hook names).
if grep -qE 'failure_policy|FailurePolicy|regression-gate|convergence-tracker' "$SM"; then
  echo "FAIL: B2 migration handler touches Cohort-B failure_policy state (EC-005 scope violation)"; exit 1
fi
echo "PASS: VP-134 — B2 migration introduces no new Cohort-B sequencing dependency"
```
