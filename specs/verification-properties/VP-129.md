# VP-129: Cohort B Flip Never Fail-Closes the validate-burst-log ^Bash$ Arm and Adds Exactly Three fail-closed Entries (Closed Cohort)

## Property Statement

The Cohort B `failure_policy` flip touches exactly the intended registry entries and nothing else.

1. **Bash-arm exclusion.** The `[[hooks]] name = "validate-burst-log" event = "PostToolUse" tool =
   "^Bash$"` entry (the exec-free git-commit chain-detection arm) is NEVER assigned
   `failure_policy = "fail-closed"` by this BC — its `failure_policy` field is absent (fail-open)
   both before and after the change (BC-7.08.001 §Postcondition 1, §Invariant 1). Only the
   `tool = "^(Edit|Write|MultiEdit)$"` arm of `validate-burst-log` is flipped.

2. **Closed cohort of exactly three.** Exactly three `[[hooks]]` entries carry
   `failure_policy = "fail-closed"` as an attributable consequence of this BC — `validate-burst-log`
   (Edit/Write/MultiEdit arm), `regression-gate`, and `convergence-tracker` — matching the named set
   with no unattributed additions (BC-7.08.001 §Postcondition 5, §Invariant 3). No other
   currently-fail-open validator is flipped as a side effect; any future expansion requires its own
   BC.

Verified by a static config-diff / audit over `hooks-registry.toml`, cross-referencing BC-1.18.004's
Cohort A enumeration plus this BC's Cohort B enumeration so that no `fail-closed` entry is
unattributed.

## Proof Method

| Leg | Method | Tool | Coverage | Status |
|-----|--------|------|----------|--------|
| Bash-arm exclusion | static-check | config-diff over `hooks-registry.toml` | the `validate-burst-log` `^Bash$` entry's `failure_policy` is absent before AND after | feasible-pending-harness (F4 registry change) |
| Closed cohort of three | static-check | config audit: grep `fail-closed` entries, cross-reference Cohort A + Cohort B enumerations | exactly the three named Cohort B entries flipped; no unattributed entry | feasible-pending-harness (F4 registry change) |

### Why static-check

The flip's correctness is a property of the declarative `hooks-registry.toml` config text — a
config-diff / grep audit (the cheapest correct mechanism, same class as VP-046/VP-099 registry
invariants and VP-061) directly asserts which entries carry `fail-closed` and which do not. A runtime
test could not cheaply prove the Bash arm was *never* flipped.

## Proof Harness Skeleton

```bash
# ci/checks/vp129_cohort_b_config_audit.sh
# VP-129: BC-7.08.001 PC1/PC5/INV1/INV3

set -euo pipefail
REG=plugins/vsdd-factory/hooks-registry.toml

# (1) Bash-arm of validate-burst-log must NOT be fail-closed.
if toml-get "$REG" 'validate-burst-log' '^Bash$' failure_policy | grep -q 'fail-closed'; then
  echo "FAIL: validate-burst-log ^Bash$ arm must never be fail-closed (VP-129/Invariant 1)"; exit 1
fi

# (2) Exactly the three named Cohort B entries carry fail-closed; every fail-closed entry is
#     attributable to Cohort A (BC-1.18.004) or Cohort B (BC-7.08.001).
COHORT_B='validate-burst-log:^(Edit|Write|MultiEdit)$ regression-gate convergence-tracker'
audit-failclosed "$REG" --cohort-a "$(bc_1_18_004_cohort_a)" --cohort-b "$COHORT_B" \
  || { echo "FAIL: unattributed fail-closed entry"; exit 1; }
echo "PASS: VP-129 closed-cohort invariant holds"
```
