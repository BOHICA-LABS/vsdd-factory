# VP-143: Governed Mechanism-A Migration (backfill-append-logs) — Four-File All-or-Nothing Atomicity AND Two-Layer Idempotency Consistency

## Property Statement

The governed one-time mechanism-A migration (`backfill-append-logs`) is safe to interrupt at any
point and safe to re-run without corrupting or double-splitting any of the four canonical
`v1.0-brownfield-backfill` append-log files — the mechanism-A analogue of BC-1.18.011's VP-133,
specialized to a FOUR-INDEPENDENT-FILE atomic unit sharing one txn record instead of BC-INDEX's
single-file ten-subsystem partition. This VP consolidates BC-1.18.013's two same-method
(integration) load-bearing safety obligations, per the verification-delta single-method-per-VP
convention BC-1.18.011's VP-133/VP-124 established.

1. **Four-file all-or-nothing atomicity under crash/interruption.** At every observable point in
   time, either ALL FOUR canonical files (`decision-log.md`, `burst-log.md`, `lessons.md`,
   `session-checkpoints.md`) are in their pre-migration monolithic form, or ALL FOUR are in their
   post-migration split form; it is never observed with two files migrated and two not. A
   simulated crash at any staging/pivot/canonical-move step MUST leave the migration in exactly one
   of these two valid whole-migration states after recovery (BC-1.18.013 §Postcondition 3,
   §Invariant 3, §EC-001, §EC-002). If Postcondition 1 or 2 (delegated per-file
   content-preservation/census, verified by VP-144) fails for ANY ONE of the four files, the
   ENTIRE migration aborts (§Postcondition 4) — none of the four files is touched, not merely the
   failing one; this generalizes BC-1.18.008's single-file hard gate to the four-file unit, exactly
   as BC-1.18.011's VP-133 generalizes it to the ten-subsystem unit. The pre-commit
   source-fingerprint recheck (§Postcondition 3a) is performed EXACTLY ONCE over the concatenated
   bytes of all four files, immediately before the CURRENT-backfill-append-logs.json pointer swap — not once per file.

2. **Two-layer idempotency consistency.** `completed-backfill-append-logs.json`'s presence (the migration's own
   top-level sentinel, checked BEFORE any lock is acquired) and BC-1.18.008's per-file
   `mechanism_a_backfill_already_migrated`/Backfill Recovery Manifest presence (the per-file
   idempotency basis consulted WHILE performing each file's split) never disagree in a way that
   causes either (a) a false `ALREADY_MIGRATED` before all four files are actually split, or (b) a
   re-split of a file whose per-file manifest already exists. On resume-from-STAGING (EC-003), the
   binary MUST re-run BC-1.18.008's own per-file idempotency check for each of the four files
   rather than assuming none have a pre-existing manifest — a file rolled by BC-1.18.006 before
   this migration ever ran (BC-1.18.008 Postcondition 3's Composability clause) is correctly
   tolerated and appended-after, never mis-classified (BC-1.18.013 §Postcondition 5).
   **(v1.1) Terminal-record/txn coherence and the live admission gate.** The top-level sentinel
   is not trusted on presence alone: a crash after the terminal record is durable but before
   the txn record reaches COMPLETED (txn COMMITTING, gate LOCKED, all four files at their
   post-migration hashes) MUST be reconciled — verify the record against the txn and the four
   files' `expected_post_hash`, rewrite the txn to COMPLETED, THEN open the gate — by EITHER the
   next PreToolUse protected-path admission (no binary re-invocation) OR a binary
   re-invocation, with a zero-mutation second run; an unmatchable record is fail-closed
   (`COMPLETION_RECORD_MISMATCH_ABORT`, nothing mutated). The admission gate itself is
   exercised through the REAL dispatcher entry point (a missing call site is invisible to the
   Kani model, VP-146), including the writer-reservation drain (reservation created at
   PreToolUse, removed at PostToolUse or on a same-dispatch block; coordinator waits for
   quiescence before computing `source_sha256`; `DRAIN_TIMEOUT_ABORT` on timeout; TTL-only
   stale reclamation) (BC-1.18.013 §Precondition 6(b)/(c), §Postcondition 5a, §Invariant 6,
   §EC-009..§EC-013). **(v1.5; anchor story S-25.09 from v1.6 — AC-001 anchoring, AC-005 label,
   AC-002 diagnostics) Anchoring, surface and diagnostics.** The same real-binary
   prong asserts that the dispatcher admission and BOTH coordinator binaries resolve ONE factory
   root by the single rule (`CLAUDE_PROJECT_DIR` canonicalized, else the process cwd; no
   `.factory` ⇒ coordinator exit 2 `FACTORY_ROOT_NOT_FOUND`, nothing created): with the process
   cwd ≠ `CLAUDE_PROJECT_DIR`, a reservation created by admission is visible to the coordinator's
   first drain, and `migration-state/` exists only under `<CLAUDE_PROJECT_DIR>/.factory`; that a
   migration-window verdict surfaces as `blocking_plugins=migration-admission` (a shard-cap
   block keeps `shard-cap-gate`); and that every admission verdict/anomaly writes its single
   `migration.admission_*` event to `dispatcher-internal-*.jsonl` (ADR-052 §5a "Admission
   diagnostics channel"), carrying no raw `tool_use_id` or record content (BC-1.18.013
   Postcondition 10 exactly-once semantics; the events' wire-format conformance is VP-079 v1.24).
   **(v1.7; BC-1.18.013 v1.12 / ADR-052 v1.23 third binary-leg extension) Contention, TOCTOU, version
   gate, exit-code classes. Delivered by: S-25.06 AC-036 (e1, e2, e4, and the binary-verifier half of
   e3; AC-031 verifier retires the interim) and S-25.09 AC-008..AC-018 (the Branch B admission half of
   e3 = AC-017, plus the `migrate-bc-index` coordinator twin VP-133 facet 9); S-25.08 delivers none.**
   The same integration prong asserts, against the real
   `backfill-append-logs` binary and the real dispatcher admission: (e1) **contention on every path** —
   with another coordinator holding `flock(exclusive.lock, LOCK_EX|LOCK_NB)`, the binary exits 1
   `MIGRATION_LOCK_CONTENTION` (`AppendLogMigrationError::LockContention`) whatever else is on disk
   (`completed-backfill-append-logs.json` present with no txn, a COMPLETED own txn, the own live
   COMMITTING txn, or a live foreign record; and with the record absent and a live own txn), NEVER exit
   0 / `ALREADY_MIGRATED`, never `FOREIGN_MIGRATION_REFUSED`, reading and writing nothing (sha256
   snapshot of `migration-state/` byte-identical; the terminal record is not even opened), while the
   uncontended control on the same state yields the deterministic Postcondition 5a verdict (EC-053);
   (e2) **terminal record read under the lock** — a record absent at the pre-lock probe but written
   (txn COMPLETED, lock released) by a running coordinator before the late process acquires the lock is
   read UNDER the lock and fed to the recovery decision (not a hard-coded `None`): no fresh run, gate
   and txn untouched, exit 0 `ALREADY_MIGRATED` (EC-054, Postcondition 5a(a2)); (e3) **Branch B / Branch
   C schema_version gate** — a live txn record whose `schema_version` is an integer >= 2 (`2`,
   `4294967296`, also with `generation_id` removed or `activation_id` removed) yields, on the admission
   surface, exactly ONE `E-MAINTENANCE-002 (state_integrity)` and ONE `migration.admission_failed`
   (`cause=state_integrity`, `kind=txn_record_newer_schema`), no `migration.admission_blocked`, no
   reservation left behind, txn bytes and gate unchanged (NOT the discard, NOT a mismatch or missing-key
   report), evaluated before the `generation_id` tri-state (Branch B) and before every Branch C check;
   a present non-integer or out-of-range value (`"1"`, `0`, `1.5`, `null`) is `txn_record_malformed`
   with bytes unchanged; an ABSENT `schema_version` or `1` is unchanged behavior (the Branch B discard

   the minimal hand-built `{"state":"COMMITTING","migration_id":"backfill-append-logs"}` with no

   Precondition 6(c) rule 9); (e4) **exit-code exhaustiveness** — a compile-time-exhaustive table test

### Why integration (fault-injection + double-invocation)

Both facets are real-filesystem/process properties: atomicity-under-interruption requires
injecting a crash at each staging step against a live tempdir and observing post-recovery state;
idempotency-consistency requires double-invocation and resume against a live staged/completed
state. Neither is provable as a pure unit test — this is the same harness class VP-124 uses for
BC-1.18.008's single-file case and VP-133 uses for BC-1.18.011's ten-subsystem case. The
per-file content-preservation/census correctness itself is a DISTINCT-method (proptest) property
proven separately by VP-144, per BC-1.18.013 §Invariant 2's independent-mandatory framing (neither
check substitutes for the other).
