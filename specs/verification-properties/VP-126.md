# VP-126: BC-INDEX changelog: Gate Rotation Reuses rotate_changelog ONLY — No Reimplemented Logic AND Zero Gate-Side prepend_changelog_item Call Sites in shard_manager.rs

## Property Statement

Mechanism B1's rotation is a *caller* of the already-shipped `rotate_changelog` primitive, not a
reimplementation — AND, under BC-1.18.009 v1.1's **CORRECTED single-actor block-and-retry contract**
(F-S2502-F2-001), the gate calls `rotate_changelog` ONLY: it NEVER calls `prepend_changelog_item`.
The prepend is exclusively the responsibility of whichever agent `Edit`/`Write`/`MultiEdit` call
ultimately lands (original or retried). This is the "reuse-don't-reinvent" AND "one-actor-per-write"
guarantee that makes B1 a low-risk, sound extension rather than a double-actor prepend hazard.

1. **Reuse via library call, rotate-only, `keep_recent = low_water_mark` (CORRECTED fix-burst
   pass-3, F-P3-005).** On `changelog:` overflow, `shard_manager.rs`'s B1 handler invokes
   `rotate_changelog` (`crates/last-amended-migrate/src/rotate.rs`) as a library call, and ONLY
   `rotate_changelog` — it trims the live sequence to the CONFIGURED `low_water_mark` items
   (`rotate_changelog(..., keep_recent = low_water_mark, ...)`, where `low_water_mark` is BC-1.18.005
   §Postcondition 8's rotation-target config, default `floor(N/2)`, sourced from config and NEVER a
   hardcoded `N-1` or `keep_recent = N`) and appends the overflow tail, then returns
   `HookResult::Block` (BC-1.18.009 §Postcondition 2 CORRECTED, §Postcondition 1 REWRITTEN). The
   `keep_recent` argument is threaded from the loaded config value — a hardcoded rotation-target
   literal (`keep_recent = N`, or an `N - 1` derivation) is the withdrawn every-write-rotation design
   and MUST be flagged as a defect by this static check.

2. **Zero gate-side `prepend_changelog_item` call sites.** `shard_manager.rs`'s B1 handler contains
   NO call site for `prepend_changelog_item` (`crates/last-amended-migrate/src/changelog.rs`)
   (BC-1.18.009 §Invariant 1 CORRECTED, §Invariant 4, §EC-006). `prepend_changelog_item` remains
   exclusively a function the AGENT's own tool-call composition follows (per ADR-049 §Decision 2) —
   never a function the gate calls on the agent's behalf. A gate-side `prepend_changelog_item` call
   after a successful `rotate_changelog` is the withdrawn v1.0 double-actor design and MUST be flagged
   as a defect (§EC-006), not accepted as a valid implementation choice.

3. **No reimplemented rotation logic; single evergreen archive.** The B1 handler contains NO
   duplicated changelog-rotation logic — it does not re-derive the tail-selection, the
   archive-append accumulation, or item-move logic that `rotate_changelog` already owns
   (BC-1.18.009 §Invariant 1). It APPENDS the overflow tail to the SINGLE evergreen archive
   `.factory/specs/behavioral-contracts/BC-INDEX-changelog-archive.md` via the generalized
   `archive_path`-parameterized call surface — and it MUST NOT contain any per-`seq`
   sealed-shard-DIRECTORY filename derivation (`BC-INDEX-changelog-shards/BC-INDEX-changelog.<seq:04>.md`),
   the WITHDRAWN model `rotate_changelog` structurally cannot produce (BC-1.18.009 §Postcondition 5
   CORRECTED). The `factory-dispatcher` → `last-amended-migrate` dependency edge is present and
   acyclic (ADR-051 §Decision 8).

4. **The `Ok`-arm counter-divergence guard is PRESENT in source (NEW, cluster-4 hardening Obs A;
   BC-1.18.009 §EC-008 / §Invariant Inv-5 / §Postcondition 6 addendum).** The B1 handler's `match`
   on `rotate_changelog_at`'s result MUST discriminate on `report.mutated`: the source MUST contain
   an `Ok(report) if !report.mutated => HookResult::Error` guard arm emitting `E-SHD-014`, ordered
   BEFORE the `Ok(_report) => HookResult::Block` success arm, so a `mutated == false` report can
   never fall through to `Block`. A bare `Ok(_) => Block` success arm with no preceding
   `!report.mutated` guard is a DEFECT — it re-introduces the infinite block+retry self-DoS on
   `BC-INDEX.md` that BC-1.18.009 §Invariant Inv-5 forbids (a falsely-claimed rotation on an
   unchanged source re-fires the trigger every dispatch). This is the SOURCE-STRUCTURAL complement
   of VP-131 point 4, which proves the guard's observable BEHAVIOR (returns `Error(E-SHD-014)`, never
   `Block`, leaves pre-rotation state byte-identical) via unit-test. The pairing mirrors this BC's
   existing VP-125 (observable single-actor block-and-retry OUTCOME, proptest) vs VP-126 (structural
   rotate-only / zero-gate-side-prepend SOURCE guarantee, static-check) split. The error code is
   `E-SHD-014` (error-taxonomy.md's authoritative slot) — NOT the stale hardening-design-doc
   `E-SHD-008` (already allocated as `BackstopProbeFailed` at taxonomy v1.3). A static check cannot
   prove the runtime Error-not-Block behavior (that is VP-131's unit-test); it CAN and MUST prove the
   guard arm is structurally present — the honest static-check facet.

### Why static-check

Both "reuse not reimplement" and "the gate never prepends" are structural, source-level invariants
best enforced by the cheapest mechanism — a CI grep asserting the B1 handler's rotation path resolves
to `rotate_changelog`, contains no duplicated rotation logic, and contains no `prepend_changelog_item`
call site (the same enforcement class as VP-061 agent-prompt-discipline presence and VP-129 config
audit). A behavioral test cannot distinguish "rotated correctly via reuse, single-actor" from
"rotated correctly but with a hidden gate-side prepend" (which would corrupt only under the
Write/MultiEdit stale-payload race BC-1.18.009 §Postcondition 2 describes); the static scan is the
right tool for the non-duplication AND zero-gate-side-prepend guarantees. VP-125 proves the
observable single-actor block-and-retry OUTCOME; this VP proves the SOURCE-level guarantee that makes
that outcome structural.

## Proof Harness Skeleton

```bash
# ci/checks/vp126_bcindex_rotation_reuse_single_actor.sh
# VP-126: BC-1.18.009 PC1(low_water_mark)/PC2(CORRECTED)/INV1(CORRECTED)/INV4/EC-006/EC-008/INV5 — rotate-only, single-actor, keep_recent=low_water_mark, mutated-guard-present

set -euo pipefail
SM=crates/factory-dispatcher/src/shard_manager.rs

# (1) B1 handler must call the shipped rotate primitive.
grep -qE 'rotate_changelog' "$SM" || { echo "FAIL: B1 does not call rotate_changelog"; exit 1; }

# (2) CORRECTED single-actor: B1 handler must have ZERO prepend_changelog_item call sites.
#     (the gate rotates only; the agent's own write is the sole prepend — BC-1.18.009 INV1/EC-006)
if grep -qE 'prepend_changelog_item' "$SM"; then
  echo "FAIL: shard_manager.rs calls prepend_changelog_item — gate-side prepend forbidden (EC-006)"; exit 1
fi

# (2b) CORRECTED (F-P3-005): the rotate call's keep_recent must be the config-sourced low_water_mark,
#      NEVER a hardcoded N / N-1 / numeric literal (the withdrawn every-write-rotation design).
if grep -qE 'keep_recent *= *[nN] *[,)]|keep_recent *= *[A-Za-z_][A-Za-z_]* *- *1|keep_recent *= *[0-9]+ *[,)]' "$SM"; then
  echo "FAIL: rotate_changelog keep_recent is a hardcoded N / N-1 / numeric literal — must be config low_water_mark (F-P3-005)"; exit 1
fi
grep -qE 'keep_recent *= *[A-Za-z_.]*low_water_mark' "$SM" || {
  echo "FAIL: rotate_changelog is not called with keep_recent = low_water_mark (config-sourced)"; exit 1; }

# (3) B1 handler must NOT contain duplicated rotation logic (per-seq sealed-shard-DIRECTORY filename
#     derivation — the WITHDRAWN model — tail-item selection, or archive-append accumulation) — those
#     live only in last-amended-migrate. The archive is the SINGLE evergreen file, appended-to.
if grep -qE 'BC-INDEX-changelog-shards|BC-INDEX-changelog\.[0-9]{4}\.md|fn +rotate_|tail_items' "$SM"; then
  echo "FAIL: shard_manager.rs reimplements rotation or emits the withdrawn per-seq shard layout"; exit 1
fi

# (4) dependency edge present (acyclic per ADR-051 D8).
grep -q 'last-amended-migrate' crates/factory-dispatcher/Cargo.toml || { echo "FAIL: missing dep edge"; exit 1; }

# (5) Obs A (cluster-4 hardening): the rotate_changelog_at result match must discriminate on
#     report.mutated. A preceding `Ok(report) if !report.mutated => Error(E-SHD-014)` guard arm
#     MUST be present, so a mutated=false report can NEVER fall through to the Ok(_) => Block
#     success arm (the infinite block+retry self-DoS BC-1.18.009 Inv-5 forbids). This static check
#     asserts the guard's SOURCE presence; VP-131 proves its Error-not-Block runtime BEHAVIOR.
grep -qE 'Ok\(report\)[[:space:]]+if[[:space:]]+!report\.mutated' "$SM" || {
  echo "FAIL: B1 handler missing the Ok(report) if !report.mutated counter-divergence guard (EC-008/Inv-5)"; exit 1; }
grep -qE 'E-SHD-014' "$SM" || {
  echo "FAIL: B1 handler does not emit E-SHD-014 on the mutated=false arm (EC-008)"; exit 1; }

echo "PASS: VP-126 rotate-only single-actor + counter-divergence-guard invariant holds"
```
