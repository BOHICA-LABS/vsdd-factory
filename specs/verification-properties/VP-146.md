# VP-146: Governed Mechanism-A Migration Crash-Recovery Decision Core — Six Kani Harnesses (B2 obl1_kani_proofs Mirror)

## Property Statement

The pure, zero-I/O crash-recovery decision core of the governed mechanism-A migration
(`backfill-append-logs`) — `decide_append_log_recovery`, the modeled txn-record state machine,
the modeled admission predicate, and the abstract two-namespace (`live`/`durable`) `Fs` crash
model — is proven correct by bounded model checking (Kani/CBMC), not sampled. This VP is the
mechanism-A structural sibling of the B2 (BC-1.18.011) OBL-1 Kani suite
(`obl1_kani_proofs.rs`, ADR-052 §Decision 12): the same seven-property program, retyped onto
mechanism-A's `AppendLogIntentLogRecord` / `AppendLogMigrationTxnState` /
`AppendLogIntentLogRecoveryDecision` domain, with the B2 suite's two state-machine harnesses
(inductive step + bounded sequence) retained as a pair under obligation a3. It discharges, for
BC-1.18.013's four-file unit, the crash-safety guarantee that VP-143's real-filesystem
fault-injection harness exercises empirically — the two are complementary, not redundant (Kani
proves the finite/sequential/pure core exhaustively; fault-injection confirms the real OS
satisfies the abstract `Fs` model's axioms — ADR-052 §Decision 12 "two-pronged verification
split").

Six obligations (a1..a6), realized as SEVEN `#[kani::proof]` functions (a3 carries two: a
single-step inductive harness and a bounded-sequence harness). The CI job
(`kani-mechanism-a`, `--harness proof_obl_a`, `EXPECTED_PROOFS=7`) counts proof functions, not
obligations:

| Obl. | Harness | Property | BC anchor |
|------|---------|----------|-----------|
| a1 | `proof_obl_a1_recover_totality` | `decide_append_log_recovery` over arbitrary bounded `(canonical_hash, staging_hash, record)` inputs always terminates in exactly one of `TreatDone` / `RedoRename` / `FailClosed`; never panics, never `unreachable!()` | §Precondition 5, §INV3, §EC-002 |
| a2 | `proof_obl_a2_recovery_safety_predicate` | every reachable durable outcome resolves old-or-new-committed, never torn/partial; content-verified (hash-keyed, not existence-keyed) so a merely-existing canonical path with foreign/stale content is never mistaken for a completed move | §Precondition 5, §INV3, §PC3, §EC-002 |
| a3 | `proof_obl_a3_transition_inductive_step` + `proof_obl_a3_transition_bounded_sequence` | txn-record state-machine (ADR-052 §Decision 7a; states Staging/Committing/Completed/Aborted) transition totality and inductive-invariant preservation: the transition relation is total, progress rank is monotonic non-decreasing ("no turning back"), terminal states are absorbing; one harness for the single-step inductive case, one for a bounded multi-step sequence | §Precondition 5, §PC3, §PC4, §INV3 |
| a4 | `proof_obl_a4_admission_gate_invariant` | INV-GATE-TXN for mechanism-A: no writer is admitted while the active txn record is in a live state (STAGING/COMMITTING), over a finite nondeterministic scheduler modeling the ADR-052 §Decision 5a drain/reopen lifecycle; the modeled predicate `append_log_admission_open` mirrors the pure core of `executor::append_log_backfill_admission_precheck` verbatim | §Precondition 6(b), §Precondition 6(c) |
| a5 | `proof_obl_a5_pointer_swap_and_move_crash_atomicity` | bounded symbolic crash-trace (nondeterministic crash point across the write/fsync/rename/fsync/pointer-swap/append sequence over the abstract `InMemoryFs` model, FILE_SLOTS slots): `recover()` applied to the post-crash durable state converges to exactly the OLD or NEW generation (never torn); the commit predicate fires on exactly the `pointer_swap` op, never on a canonical-path-move rename; WAL ordering (every INTENT record fsynced before the pointer swap) | §Precondition 5, §PC3, §PC3a, §INV3, §EC-002 |
| a6 | `proof_obl_a6_recovery_idempotence` | `recover()` → apply decision → `recover()` again converges to the same (or next-table-row-deterministic) decision; never a repeated destructive action | §Precondition 5, §INV3, §EC-002, §EC-003 |

**Defensible claim form (the property statement VP-146 asserts, verbatim from the harness
module doc):** *under abstract filesystem model M, every modeled op/crash sequence of length <= N
keeps the four-file CURRENT.json pointer old-or-new (never torn), and content-verified per-move
recovery never mistakes a merely-existing canonical path for a completed move.*

**Scope boundary (what this VP does NOT claim).** Kani has no semantics for `rename(2)`,
`F_FULLFSYNC`, the page cache, torn sectors, or power loss. VP-146 proves properties of the pure
decision logic and of an explicit abstract filesystem model; the real-OS refinement of that
model's axioms (two-namespace live/durable; atomic rename) is VP-143's empirical fault-injection
obligation, not VP-146's. Per-file content-preservation/census correctness is VP-144's.
Closed-grammar rejection is VP-145's. VP-143 + VP-146 together form the four-file crash-safety
verification set exactly as B2's fault-injection suite + `obl1_kani_proofs` do under ADR-052
§Decision 12.

## Proof Method

| Leg | Method | Tool | Coverage | Status |
|-----|--------|------|----------|--------|
| a1 recovery totality | kani-proof | `cargo kani` (`#[kani::proof]`, `#[kani::unwind(4)]`) | exhaustive over `{absent, P, R, F}` hash trichotomy for canonical/staging hashes × record pre-state shapes | implemented (harness present) |
| a2 recovery safety predicate | kani-proof | `cargo kani` (`#[kani::unwind(4)]`) | exhaustive, same domain | implemented |
| a3 txn state-machine (step + sequence) | kani-proof | `cargo kani` (step: no unwind; sequence: `#[kani::unwind(7)]`) | all single transitions; all sequences of length <= bound | implemented |
| a4 admission-gate invariant | kani-proof | `cargo kani` (`#[kani::unwind(7)]`) | modeled gate/txn state product over bounded op sequences | implemented |
| a5 pointer-swap + move crash atomicity | kani-proof | `cargo kani` (`#[kani::unwind(12)]`) | symbolic bounded crash trace over `InMemoryFs` (FILE_SLOTS file slots) incl. foreign/stale canonical content | implemented |
| a6 recovery idempotence | kani-proof | `cargo kani` (`#[kani::unwind(4)]`) | exhaustive decision-table double application | implemented |

All harnesses are `#[cfg(kani)]`-gated (`cfg(kani)` is allowlisted in the workspace
`[workspace.lints.rust.unexpected_cfgs]` block), so a normal `cargo build`/`test`/`clippy` never
compiles them; they run only under `cargo kani` in the `kani` CI job (`.github/workflows/kani.yml`,
whose `kani-mechanism-a` job runs `cargo kani -p factory-dispatcher --harness proof_obl_a` with
an `EXPECTED_PROOFS=7` anti-silent-partial-verification guard, alongside the B2 `proof_obl1`
job). Inputs follow the crate's String-field convention (empty path/id fields; single-character
hash constants `"P"`/`"R"`/`"F"`), which is sound and complete for `decide_append_log_recovery`
because its only comparisons are `canonical_hash`/`staging_hash` against
`expected_post_hash`/`expected_pre_state`.

### Why kani-proof (and why a separate VP from VP-143)

Recovery totality, safety, and idempotence are universally-quantified properties over a finite
decision domain — exactly Kani's strength — and a crash-trace over every interleaving of a
bounded op sequence is not enumerable by a hand-written fault-injection suite. VP-143 remains
the single-method (integration) real-filesystem VP; folding a kani-proof leg into it would
violate the single-method-per-VP convention that VP-133/VP-124 and BC-1.18.013's own §VP Anchors
establish. A distinct VP also gives the Kani suite its own lifecycle (`verification_lock`,
`proof_completed_date`, `proof_file_hash`) at F6 formal hardening.
