# VP-133: B2 BC-INDEX Body Split — Independent-Census Integrity, Crash-Atomicity, Fail-Loud Rollback (E-SHD-005), Idempotency, and SS-05/SS-06 Second-Level Sub-Split Census

## Property Statement

The governed one-time B2 migration is census-honest, safe to interrupt, safe to re-run, and fails
loud without leaving a partial state — BC-1.18.008 §Postcondition 5/6 + §Invariant 3's exact analogue
(VP-124), specialized to `BC-INDEX.md`'s ID-keyed census partition. This VP consolidates the
same-method (integration) load-bearing safety obligations of BC-1.18.011 — facets 1-5 (census,
atomicity, fail-loud rollback, idempotency, sub-split) and, from v1.1, facets 6-8 (production-path
reconciliation wiring; reserve-then-verify admission/release-on-block/TTL; verified finalize,
mismatch fail-closed, migration discriminator and per-migration namespace) — per the
verification-delta single-method-per-VP convention (the same consolidation VP-124 applies for
BC-1.18.008 and VP-143 applies for BC-1.18.013's equivalent facets). Facets 6-8 are the B2
conformance obligations (defects B2-1..B2-4 of the merged B2 code against ADR-052 v1.18) and are
deliberately black-box through the real dispatcher / real binary: a model cannot see an uncalled
function (B2-1) or a wrong constant in the production entry point (B2-3).

1. **Independent-census integrity — every BC-ID in EXACTLY one shard.** After the split, every
   `BC-X.YY.NNN` ID present in the pre-split census (a fresh enumeration of the original body's
   rows, cross-checked against `BC-INDEX.md`'s `total_bcs` frontmatter as an independent
   count-oracle) appears in EXACTLY ONE resulting shard/sub-shard file — never zero, never two; the
   union of all shard files' row counts equals the pre-split census count exactly; and
   `BC-INDEX.md`'s post-split body contains ZERO per-BC rows (BC-1.18.011 §Postcondition 2, §EC-001
   duplicated-row negative control). The census is independently mandatory alongside VP-132's
   content-preservation: a byte-identical concatenation that nonetheless duplicates one row and drops
   another (a compensating error) STILL fails this census (BC-1.18.011 §Invariant 2).

2. **Crash-atomicity — staging + verify + atomic commit, all-or-nothing.** All shard files and the
   shard-manifest TOML are written to an immutable staging generation first; the commit is the
   single atomic `CURRENT.json` pointer swap (ADR-052 §Decision 7c; BC-1.18.006 atomic-write
   primitives reused for each staged file) ONLY after both
   content-preservation (VP-132) and the census verify clean. A simulated crash at any staging step
   leaves `BC-INDEX.md`'s body in exactly one of two valid states — fully original or fully split —
   never a partial/corrupt intermediate (BC-1.18.011 §Postcondition 3, §Invariant 3, §EC-002).

3. **Fail-loud rollback (E-SHD-005).** If EITHER content-preservation OR the census fails, the
   migration ABORTS: `BC-INDEX.md`'s original monolithic body is left completely untouched, no
   partial shard set is treated as authoritative, no partial `§Subsystem Shard Manifest` is
   published, and a loud `HookResult::Error` / migration-abort surfaces (taxonomy `E-SHD-005`,
   naming the mismatch — e.g., the duplicated BC-ID) (BC-1.18.011 §Postcondition 4, §EC-001,
   §EC-003-error, §EC-004). This is VP-124's fail-loud preservation-gate (E-SHD-003) analogue for
   B2's census gate.

4. **Idempotency.** Running the migration twice against an already-split `BC-INDEX.md`, or resuming
   from a verified-complete staged state, does not re-split, re-duplicate, or corrupt any shard: the
   operation either resumes from the last verified-complete checkpoint or detects the already-split
   end-state (zero per-BC rows in the body) and exits as a no-op (BC-1.18.011 §Postcondition 5,
   §EC-003 resume-from-checkpoint, §EC-006 completed-run no-op). **(v1.1 meaning change — B2-2)**
   The `completed.json` no-op is the ONLY no-op on a clean steady state (gate OPEN, no live txn: ZERO
   filesystem mutation). When `completed.json` is present beside a LIVE txn the "already done" path
   is NOT an unverified short-circuit: it is the verified own-migration finalize of facet 8 (the
   merged code's behavior of rewriting ANY non-COMPLETED txn to COMPLETED on `completed.json`
   presence is the defect this facet now rejects).

5. **SS-05/SS-06 second-level sub-split census.** The census/atomicity/rollback/idempotency
   obligations hold IDENTICALLY at the sub-shard level for SS-05 and SS-06: every `BC-5.*` row lands
   in exactly one of `shards/BC-INDEX-SS-05.a.md`/`.b.md`/… with the SS-05-scoped total matching an
   independent pre-split count of `BC-5.*` rows (likewise SS-06), all within the SAME one-time
   operation; a sub-shard-level census failure aborts the ENTIRE operation, not just the affected
   subsystem (BC-1.18.011 §Postcondition 6, §EC-004).

6. **(v1.1; B2-1) Production-path wiring of the PreToolUse stale-gate reconciliation.** A real
   spawned `factory-dispatcher` PreToolUse payload (`Edit`/`Write`/`MultiEdit`) under
   `.factory/specs/behavioral-contracts/` or `.factory/cycles/`, with the gate stuck `LOCKED`/
   `DRAINING` and (a) no active txn → Branch A (gate → OPEN, then admitted); (b) txn STAGING with
   `generation_id = null` → Branch B (txn → ABORTED `null_generation`, gate → OPEN, admitted);
   (c) `exclusive.lock` held by a live coordinator → no action, `E-MAINTENANCE-001`. A
   `reconcile_stale_admission_gate` that exists and is unit-tested but is never called from the
   production path FAILS this facet (BC-1.18.011 §Precondition 6(d), §EC-010). The shared core is
   evaluated EXACTLY once per event, ahead of `shard_cap_precheck` (BC-1.18.013 §Precondition 6(b)).

7. **(v1.1; B2-3, B2-4) Reserve-then-verify admission, release-on-block, TTL.** (a) For every
   protected-path `Edit`/`Write`/`MultiEdit`, `reservations/<tool_use_id>.reservation` is created
   BEFORE the gate/txn are read; on failed verification (gate ≠ OPEN or live txn) the admitter
   removes its OWN reservation; no admitter lock is taken; at every ordering of {W1 create, C1
   DRAINING flip, C2 read reservations, W2 read gate} the "both miss" outcome never occurs
   (scripted interleaving; an admitter that read `OPEN` from the pre-`rename` gate-file inode is
   still observed by the coordinator) (BC-1.18.011 §Precondition 6(c), §EC-007). (b) A reservation
   created at admission is removed by the dispatcher when a LATER stage of the same dispatch
   (`shard_cap_precheck`, registry plugin) blocks or errors (§EC-008). (c) Production
   `DEFAULT_MAX_RESERVATION_TTL` is 3,600 s (not the merged 120 s), the production entry point
   rejects any value below the 1,800 s floor, staleness is judged by `created_at` with mtime only
   as the absent/unparseable fallback, and no PID-liveness inference exists anywhere (§EC-009).

8. **(v1.1; B2-2) Verified own-migration finalize; mismatch fails closed; migration discriminator
   and per-migration namespace.** (a) `completed.json` valid + live txn COMMITTING (matching
   `activation_id`/`generation_id`, `migration_id` = `migrate-bc-index` or absent) + all canonical
   hashes at `expected_post_hash` ⇒ txn → COMPLETED THEN gate → OPEN, both via the next PreToolUse
   (Branch C, no binary re-invocation) and via a binary re-invocation (exit 0 `ALREADY_MIGRATED`);
   second run zero-mutation; crash between the two writes repaired by Branch A (§Postcondition 9,
   §EC-011). (b) ANY verification failure (unparseable; `txn_id`/`generation_id` mismatch;
   `canonical_paths_count` ≠ N; any hash ≠ `expected_post_hash`; txn STAGING — always fail-closed,
   no verification attempted; COMMITTING with a different `activation_id`) ⇒ NO txn write, NO gate
   write, `.factory/migration-state/` byte-for-byte unchanged, binary exit 2
   `COMPLETION_RECORD_MISMATCH_ABORT`, PreToolUse `E-MAINTENANCE-001` with the reason logged
   (§EC-012). (c) A live txn of `backfill-append-logs` is NEVER finalized on the strength of B2's
   `completed.json`: cross-migration refusal (exit 2 `LockContention`-class, no `recover()`; PreToolUse
   plain `E-MAINTENANCE-001`), and a txn record lacking `migration_id` is read as `migrate-bc-index`
   (§Precondition 6(e), §EC-013). (d) Per-migration namespace: with only
   `completed-backfill-append-logs.json`/`CURRENT-backfill-append-logs.json` present,
   `migrate-bc-index` is NOT `ALREADY_MIGRATED` and `detect_migration_read_state` does NOT report
   the BC-INDEX migration complete; B2 is the only writer of `completed.json`/`CURRENT.json`
   (§EC-014).

**Claim boundary (v1.1).** Facets 6-8 are empirical/black-box on the real substrate: they prove the
production wiring, constants and observable behavior of the binary actually built. The
gate/txn/reservation/lock STATE-MACHINE safety argument for B2 (INV-GATE-TXN,
quiescence-before-snapshot, no admission while live, no self-heal under a live lock, bounded
progress) is a Kani obligation carried by **VP-147** (B2's `obl1_kani_proofs` suite, ADR-052
§Decision 12) and mirrored for mechanism-A by VP-146 a4; ADR-052 v1.18 §Verification Strategy
item (1) re-opens it for B2 (re-run against the shared core with the reserve-then-verify
ordering; INV-GATE-TXN UNSAT-for-violation and non-vacuity re-confirmed). This VP does NOT claim
that model proof, and the Kani suite does NOT claim facets 6-8.

### Why integration (fault-injection + full-corpus census)

Census integrity is a full-corpus cross-reference property (every BC-ID across all shard files vs a
fresh enumeration vs `total_bcs`); crash-atomicity is a property of real filesystem interaction under
interruption; idempotency requires double-invocation against a live staged state. All are real-
substrate/process properties requiring a harness that runs the actual migration against a live
tempdir and injects failures/re-runs — the same harness class VP-124 uses for the mechanism-A
backfill and VP-128 uses for multi-file corpus integrity — not a pure unit test. The byte-for-byte
content-preservation half is a DISTINCT-method (proptest) property proven separately by VP-132, per
BC-1.18.011 §Invariant 2's independent-mandatory requirement.
