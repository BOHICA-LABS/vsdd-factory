# VP-121: Retention Accounting Is Honest O(Active-Shards) — Bounded Active Count and No Shard-Index Entry Ever Lost

## Property Statement

Over an arbitrary sequence of seals and retention-driven archival moves against a simulated
artifact:

1. **Bounded active count.** After every seal, the number of NON-archived `[[shard]]` entries for
   the artifact is `<= retention_count` (BC-1.18.007 §Postcondition 2/§Postcondition 4). This is
   the honest `O(active shards)` bound ADR-047 §8b requires: the default whole-corpus scope never
   grows without bound. The property holds for `retention_count` lowered mid-flight (multiple
   archival moves in one invocation — §EC-002).

2. **No data loss.** Every `[[shard]]` entry ever created remains present in the shard-index (active
   or archived) — archival updates an entry's path (or sets `archived: true`) but never removes it
   (BC-1.18.007 §Postcondition 3, §Invariant 1, §Invariant 3). The lifetime shard-count derived from
   the index is monotonically non-decreasing across the whole sequence.

3. **Crash-reconciliation / exactly-once presence (BC-1.18.007 v1.3 §Postcondition 7, §Invariant 4,
   §EC-007..EC-011).** Let an archival pass move N >= 1 shards (oldest-first) and let a fault
   (crash, or a failed/refused move including cross-device rename failure and destination-exists)
   be injected at any of the N+3 points between BC-1.18.006 step (b) and the single index
   publish, with an arbitrary subset of destinations pre-existing under
   `archive/<artifact-stem>/`. Then for every indexed non-archived `[[shard]]` entry, with R the
   root file and A the archive file:
   (a) *Ordering/atomicity:* the published index never records the new seal without the archived
   paths of the shards moved in the same invocation (or the reverse); a failed or refused move
   applies NO index publish and returns `HookResult::Error` (`E-SHD-002`; never `Block`), and a
   pre-existing destination is never replaced (A bytes before == after).
   (b) *Exactly-once presence:* after every filesystem step, and after the next invocation's
   reconciliation, the content of every indexed sealed shard exists in exactly one of R and A,
   except the fail-loud duplicate/missing states below; no sealed-shard byte is ever read-modified,
   copied or deleted (SHA-256 of each sealed shard is unchanged).
   (c) *Roll-forward classification (total, deterministic function of (R, A)):*
   (R present, A absent) -> no action; (R absent, A present) -> repair the entry `path` to
   `archive/<artifact-stem>/<filename>` in ONE atomic index write; (R present, A present) ->
   fail loud `E-SHD-002` form (d) `archive_duplicate`, nothing moved/deleted/overwritten, index
   unchanged; (R absent, A absent) -> fail loud `archive_missing`, nothing fabricated.
   (d) *Idempotence:* a second reconciliation over the repaired index performs no write
   (byte-identical index and tree); the lifetime `[[shard]]` count is unchanged by reconciliation
   (composes with property 2); a crash between the canonical truncate and the publish composes
   with the `E-SHD-007` unindexed-seal heal (EC-011) and the owed archival completes on the next
   invocation with no loss or duplication.

`retention_count` is a config value (default 10); the properties hold for any configured value, so
they are not F4-provisional.

### Why proptest (and why not Kani for the crash leg)

Property 3 is a property of a filesystem effect sequence (rename, truncate, atomic publish) under
fault injection; it lives in the effectful shell and cannot be model-checked. The roll-forward
classification table (property 3(c)) is, however, a pure total function of (recorded-path kind,
R present, A present) over a four-row finite domain: a Kani harness over that extracted pure
classifier (exhaustive over the 2x2 presence domain, asserting totality, determinism and that the
repair action is idempotent) is FEASIBLE, but it is not adopted as a separate counted leg: the
proptest crash-point x move-count x pre-existing-destination matrix already exercises every table
row and the idempotence clause end to end, which a classifier-only proof cannot. The classifier is
required to be a pure function in the implementation (purity boundary) so a Kani harness can be
added without redesign. VP-121 therefore remains `proptest` primary; per-tool counts are unchanged.


Both are universal invariants over arbitrary seal/archival sequences with a variable
`retention_count` — a generated-sequence property test covers the interleavings (including the
lower-mid-flight case) that a fixed fixture would miss.

## Proof Harness Skeleton

Harness locations: `crates/factory-dispatcher/tests/proptest_retention.rs` (properties 1, 2 and the
property-3 proptest), `crates/factory-dispatcher/tests/shard_archive_crash_reconcile.rs` (property-3
deterministic fault-injection integration cases, one per crash point). Owning story: S-25.02, task
T-5 (per-seal wiring obligation; BC-1.18.007 PC2/PC7, EC-005, EC-007..EC-011).

```rust
// crates/factory-dispatcher/tests/proptest_retention.rs
// VP-121: BC-1.18.007 PC2/PC3/PC4/PC7/INV1-4/EC-002/EC-007..EC-011

proptest! {
    #[test]
    fn prop_active_count_never_exceeds_retention((seals, ret) in arb_seal_sequence_and_retention()) {
        let mut art = SimArtifact::with_retention(ret);
        for s in seals {
            art.seal(s);
            prop_assert!(art.active_shard_count() <= art.retention_count());
        }
    }

    // Property 3 (BC-1.18.007 v1.3 PC7/INV4/EC-007..EC-011).
    #[test]
    fn prop_crash_reconciliation_exactly_once(
        n_moves in 1usize..=6,
        crash_at in 0usize..9,            // clamped to the N+3 injection points
        preexisting in proptest::collection::vec(any::<bool>(), 6),
    ) {
        let mut art = SimArtifact::with_overflow(n_moves);
        let sealed_hashes = art.sha256_of_all_sealed();
        art.seed_archive_destinations(&preexisting[..n_moves]);
        let before_count = art.index().shards.len();
        let _ = art.seal_with_fault(FailAfter(crash_at));   // Err => no publish on failed move
        art.reconcile();                                    // next invocation, pre-trigger
        for sh in art.index().shards.iter().filter(|s| !s.archived()) {
            let (r, a) = (art.root_has(sh), art.archive_has(sh));
            prop_assert!(r ^ a || art.last_error_is_fail_loud(sh)); // exactly once, or loud
            prop_assert!(art.index_path_matches_location(sh) || r && a);
        }
        prop_assert_eq!(art.sha256_of_all_sealed(), sealed_hashes); // bytes unchanged
        prop_assert!(art.index().shards.len() >= before_count);     // no loss (prop 2)
        let (idx, tree) = (art.index_bytes(), art.tree_snapshot());
        art.reconcile();                                    // idempotent
        prop_assert_eq!((art.index_bytes(), art.tree_snapshot()), (idx, tree));
    }

    #[test]
    fn prop_lifetime_shard_count_monotonic(seals in arb_seal_sequence()) {
        let mut art = SimArtifact::with_retention(10);
        let mut prev = 0;
        for s in seals {
            art.seal(s);
            let now = art.index().shards.len();
            prop_assert!(now >= prev);            // no entry ever removed
            prev = now;
        }
    }
}
```
