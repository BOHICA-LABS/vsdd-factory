# VP-124: Backfill-Split Is Atomic Under Interruption and Idempotent Against an Already-Sharded Artifact

## Property Statement

The one-time backfill-split is safe to interrupt and safe to re-run.

1. **Atomicity under interruption.** A simulated crash at any point during the split leaves the
   system in one of exactly two valid states: the original monolithic file fully intact (staging
   incomplete, partial output discarded on the next attempt) or the split fully complete — never a
   partial/corrupt intermediate (BC-1.18.008 §Postcondition 5, §EC-003). The original file is not
   touched until all shards + the shard-index are staged AND content-preservation is verified
   (VP-123), at which point a temp-file-then-rename atomically retires the original's role.

2. **Fail-loud preservation gate.** If content-preservation verification (byte-count or record-count
   mismatch) fails, the backfill aborts, the original file is left untouched, and a loud error
   (taxonomy `E-SHD-003`) surfaces to the operator — never partial-and-silent (BC-1.18.008
   §Postcondition 6, §EC-004).

3. **Idempotency.** Running the backfill-split twice against an already-sharded artifact (a valid
   pre-existing shard-index) produces no duplicate or additional shards: the operation either
   resumes from the last verified-complete shard or detects the already-sharded state and skips
   (BC-1.18.008 §Invariant 3).

4. **Archival crash-safety composition and no-replace carve-out (BC-1.18.008 v1.11 §Postcondition 4
   "Crash-safety composition", §EC-016; composes BC-1.18.007 v1.3 §Postcondition 7).** For a
   backfill whose archival pass is killed at any point before the single index publish, with an
   arbitrary mix of pre-existing indexed (root-recorded) entries and backfill-produced not-yet-indexed
   seqs among the moved set:
   (i) *Moves obey 7(a)/(b):* every backfill archival move is a rename-only, no-copy-fallback move
   executed before the one index publish; a failed move surfaces as `MechanismABackfillError::Io`
   wrapping `E-SHD-002` and publishes nothing.
   (ii) *Reconciliation first:* on every re-run, BC-1.18.007 §PC7(c) reconciliation executes BEFORE
   `mechanism_a_backfill_already_migrated`, `heal_or_confirm_already_migrated` and partitioning, so a
   pre-existing indexed entry whose root file is absent and archived file present is repaired (one
   idempotent index write, bytes untouched) before `existing_max_seq` is read.
   (iii) *Carve-out is exactly this narrow:* a stale archived copy may be replaced if and only if its
   seq is in no published index entry AND no Backfill Recovery Manifest is published AND its
   `(length, SHA-256)` equals the regenerated shard's. Any other existing destination (bytes differ;
   or Manifest published / seq indexed) is never replaced: the differing-bytes case fails loud
   (`E-SHD-002` form (d) `archive_destination_exists`, both files untouched, no publish); the
   Manifest-published case performs no replacement and no archival re-move, 7(c) finds nothing to
   repair, and `heal_or_confirm_already_migrated` completes the truncation.
   (iv) *Outcome:* no shard lost or duplicated; the final index lists every shard exactly once, active
   count `<= retention_count`, file count == `[[shard]]` count plus the current file; sealed bytes of
   pre-existing shards unchanged; a second re-run writes nothing.

### Why integration (fault-injection)

Crash-atomicity is a property of real filesystem interaction under interruption — it requires a
harness that runs the actual split against a live tempdir and injects failures at each write step
(the same harness class VP-118 uses for the on-disk roll), not a pure unit test of a helper.

## Proof Harness Skeleton

```rust
// crates/factory-dispatcher/tests/backfill_atomicity_test.rs
// VP-124: BC-1.18.008 PC5/PC6/INV3/EC-003/EC-004

#[test]
fn test_BC_1_18_008_EC003_crash_at_each_step_leaves_valid_state() {
    for step in 0..expected_write_steps("decision-log.md") {
        let cx = BackfillHarness::with_fixture("decision-log.md");
        cx.inject_crash_after_step(step);
        let recovered = cx.run_then_restart();
        assert!(recovered.original_intact() || recovered.split_complete()); // never partial
    }
}

#[test]
fn test_BC_1_18_008_PC6_preservation_mismatch_aborts_fail_loud() {
    let cx = BackfillHarness::with_injected_record_mismatch();
    let r = cx.run();
    assert!(matches!(r, HookResult::Error { .. }));   // E-SHD-003
    assert!(cx.original_untouched());
}

// Facet 4: BC-1.18.008 v1.11 PC4 crash-safety composition / EC-016 (harness:
// crates/factory-dispatcher/tests/backfill_archival_crash_test.rs)
#[test]
fn test_BC_1_18_008_EC016_identical_stale_archive_copy_is_replaced() {
    let cx = BackfillHarness::with_indexed_rolls(3).backfill_produces(19).retention(10);
    cx.kill_after_archival_rename(/* seq1 pre-existing, seq4 backfill */ 2);
    let r = cx.rerun();
    assert!(cx.reconcile_ran_before_already_migrated_check());   // PC7(c) first
    assert_eq!(cx.index_seqs(), (1..=22).collect::<Vec<_>>());   // each once
    assert!(cx.active_count() <= 10 && cx.sealed_bytes_unchanged());
}
#[test]
fn test_BC_1_18_008_EC016_differing_stale_copy_fails_loud_untouched() {
    let cx = BackfillHarness::ec016_state().with_divergent_stale_copy(4);
    assert!(matches!(cx.rerun(), HookResult::Error { .. }));     // archive_destination_exists
    assert!(cx.both_files_untouched() && !cx.index_published());
}
#[test]
fn test_BC_1_18_008_EC016_manifest_published_is_not_a_stale_leftover() {
    let cx = BackfillHarness::ec016_state().manifest_published();
    cx.rerun();
    assert!(!cx.any_archive_file_replaced() && cx.canonical_truncation_completed());
}

#[test]
fn test_BC_1_18_008_INV3_second_run_adds_zero_shards() {
    let cx = BackfillHarness::already_sharded("decision-log");
    let before = cx.shard_count();
    cx.run();
    assert_eq!(cx.shard_count(), before);             // idempotent
}
```
