# VP-144: Per-File Delegation-Correctness Invariant Against BC-1.18.008

## Property Statement

For each of the four canonical `v1.0-brownfield-backfill` files independently, the governed
mechanism-A migration's content-preservation and independent-census verification outcomes are
BYTE-IDENTICAL to the outcome of invoking BC-1.18.008's own Postcondition 6(a) (content-preservation)
and Postcondition 6(b) (record-integrity) checks DIRECTLY against that file in isolation. No
divergent or duplicated verification logic exists between the governed-migration wrapper and the
per-file algorithm it invokes (BC-1.18.013 §Invariant 1 — this BC's per-file split logic invokes
BC-1.18.008's `run_mechanism_a_backfill_split`, never a reimplementation).

This is a differential-correctness property, distinct in kind from BC-1.18.011's VP-132 (which
recomputes a fresh structured SHA-256 against a `source_body_row_sha256` oracle, because BC-INDEX's
ID-keyed census gives it a cross-file oracle to check against). Mechanism A has no such cross-file
oracle: each of the four files' own record set is closed and self-contained (BC-1.18.013
§Postcondition 2), so there is nothing to "recompute independently" beyond what BC-1.18.008 already
computes. The genuinely load-bearing property here is therefore DELEGATION FIDELITY — that the
governed migration calls the SAME function, on the SAME input, and gets the SAME PASS/FAIL
determination and the SAME failure detail as calling `run_mechanism_a_backfill_split` directly —
not a second, independently-derived verification path that could silently diverge from the first
(a divergence risk this property exists specifically to close).

1. **PASS/FAIL agreement.** For any of the four canonical files, in any content state (well-formed,
   record-boundary-degenerate per BC-1.18.008 EC-007, oversized-record per BC-1.18.008 EC-002/EC-006,
   or corrupted), invoking that file through BC-1.18.013's governed-migration wrapper yields the
   IDENTICAL Postcondition 6(a)/6(b) PASS/FAIL determination as invoking
   `run_mechanism_a_backfill_split` directly against the same file in isolation.
2. **Failure-detail agreement.** When the determination is FAIL, the failure detail (which record,
   which byte offset, which mismatch class — `CONTENT_PRESERVATION_ABORT` vs. `CENSUS_MISMATCH_ABORT`)
   surfaced by the governed-migration wrapper is IDENTICAL to the failure detail
   `run_mechanism_a_backfill_split` itself produces, not a re-derived or re-worded summary.
3. **No additional gate.** The governed-migration wrapper introduces NO additional per-file
   content-preservation or census gate beyond what BC-1.18.008 already performs — Postconditions 1
   and 2 exist ONLY to state that this BC's obligation IS BC-1.18.008's existing obligation,
   discharged per file, not a new one (BC-1.18.013 §Postcondition 1/§Postcondition 2 preamble).

## Source Contract

- **BC:** BC-1.18.013 §Postcondition 1 / §Postcondition 2 / §Invariant 1.
- **Cross-BC:** BC-1.18.008 §Postcondition 6(a) (byte-for-byte record-boundary-safe partition
  check) / §Postcondition 6(b) (record-integrity check) — the checks this VP asserts are invoked
  unmodified, never reimplemented.
- **Precedent:** VP-132 (BC-1.18.011's B2 content-preservation proptest — a DIFFERENT proof shape,
  since B2 has a cross-file `source_body_row_sha256` oracle mechanism A lacks); VP-123
  (BC-1.18.008's own content-preservation/record-integrity proptest — the function under test THIS
  VP delegates to and differentially compares against).

## Proof Method

| Leg | Method | Tool | Coverage | Status |
|-----|--------|------|----------|--------|
| PASS/FAIL and failure-detail agreement | proptest | differential test: for each of the four canonical files, run BOTH (a) the governed-migration wrapper's per-file verification and (b) a direct `run_mechanism_a_backfill_split` invocation against the same fixture; assert identical PASS/FAIL and, on FAIL, identical failure-detail structure | arbitrary well-formed / record-boundary-degenerate / oversized-record / corrupted fixtures generated by VP-123's existing proptest strategies, replayed against both invocation paths | feasible-pending-harness (F4 code) |

### Why proptest (differential test)

Delegation fidelity is a property over an unbounded space of file-content fixtures (arbitrary
record sequences, boundary placements, and corruption patterns) — the same space VP-123's proptest
strategy already generates for BC-1.18.008. Reusing that generator and running it through BOTH
invocation paths (wrapper vs. direct) in a single differential-test harness is strictly cheaper and
strictly more thorough than a hand-picked unit-test fixture table, and it is the correct tool for
"these two code paths must never diverge" — a class of property proptest's shrinking behavior is
specifically good at localizing when a regression is introduced in either path.

## Proof Harness Skeleton

```rust
// crates/factory-dispatcher/tests/proptest_backfill_append_logs_delegation.rs
// VP-144: BC-1.18.013 PC1/PC2/INV1 — differential agreement vs. BC-1.18.008 PC6(a)/(b)

use proptest::prelude::*;

proptest! {
    #[test]
    fn vp144_governed_migration_agrees_with_direct_bc_1_18_008_invocation(
        fixture in arbitrary_cycle_log_fixture() // reuses VP-123's existing strategy
    ) {
        for target_file in fixture.four_canonical_files() {
            let via_wrapper = backfill_append_logs_migration::verify_per_file(&target_file);
            let via_direct = shard_manager::run_mechanism_a_backfill_split(&target_file)
                .verification_outcome();

            prop_assert_eq!(via_wrapper.pass_fail(), via_direct.pass_fail());
            if let (Outcome::Fail(a), Outcome::Fail(b)) = (&via_wrapper, &via_direct) {
                prop_assert_eq!(a.failure_class(), b.failure_class());   // CONTENT_PRESERVATION_ABORT vs CENSUS_MISMATCH_ABORT
                prop_assert_eq!(a.failure_detail(), b.failure_detail()); // same record/offset/mismatch detail
            }
        }
    }
}
```
