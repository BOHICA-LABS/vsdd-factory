## Error Categories

| Category Code | Category | Description |
|--------------|----------|-------------|
| REG | Registry errors | Hook registry load/validation failures. Three coded fail-closed (exit 2) invariant violations: schema version mismatch, async+block conflict, duplicate hook entry. Uncoded fail-open (exit 0) operational failures: registry file not found / unreadable, TOML parse failure, invalid tool regex (BC-1.08.001 Invariant 1) |
| PAY | Payload errors | Malformed or incomplete tool-call payloads reaching the dispatcher |
| CAP | Capability denial | Host-function calls denied by the plugin's declared capability set |
| PLG | Plugin execution | Timeout, crash, or resource-exhaustion outcomes during WASM plugin execution |
| SNK | Sink errors | Event-sink (JSONL/OTLP) write or routing failures |
| ACT | Activation errors | Platform/binary/hooks.json activation failures |
| HK | Hook gate blocks | PreToolUse gate blocks (secrets, destructive commands, branch protection) |
| SHD | Shard management errors | Layer-2 artifact-sharding failures (rotation, backfill, migration) — native dispatcher `HookResult::Error` outcomes, not process exit codes |
| MIG | Migration binary exit codes | Process exit codes emitted by the governed one-time shard migration binary (`factory-dispatcher migrate-bc-index`, `backfill-append-logs`) invoked via one-time interactive Bash approval (ADR-052 §Decision 1). NOT HookResult outcomes — these are process exit codes returned to the Bash tool caller. Exit 2 = error abort (unexpected termination due to integrity, capacity, or timing failures; re-activation required after investigating root cause); exit 1 = expected non-error termination (activation window elapsed; no canonical paths changed; re-activation accepted without error investigation); exit 0 = non-error sentinel (idempotent). |
| MAINTENANCE | Migration window guards | BC-INDEX path writes blocked during an active one-time migration window by dual independent mechanisms: (1) the txn record at `.factory/migration-state/txn-*.json` in state STAGING or COMMITTING — the native admission gate in `executor.rs` (ADR-052 §Decision 5a) blocks ALL mutation tool calls (Edit, Write, MultiEdit, Bash) when this state exists, regardless of PID liveness, firing before any registry plugin; (2) the OPEN/DRAINING gate state (ADR-052 §Decision 5a) prevents new writer reservations when the migration coordinator has declared maintenance intent (gate state = DRAINING or LOCKED); a writer reservation created at PreToolUse admission is released on `PostToolUse` / `PostToolUseFailure` for the same `tool_use_id` (ADR-052 §Decision 5a v1.20). `E-MAINTENANCE-001` is the deliberate exit-2 block; `E-MAINTENANCE-002` is the `HookResult::Error` fail-closed outcome when the writer-admission check itself cannot be completed (`invalid_tool_use_id`, `io`, `state_integrity`). The `validate-factory-path-staging` guard (ADR-052 §Decision 5c, Bash path) is a secondary classifier layer that enforces the full-command classifier and four-branch guard logic. Per BC-1.18.011 Precondition 6 (ADR-052 §Decision 5a/7a). |

**Exit-code classes (v1.40; ADR-052 §Error Code Semantics item 7(e), as amended; supersedes the earlier "exit 1 = re-activation" definition).** Within the migration subcommands (`migrate-bc-index`, `backfill-append-logs`) the exit status is one of three classes, matched EXHAUSTIVELY (`process_exit_code` has no wildcard arm; a new variant must be assigned a class explicitly): **exit 0** = the requested end state holds and was read under `exclusive.lock` (`Completed`, or `ALREADY_MIGRATED`); **exit 1** = *no harm done, safe to re-run; the stderr code token says what to do next* — exactly {`EXPIRY_ABORT` ⇒ re-activate, then re-run; `MIGRATION_LOCK_CONTENTION` ⇒ re-run after the holding coordinator exits}, told apart by the stderr token, never by the status alone; **exit 2** = fail closed, an operator must act (every other code in this category). A caller branching on exit codes alone MUST treat 1 as "re-run is safe" and 2 as "stop". The status reaches its caller as a Bash-tool result, never as a hook verdict.

**Coordinator advisory tokens (not exit codes) (v1.42; ADR-052 v1.25 item 11(f); BC-1.18.013 v1.14 Postcondition 10 "Coordinators" clause, EC-058..EC-061).** The migration coordinators (`migrate-bc-index`, `backfill-append-logs`) may print, besides the catalog codes above, a NON-FATAL advisory line for a `warn!`/`error!` condition that changes what the operator must know about the on-disk outcome (a completed-but-degraded state or a skipped step) but does not change the exit status: `<subcommand>: <TOKEN> (advisory): <path>: <os error>; <what is true now>`, one line per condition, stdout empty, `<path>` and `<os error>` rendered by the same sanitizer as the other coordinator diagnostics (control characters escaped, 256 characters), the final clause TRUE at print time. `<TOKEN>` is drawn from a CLOSED domain of exactly four values: `GATE_OPEN_RESET_FAILED` (the best-effort gate-OPEN write after the txn reached COMPLETED failed; exit stays 0; the clause names the gate state actually on disk and never claims OPEN), `TERMINAL_TXN_ARCHIVE_FAILED` (the best-effort archive rename of a stale terminal txn record failed with a non-ENOENT error; the record stays in place and is skipped as non-live), `STAGING_DIR_REMOVE_FAILED` (the inert generation-directory removal after an abort failed; the txn is ABORTED), and `OVERSIZED_ROW_SUBSHARD` (the lone-oversized-row sub-shard warning; present ONLY if it is reachable from a coordinator process). These tokens are NOT taxonomy codes: they have no catalog row, no exit status of their own and no class in the 0 / 1 / 2 scheme above — an exit-0 run that prints one is still exit 0 (the earlier "an exit-0 run prints nothing" statement is amended to "prints nothing EXCEPT advisory lines"; callers still branch on the exit status alone). A failure keeps its existing form (`<subcommand>: ` + the variant text, exit 2 or 1) and a canonical-move halt is carried by `CANONICAL_MOVE_HALTED` (six sites, ten `<reason>` tokens), never by an advisory. The five reservation-timestamp stderr tokens keep their existing `drain_bc_index_writers: ...` lines and are likewise not taxonomy codes.

E-REG-001/002/003 are fail-closed (exit 2) per ADR-019 §Decision 2 and BC-7.06.001 §Fail-Closed Symmetry; all other registry-load failures (file not found, I/O, TOML parse, invalid tool regex) carry no E-REG code and remain fail-open (exit 0) per BC-1.08.001 Invariant 1. E-PAY, E-PLG, and E-SNK are non-blocking (exit 0 or non-blocking per NFR-REL-001); E-CAP and E-HK block with exit 2; E-ACT exits non-zero.
`E-SHD-NNN` errors are native-gate `HookResult::Error` outcomes (a PreToolUse hook result, not a
process exit code) — dispatcher exit-code semantics do not apply to this category, per BC-1.18.006
through BC-1.18.011's own Postcondition/Edge-Case tables.
`E-MAINTENANCE-NNN` errors are emitted by the native admission gate in `executor.rs` (ADR-052
§Decision 5a), not by the migration binary itself: `E-MAINTENANCE-001` is an exit 2 block on ALL
mutation tool calls (Edit/Write/MultiEdit/Bash) during a migration window; `E-MAINTENANCE-002` is a
`HookResult::Error` (exit 2 at the PreToolUse hook surface) fail-closed outcome of the admission
check itself. Reservation release occurs on `PostToolUse` / `PostToolUseFailure`. Each
`E-MAINTENANCE-001` verdict writes exactly one `migration.admission_blocked` and each
`E-MAINTENANCE-002` verdict exactly one `migration.admission_failed` InternalLog event to
`dispatcher-internal-YYYY-MM-DD.jsonl` (BC-3.08.001 Events 11/12; the operator-visible stderr line
names `blocking_plugins=migration-admission`).
`RESERVATION_TTL_BELOW_FLOOR`, `MIGRATION_STATE_INTEGRITY_FAILURE` and `FACTORY_ROOT_NOT_FOUND` are
migration-binary process exit codes (exit 2), not `HookResult` outcomes.

## Severity Definitions

| Severity | Meaning | Exit Code / HookResult Impact |
|----------|---------|-------------------------------|
| broken | Cannot continue | Non-zero exit, OR (for E-SHD) `HookResult::Error` — the triggering write is blocked and no partial state is left authoritative |
| blocked | Explicitly denied by policy | Exit 2 |
| degraded | Partial result possible | Zero exit with warnings, non-blocking |
| cosmetic | Formatting/display issue | Zero exit |
