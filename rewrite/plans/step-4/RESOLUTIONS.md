## Probe questions the planners left, after round 4

The planners' open questions are in `RESULT.json`; `ORDER.md` section 7 carries three of them as P1 to P3.
Round 4 and its independent check ran on 2026-11-24 (`rewrite/spike/probes-round-4/CHECK.md`; Claude Code
2.1.331, macOS, a plugin loaded by `--plugin-dir`, default permission mode). Item numbers are those of the
platform record, `rewrite/spec/topics/platform-proven-2.md`.

- (G3) Is the `agent_type` in a workflow step's `StructuredOutput` payload exactly `vsdd-factory:<name>`? **Answered, item 36 (P1):** a typed step carries exactly `<plugin>:<agent>`, an untyped one `workflow-subagent`, the main session no such key. An installed (marketplace) copy is unprobed, so G3's `skipped` listing stays (PR4C-01).
- (H7) Does a `StructuredOutput` rewrite that adds a key the step's schema does not declare (`grounded: false` in a finding) pass the platform's check and reach the script? **Answered, item 37 (P2):** yes, declared or not, while the finding object is open. C1 adds no `grounded` property and the prelude is not regenerated for it. A finding object closed with `additionalProperties: false` refuses the rewrite and the step fails after the platform's retries; rules.md's `test_finding_schemas_stay_open` fails the build before that can ship (PR4C-02). It reads the shipped schema files with `$ref` resolved (`finding.schema.json` and every schema that embeds it: `review-data`, `gate-result`, `verdict`, `wave-gate-data`); the prelude's copies are generated from those files and from nothing else (`tools/build.py --check`), so checking the files checks them.
- (H7) Is `allow` plus `updatedInput` on a `StructuredOutput` call honoured in the default mode? **Answered, item 38 (P3):** yes, inside a step, for Bash too. The script's copy carries the mark (PR4C-03).
- (H7) Does `PreToolUse` on `StructuredOutput` run before the platform's own schema check? **Answered, item 40:** yes, and the platform then checks the input as the hook left it. `schema_invalid` can fire; a stored result can still be refused by the platform. The agent reads a block inside the platform's wrapper, never as the first characters: rules.md D16 (PR4C-05).
- (H7) Does exit 2 on `UserPromptExpansion` stop a typed `decide` command? **Answered, item 46,** for a typed plugin command in the default mode: zero turns, no cost, and a result that still says `is_error: false`. The missing-launcher leg of item 13 on that event stays unexercised; the `decisions` rule is not in the slice (PL4-18).
- (G4a) Can a project's git hooks run in the bare `.worktrees/_integration/` worktree? **Answered, item 45:** they run, with cwd = the worktree, that worktree's `GIT_DIR`, and tracked files only, so a hook that needs an untracked or generated file fails and the story is `refused`, naming the hook. An automatic merge runs `pre-merge-commit` and not `pre-commit`, so both strategies now commit explicitly (delivery.md D6, D7; `ORDER.md` rule 7; PR4C-10).
- (G4a, S3, G2) With the Bash sandbox on, can the tool's git write in a linked worktree? **Answered, item 41:** no. Every commit, merge and merge-in in `.worktrees/<story>` and `.worktrees/_integration`, and every flush, is refused. Each refusal names the sandbox and moves nothing (`ORDER.md` rule 7; delivery.md D7; PR4C-09).

Still open after round 4, each a B8 probe: a marketplace-installed plugin's `agent_type` (item 36); the detached job worker on Linux (item 43); whether a workflow survives `/clear` (item 46); a write under `.git/worktrees/` from a hook or a detached worker, and any sandbox allowance that works (item 41).
