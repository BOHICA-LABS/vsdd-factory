Where it was found: next/plugins/vsdd-factory/py/vsdd/config.py and next/tests/unit/test_config.py (the shipped loader); rewrite/spec/tables/config-keys.toml; rewrite/spec/schemas/config.schema.json; the annotated example in rewrite/spec/topics/project-configuration.md

A key marked person (flags.require) is accepted only in [flags]. Compute the three states off, requested and on from the two tables. Ship accept and reject cases; add the section to the annotated example; for the two files at the size limit either split them or have them name flag-config-keys.toml as the home of the flag rows. ## D31-6 (minor; decision D31, design; left-for-builder)

Earlier outcome: The scheme is settled in rewrite/spec/artifacts/flag.md. Package F1 adds the row to the identifier table with the artifact kind.

Files: artifacts/flag.md, tables/flag-checks.toml, tables/identifiers.toml

Where it was found: rewrite/spec/tables/identifiers.toml

The identifier table lists every identifier scheme, and the flag key is a new one: it is the identifier of a flag record, its file stem is a function of it, and it is never reused. Test names carry a second function of it, the encoded form, which no two keys that tests can name may share.

Proposed resolution: Add a row for the flag key: any key existing code reads, held to the tidy form ^[a-z0-9][a-z0-9._-]*$ for a new flag; chosen by the story-writer; the file stem is the key with /, % and whitespace percent-encoded; never reused, because the record of a removed flag is kept. For the encoded form point at the header of rewrite/spec/tables/flag-checks.toml, which defines it; do not restate it.

## D31R-F-15 (minor; decision D31, review (fit); left-for-builder)

Earlier outcome: Recorded again with its outcome unchanged, because the correction of d31-fix-2-C1-1 added a second way to remove a flag and the earlier text named one. The design is settled in the spec; the shipped artifact registry (next/plugins/vsdd-factory/py/vsdd/policy/artifacts.toml) and the artifact rule must follow it when package F1 is built, in the same change as D31-1. F1 adds: the stem cell of the [flag] row and the check that a record's path is its key percent-encoded (the id no longer equals the stem); the lock value removed (frozen once a delivered story removes the flag, with flag_change: remove or withdraw); the fourth story key flag_irreversible and the record keys permanent_because and default_because, as artifacts/flag.md gives them; the [deferred-item] writer vsdd checkpoint, with the item named deferred/flag-<stem>.md; and a [toolchain] cap of 12,000 bytes. Files: artifacts/deferred-item.md, artifacts/flag.md, artifacts/story.md, artifacts/toolchain.md, tables/artifacts.toml, topics/state-layout.md

Where it was found: artifacts/flag.md

The flag row introduces artifact-registry semantics that the shipped format does not have, and the ledger does not name them. A 'stem' column percent-encodes the key, so the id no longer equals the file stem, against the shipped header's rule that id equals the stem. Freezing on 'removed' is a lock condition outside the existing 'spec' and 'done'. The deferred item 'deferred/flag-<key>.md' is built from the raw key, which for an inherited key may hold '/', capitals or spaces. state-layout.md writes the path as stories/flags/<key>.md. The [toolchain] row caps the file at 4,000 bytes, which a [flags] table of pattern and glob lists, unioned across components, can exceed.

Proposed resolution: Widen D31-1 (and its by-package entry for F1, which depends on H4) to name the artifact-rule changes: the stem column and its check, a 'removed' lock, deferred items named from the stem, state-layout written with <stem>, and a raised [toolchain] max_bytes.
