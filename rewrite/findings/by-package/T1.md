## PR4-1 (major; platform probes, round 4; left-for-builder)

Earlier outcome: T1 (doctor and sandbox-needs): a factory run needs the Bash sandbox off until an allowance is shown to work; doctor tests a commit inside a linked worktree. Every unit that writes with git names the sandbox when git answers Operation not permitted (rule 11 of rewrite/plans/step-3/ORDER.md). Whether sandbox-off is the product's stated requirement waits for the user's answer.

Files: packaging/sandbox-needs.md

Where it was found: rewrite/spec/packaging/sandbox-needs.md (T1); item 41 of topics/platform-proven-2.md; rewrite/plans/step-3/survey.md (admission) and ORDER.md rule 11 (flush); rewrite/plans/step-4/delivery.md D7 and ORDER.md rule 7; rewrite/plans/step-5/agents.md M2

sandbox-needs.md listed write access to .factory/ and .worktrees/ but not git's own files for a linked worktree. With the Bash sandbox on (--settings {"sandbox":{"enabled":true}}, default mode, Claude Code 2.1.331, a --plugin-dir plugin), every write under .git/worktrees/ from a workflow step's Bash call is refused with 'Operation not permitted': mkdir .git/worktrees/x, touch inside an existing .git/worktrees/<name>/, git add and git commit in an existing linked worktree ('Unable to create .git/worktrees/z/index.lock') and in the .factory mount, and git worktree add. So nothing can be committed in a story worktree, in the integration worktree or in the .factory state mount, and no worktree can be added. A refused 'git worktree add <path> -b <branch>' has already created the branch, and its retry fails with 'a branch named ... already exists'. A commit with the person's global signing on fails too (gpg cannot reach its agent or write its home). Allowed: reads, git branch, git update-ref, mkdir directly under .git/, a main-checkout commit with signing off. No setting that grants the write was shown: excludedCommands ["sh"] did not take the call out of the sandbox. Not probed: the sandbox set in the project's settings file; a write under .git/worktrees/ from a hook or from a detached job worker. Evidence: rewrite/spike/probes-round-4/CHECK.md (q8-sandbox/s4b.jsonl; reruns D and E2).

Proposed resolution: sandbox-needs.md gains two rows: write access to .git/worktrees/ and, where commits are signed, the gpg home and its agent socket; T1's doctor tests the first by taking the index lock of an existing linked worktree (the .factory mount's), not by adding a worktree. Until an allowance is shown to work, a factory run needs the Bash sandbox off (platform.md, 'Headless runs'); whether that becomes the deployment default is the person's decision. Every unit whose git call is refused this way reports it with a cause that names the sandbox and undoes nothing, so the next run finishes: records' flush (state failed), the survey's worktree library (WorktreeError not_permitted; a branch left without its worktree is reused), delivery (refused), and a builder agent's commit (blocked, kind environment).

## D33-22 (minor; decision D33, design; left-for-builder)

Earlier outcome: Package M6 builds the function when the build widens; T1's owner prints its lines and the rest when T1 is built.

Files: commands/doctor.md, packaging/sandbox-needs.md, tables/sync-checks.toml, tables/team-checks.toml

Where it was found: rewrite/spec/commands/doctor.md; rewrite/spec/packaging/sandbox-needs.md ("Network to the git remote")

vsdd doctor checks git and nothing about the remote. On a team, a clone that cannot list the remote, has no git identity, is shallow, has a git below the floor, or runs a plugin below team.min_plugin fails at its first survey with no earlier warning; and nothing lets people see that two clones push to two different repositories, which no program can measure.

Proposed resolution: Package M6 delivers one preflight function that returns a line for each check: git at 2.34 or newer, this plugin's version against team.min_plugin, not a shallow clone, the identity git would use, the upstream of each factory branch, and whether the remote answers a listing inside the time limit. The sync, vsdd init, vsdd status and the doctor all call it, so they cannot disagree, and M6 does not wait for T1. With team use on the doctor prints those lines, the address each factory branch is pushed to with any user or password part removed, the length of the state branch, and what the factory needs of the repository's rules (direct pushes of unsigned commits to the state branch; no forced push or deletion there). Whether the clone may push stays unmeasured and is said so.
