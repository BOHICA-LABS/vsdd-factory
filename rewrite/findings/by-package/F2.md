## D31-8 (minor; decision D31, design; left-for-builder)

Earlier outcome: The items are settled as check F-ITEMS in rewrite/spec/tables/flag-story-checks.toml: four items, of which only checked counts, two added again in a later loop that touches source or tests, and one known only from the green evidence. Package F2 carries them to the reviewers and into the tool's verdict, widens the schema description, and proves with a harness scenario that a story behind a flag converges only when a reviewer marks flag-off checked.

Files: schemas/story-unit.schema.json, tables/flag-duties.toml, tables/flag-story-checks.toml, topics/verdicts.md

Where it was found: next/plugins/vsdd-factory/schemas/story-unit.schema.json (the acs field); rewrite/spec/topics/verdicts.md (items to account for); rewrite/spec/tables/flag-story-checks.toml (F-ITEMS)

F-ITEMS (rewrite/spec/tables/flag-story-checks.toml) adds four review items that are not acceptance criteria to the items a story's review must account for: flag-off:<key>, for a story behind a flag and for a story that turns one on; flag-removed:<key>; flag-system; and not-a-flag. The workflow script hands reviewers the unit's acs list, and the shipped schema describes acs as acceptance criteria only, so without a change the reviewers are never told of an item the tool's verdict then waits for, and the story cannot converge. These items differ from a criterion in three ways. Only checked counts for them: not_checkable leaves the item uncovered. flag-off and flag-removed are added again in a later review loop whose commits touch a file of class source or tests. And not-a-flag is known only once the green gate has run, because it is added when the green evidence lists a marked line, so it cannot come from a unit the survey built before that gate.

Proposed resolution: Have the survey and the admission commands append the items that the story's own keys decide (flag-off, flag-removed, flag-system) to the unit's acs, and widen the field's description to say so. Carry not-a-flag to the reviewers from the green gate's result, and have the tool's verdict add it from the green evidence. For a later loop, have the verdict and the script's list for that loop both carry flag-off or flag-removed when the loop's commits touch source or tests. Check that nothing reads every acs entry as AC-<N> (the criterion-to-test table is built from the red record's criteria map, not from acs); if a consumer does, carry the items in a field of their own and pass it in the review step's prompt instead. Prove with a harness scenario that a story behind a flag converges only when a reviewer marks flag-off checked, and that not_checkable does not converge it.

Where it was found: next/plugins/vsdd-factory/schemas/implement-data.schema.json (test_defects description); rewrite/spec/topics/story-script.md (the test-defects prompt); rewrite/spec/tables/flag-duties.toml (implementer duty)

The design choice 'no ledger entry was added: test_defects carries a test that F-ON names, with its shape unchanged' is right about the shape (path, test, reason). But the shipped schema describes the field as 'frozen tests the builder believes are wrong and may not edit', and the story script's prompt tells the test-writer 'The implementer reports these frozen tests as wrong'. A test that F-ON names is an existing test the story did not write, and it is not frozen. Moved tests are expressly not held among the frozen tests (F-STATES). So D31 uses a shipped field beyond its documented meaning, with no ledger entry to widen the description. D31-8 makes exactly that kind of change for the acs field. A builder or reviewer who reads the description could reject or ignore such an entry.

Proposed resolution: Add a ledger entry, left-for-builder for package F2: widen the description of test_defects in implement-data.schema.json to 'tests the builder believes are wrong and may not edit: frozen tests, and existing tests that the green gate's run with a flag on names'. The shape does not change. Leave the story script's prompt unchanged, so nothing on the slice path changes. F4's harness scenario, in which an existing test is moved once the run with the flag on has named it, already proves that the step works with that prompt.
