If the time is not wanted, extend DIFFERENTIAL_CHARACTERS with one code point per Unicode general category, every Zs, Zl, Zp and Cf code point, a surrogate, an astral code point and the four case-folding letters, and rerun the non-ASCII mutants.

Files: topics/caller-identity.md

Where it was found: next/tests/hooks/test_caller.py (DIFFERENTIAL_CHARACTERS and test_grammar_checker_agrees_with_the_allow_list); the classes are in _CALL_TEXT_RE, _SAFE and _QUOTED of next/plugins/vsdd-factory/py/vsdd/hooks/caller.py

The differential test pins every character class only for ASCII and three code points beyond it: e-acute, U+0085 and U+2028 (DIFFERENTIAL_CHARACTERS). No other test puts a non-ASCII code point outside a quoted span. The only other non-ASCII code points inside one are e-acute, u-umlaut and i-umlaut. So widening or narrowing a character class with any other non-ASCII code point passes all 27 tests. I ran 1163 mutants of caller.py in a scratch copy of next/. These were killed: all 1032 per-character ASCII widenings and narrowings of the program's first class, its rest class, _SAFE, the separator, both pads and the quoted span; all 53 recorded mutations (the 49 and their variants); the pre-fix 'head required' revert; and every look-ahead, quantifier, structure and gate change. 70 survived. Two are equivalent mutants and need no test: [SAFE]*= changed to [SAFE]+= after (?!=), and the bare word's + changed to *. Neither differs from the current regex on any of 1,069,774 texts. The other 68 are real. (1) 54 mutants add one of U+00A0, U+1680, U+2002, U+202F, U+3000, U+FEFF, U+200B, U+4E2D or U+1F600 to the program first class, the program rest class, _SAFE, the separator, the leading blanks or the trailing blanks. (2) 13 mutants refuse one of those nine inside a quoted span, or refuse the range U+0100-U+2027, the zero-width characters U+200B-U+200F with U+FEFF, the surrogates, or U+10000-U+10FFFF. The four shells and the runner's parser read non-ASCII characters as word characters. So a widened blank class is refused by the parsed gate wherever it would change the program, and elsewhere it only admits an odd argument. A narrowed quoted span fails safe, but it silently stops marking real calls, such as a quoted title with an emoji or CJK text. The gap predates this round. One text that holds every one of them inside a single quoted span must be accepted. Also send U+017F, U+212A, U+0130 and U+0131 in a bare word through is_vsdd_call and assert refusal; that catches a case-insensitive gate. I ran this test in a scratch copy. It adds about 4.6 s, passes on the current code and kills all 68 survivors. If 4.6 s is too slow, extend DIFFERENTIAL_CHARACTERS instead: add one code point from each Unicode general category, every Zs, Zl, Zp and Cf code point, a surrogate, an astral code point and the four case-folding letters. Then re-run the non-ASCII mutants.
