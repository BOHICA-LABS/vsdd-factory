## S3R-hook-runner-b-6 (major; slice step 3, hook-runner-b, review; left-for-builder)

Earlier outcome: Fixed for the case the finding named. What remains is a path that goes through a directory symlink inside the project and is spelled through an alias of the project root: only its resolved form is classed. Left for H4, which builds the first rule that decides on a path's classes: before the realpath fallback, walk the literal path's parents and anchor at the first ancestor whose realpath equals the resolved root, with the confirmer's probe as the test.

Files: topics/rule-model.md

Where it was found: next/plugins/vsdd-factory/py/vsdd/hooks/paths.py (classes_of); next/plugins/vsdd-factory/py/vsdd/hooks/model.py (Ctx.classes); rewrite/spec/topics/rule-model.md (target row)

rule-model.md's target row, taken from hooks.md 2.5, says that class matching tests both the literal and the resolved path. ctx.classes classes only the resolved target. paths.classes_of applies os.path.realpath to whatever it is given, so even ctx.classes_of(ctx.target_literal) cannot answer for the literal path. Probe: with .factory/specs/product/brief.md a symlink to src/x.rs, both forms gave ('unclassified', 'project'), and 'brief' appeared in neither. A write-scopes or tests-first rule built in step 4 on ctx.classes would judge a write through a symlink only by where the link points. The builder did not report this departure.

Proposed resolution: Class the literal path in its absolute form, without realpath, as well as the resolved path, and have ctx.classes return the union of the two, keeping innermost-first order. Alternatively, give classes_of a resolve flag and document that rules must call it for both forms. Either way, add a symlink case to test_classes.py. If the design is to change instead, amend rule-model.md and say so in the plan.
