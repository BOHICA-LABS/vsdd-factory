Delivery in pr mode is specified through one vendor's command-line tool, which the design, the wall table, a hook rule, the doctor and the list of hosts all name. Git has no notion of a pull request, so some host-specific step is unavoidable; but decision D33 makes pr mode the only delivery a team has, and under it nothing a program reads may depend on the name of a Git host. As specified, a team whose repository is on another host has no delivery at all, and finds out at its first delivery.

Proposed resolution: G4a puts the operations on the host (find or open the pull request of a branch; read its state, merged head and checks; merge it at a named head; close it; and answer whether it can serve a given remote) behind one module with one implementation. Nothing else in the tool calls or names the vendor's tool; the rules and the doctor ask that module what to guard and what to check. No configuration key names the module or a host: the tool asks the module whether it can serve the remote, and T-SWITCH, T-DELIVERY and the doctor refuse or report when it cannot. vsdd release uses the same module (D33-27). Whether a second implementation is built for 1.0 is a question for the person.
