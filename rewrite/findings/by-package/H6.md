## P3OPS-15 (major; review pass 3; open)

Files: rules/auto-allow.md

Where it was found: rewrite/design/hooks.md 2.11.10 auto-allow core row; 2.11.1 shell.py; rewrite/BLUEPRINT.md 5.4

The built-in part of auto-allow requires a single segment, but the core prefix match of configured commands does not. A configured command followed by ;, &&, $(...), backticks, eval or sh -c with an opaque payload is approved without a prompt in the default permission mode, for exactly the commands the heuristic checks cannot read.

Proposed resolution: Approve a configured command only as one segment followed by plain argument tokens: no separators, substitutions, eval, sh -c, xargs or redirects. shell.py marks commands with substitutions as opaque, and auto-allow never permits an opaque command. Add cases.
